# FE-003: 定期健診タブ - 健診種別IDスピンボタン無効な境界値

## 問題
医療記録（カルテ）の「定期健診」タブで、健診種別の入力フィールドが`spinbutton`として実装されており、`min="0"` `max="0"`という無効な境界値が設定されているため、ユーザーが値を入力できない。

## エラー発生箇所
- **タブ**: 定期健診 (Checkups)
- **要素**: 健診種別ID spinbutton
- **属性**: `valuemin="0"` `valuemax="0"` - 最小値と最大値が同じため、値の変更が不可能
- **リクエスト例**: `POST /api/v1/medical-records/{id}/checkups`

## 問題の詳細
フォームに「記録を追加」ボタンをクリックすると以下のフィールドが表示される：
1. 日付 (Date) - date input
2. **健診種別ID (Checkup Type ID)** - spinbutton（⚠️ 問題のあるフィールド）
3. 次回予定日 (Next scheduled date) - date input
4. 結果を入力 (Result) - textbox

健診種別IDフィールドの`valuemin="0"`と`valuemax="0"`により、いかなる値も設定できず、フォームの「追加」ボタンは無効な状態を保つ。

## 根本原因
フロントエンドUIの設計不良：
- spinbutton を使用すべきではなく、コンボボックス（select dropdown）またはポップオーバーを使用して、有効な健診種別を選択できるようにすべき
- または、バックエンド側で有効な健診種別IDの一覧を提供し、フロントエンド側でそれを選択肢として提示すべき

## 再現手順
1. 医療記録編集画面を開く
2. 「定期健診」タブをクリック
3. 「記録を追加」ボタンをクリック
4. 健診種別IDフィールドを確認すると、spinbutton の min/max が両方 0 に設定されている
5. 「追加」ボタンが無効のままで、フォーム送信不可

## テスト環境
- 記録ID: 17
- ペットID: 15
- タイムスタンプ: 2026-03-16

## 対応
1. **フロントエンド側**: 健診種別IDフィールドを spinbutton から combobox/select に変更
2. **バックエンド側**: 有効な健診種別IDの一覧を取得するエンドポイントを実装（または既存エンドポイントを確認）
3. フロントエンド側でマスタデータから健診種別を取得し、ドロップダウンで選択可能にする
