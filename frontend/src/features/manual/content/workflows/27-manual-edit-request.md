# マニュアルの編集依頼方法

このマニュアル自体を **修正・追加・削除** したい時の依頼手順です。

## 現状

マニュアルは **MD ファイルバンドル（初期版）+ DB（編集オーバーライド）** の二層構成で管理されています。

| 保存先                           | 役割                                 |
| -------------------------------- | ------------------------------------ |
| MD ファイル（ビルド時バンドル）  | 初期版・既定値                       |
| DB の `manual_articles` テーブル | 編集オーバーライド版（管理者編集分） |

読み込み時、DB に該当 slug の編集版があればそれを優先表示。なければ MD バンドル版を使用。

### 編集方法（3 通り）

1. **DB 保存（推奨・即時反映）**: 編集モードの「**保存**」ボタン → 全スタッフに即時反映
   - 必要権限: `manual-edit`（院長・管理者）
   - 編集履歴が DB に自動記録される
2. **コピー → IT 担当に送付**: 「**コピー**」ボタンで内容をクリップボードへ
3. **ダウンロード → IT 担当に送付**: 「**ダウンロード**」ボタンで .md ファイル保存

権限がないスタッフは「保存」ボタンが使えないため、コピー・ダウンロード方式で IT 担当に依頼します。

---

## 編集依頼の流れ

### 流れ A: 管理者権限あり（推奨）

```
スタッフが気づき
   ↓
編集モードで該当ページを修正
   ↓
「保存」ボタンをクリック
   ↓
DB に保存（即時反映、全スタッフに表示）
   ↓
編集履歴が DB に自動記録
```

### 流れ B: 一般スタッフ（権限なし）

```
スタッフが気づき
   ↓
編集モードで該当ページを修正
   ↓
「コピー」または「ダウンロード」して内容を保存
   ↓
管理者・IT 担当者に送付（メール・Slack）
   ↓
管理者が内容確認・承認後、自身で「保存」ボタンで反映
```

## ブラウザ内編集モードの使い方（推奨）

各マニュアルページ右上の **「編集」ボタン（鉛筆アイコン）** をクリックすると、ブラウザ上で編集できます。

### 操作手順

1. 該当マニュアルページを開く
2. 画面右上の **編集ボタン（鉛筆アイコン）** をクリック
3. 編集モードに切り替わる：
   - 左側: 編集用テキストエリア（マークダウン形式）
   - 右側: ライブプレビュー（編集結果を即時確認）
4. 内容を編集（修正・追加・削除）
5. 「**コピー**」ボタンでクリップボードにコピー、または「**ダウンロード**」ボタンで .md ファイルとして保存
6. 保存した内容を管理者・IT 担当者にメール・Slack で送付
7. 「**編集を終了**」ボタンで編集モードを終了

### モード切替

ツールバーで 3 つのモードを切り替えできます：

- **編集**: テキストエリアのみ表示（広く編集したい時）
- **分割**: 編集 + プレビューを左右に並べる（既定）
- **プレビュー**: プレビューのみ（仕上がりを確認したい時）

### ⚠️ 重要な注意

- ブラウザ上の編集内容は **一時的** です。ページを離れると消えます
- **コピー or ダウンロード** で保存してから管理者に渡してください
- ブラウザ編集は **本番マニュアルには即座には反映されません**
- 実際の更新は管理者・IT 担当が行います

## こんな時に依頼する

| 状況                   | 依頼の例                                             |
| ---------------------- | ---------------------------------------------------- |
| 操作方法が変わった     | 「会計確定後に〇〇の確認が必要になった」             |
| ボタン名が変わった     | 「『確定』ボタンが『保存して確定』に変更されている」 |
| 院内ルールが変わった   | 「うちの病院では支払方法に『回数券』が追加された」   |
| 誤った記述             | 「『3 回まで再発行可能』とあるが実際は無制限」       |
| 分かりにくい説明       | 「『連動』の意味が分からない」                       |
| 抜け漏れ               | 「○○の手順が書いていない」                           |
| スクリーンショット古い | 「画面が現在の UI と違う」                           |
| 業務シナリオ追加       | 「往診業務の手順を追加してほしい」                   |

## 依頼を提出する方法

### 方法 1: 院内メール（最も簡単）

宛先: （院ごとに設定）

件名例:

```
マニュアル編集依頼: 会計画面の取消手順
```

本文テンプレート:

```
■ 対象マニュアル
画面名 or 業務フロー名: 会計
URL: /manual/screens/05-accounting

■ 該当箇所
セクション「会計を取り消す」の Step 3

■ 現状の記述
「取消理由を入力します（例: 「金額入力ミス」「飼主返金」）」

■ 変更要望
取消理由に「保険適用漏れ」の例も追加してほしい

■ 理由・背景
うちの病院では保険適用漏れによる取消が多いため

■ 依頼者
受付スタッフ ○○
```

### 方法 2: Slack（社内チャットがある場合）

専用チャンネル: `#manual-edit`（院ごとに設定）

```
@管理者
マニュアル「会計」の取消手順について：
取消理由の例に「保険適用漏れ」を追加してほしいです。
理由: うちの病院では保険適用漏れによる取消が多いため
```

### 方法 3: GitHub Issue（IT 担当者向け）

リポジトリ: （院ごとに設定）

```markdown
**対象マニュアル**

- ファイル: workflows/13-accounting-refund.md
- セクション: 「会計を取り消す」

**変更内容**

中
```

## 依頼後の流れ

| 段階                    | 担当             | 想定期間   |
| ----------------------- | ---------------- | ---------- |
| 1. 依頼受付             | 管理者           | 即日       |
| 2. 内容確認・優先度判断 | 管理者           | 1〜2 日    |
| 3. 修正作業             | 開発者 / IT 担当 | 1〜3 日    |
| 4. 院長レビュー         | 院長             | 1 日       |
| 5. 本番反映（デプロイ） | 開発者           | 即日〜数日 |

合計：**約 1 週間** 程度。

緊急の場合（誤情報による業務支障）は管理者に **「緊急」と明示** して依頼。

---

## 編集が却下される場合

以下は依頼があっても採用されない可能性があります：

- システム動作と矛盾する内容
- 院内ルールに反する内容
- 法的・コンプライアンス上問題のある変更
- 個人的な好み（フォーマット・絵文字 等）
- 既に別の場所で説明されている情報の重複追加

却下時は理由を依頼者に説明します。

---

## 編集の種類別の対応

### A. 文章の修正（誤字・分かりにくい）

- 比較的早く対応
- 即日〜数日

### B. 手順の追加・削除

- 院長承認が必要
- 1 週間程度

### C. 新規ページ・新規業務フローの追加

- 院長 + 院全体の判断
- 2〜4 週間
- 既存マニュアルとの整合性チェック必要

### D. スクリーンショットの更新

- 個人情報マスキング必要
- 1〜2 週間

### E. システム動作の解説変更

- 開発者の動作確認が必要
- 1〜2 週間

## 「マニュアル編集会議」の開催（推奨）

月 1 回程度、以下を議題に：

- 蓄積した編集依頼のレビュー

- 古い記述・スクリーンショットの棚卸し

参加者：院長・管理者・各役職代表
