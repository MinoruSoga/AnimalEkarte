# セキュリティと複数医院の運用

スタッフ全員が知っておくべき **ログインセキュリティ** と、グループ運営の **医院切替** の運用ルールです。

---

## ログインセッションの仕組み

### 自動ログアウト

セキュリティ保護のため、以下の場合に **自動ログアウト** されます：

- パスワードを変更した直後（強制ログアウト）
- 一定時間操作がない（リフレッシュトークン期限切れ）
- 管理者がアカウントを無効化
- 管理者がパスワードをリセット

### セッション維持

通常の業務操作中はセッションが維持されます。

- 短時間（15 分以内）の操作: 自動継続
- 長時間（数時間〜数日）の不操作: 再ログインが必要

---

## 共有端末での運用ルール

複数スタッフが同じ PC を使う場合の **重要な注意**：

| 状況                             | やるべきこと                                      |
| -------------------------------- | ------------------------------------------------- |
| 業務終了時                       | 必ずログアウト（サイドバー左下）                  |
| 短時間離席                       | PC をロック（OS の機能）                          |
| シフト交代                       | 前のスタッフがログアウト → 次のスタッフがログイン |
| 共有端末で「ログイン状態を保持」 | **しない**（個人特定不能になる）                  |

### 監査ログとの関係

すべての操作は **操作スタッフが記録** されます。他人のアカウントでログイン状態のままだと、誤った担当者として記録される問題が発生します。

---

## パスワード管理

### 最低限のルール

- 8 文字以上・英字数字混在
- 共有しない・他人に教えない
- 紙に書いて貼らない（机・モニター付箋等）
- 定期的に変更（6 ヶ月〜 1 年）

### パスワード変更方法

サイドバー左下の **鍵アイコン** から変更可能。

→ 画面マニュアル「**ログイン**」参照。

### 紛失時

ログイン画面の「**パスワードをお忘れですか？**」リンクからリセット可能。または管理者に依頼。

---

## 医院切替（グループ運営の場合）

複数の医院でシステムを共有している場合、サイドバー上部の **医院名プルダウン** で切替できます。

### 切替の手順

1. サイドバー上部の医院名（例: 「八王子病院」）をクリック。
2. 医院選択ポップオーバーが表示される。
3. 切替先の医院名をクリック。
4. **確認ダイアログ** が表示される：「○○病院に切り替えます」
5. 「**切り替える**」をクリック。

### 切替時に起きること

- 画面のデータが切替先医院のデータに **完全に更新** されます
- 該当医院の権限グループに応じた画面が表示されます
- 操作ログには切替後の医院 ID が記録されます

### 表示される医院

ログイン時に **アクセス権が付与された医院のみ** が選択肢に表示されます。権限のない医院は **物理的に表示されません**。

---

## 医院間のデータ越境について

システムは **医院ごとにデータが完全に隔離** されています：

- A 病院のスタッフは B 病院の飼主・カルテを **見ることができません**
- 医院切替で権限のある医院だけ操作可能
- API レベルで他院データへのアクセスは **遮断**

### 同一飼主が複数医院に登録されている場合

同じ飼主が A 病院と B 病院の両方を利用している場合：

- A 病院では A 病院のカルテのみ表示
- B 病院では B 病院のカルテのみ表示
- 医院切替で両方のデータを順番に参照可能

---

## 不正アクセスの防止

### ログインのレート制限

ログインは **同一 IP につき 5 回 / 1 分** までに制限されています（総当たり攻撃対策）。

- 超過時は一時的に拒否されますが、**アカウント自体はロックされません**
- **約 1 分待つと自動的に再試行可能** になります（解除操作は不要・存在しません）
- 続く場合はパスワードリセット、または管理者によるアカウントの **有効/無効** 確認

詳細は画面マニュアル「**ログイン**」を参照。

### 不審な操作の検知

すべての操作は監査ログに記録されます。管理者は以下を定期的に確認：

- 異常な時間帯の操作
- 大量の取消・削除操作
- 通常使わない機能へのアクセス

不審な操作があれば、対象スタッフに確認の上、必要なら **アカウント無効化** で対応。

---

## 退職スタッフの対応

退職スタッフの **アカウント無効化** は退職当日に実施：

1. 管理者が「**マスタ設定**」→「**スタッフ管理**」→ 該当スタッフ
2. 「**ステータス**」を「**無効**」に変更
3. 「**保存**」

### 無効化後

- ログイン不可
- 過去のカルテ・会計の担当者参照は維持
- 監査ログから過去の操作履歴は閲覧可能

> 削除ではなく **無効化** を必ず使用。過去データの整合性のため。
