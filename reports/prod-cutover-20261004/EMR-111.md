- 収集日時: 2026-10-04 (JST)、STG PlanetScale `animalekarte-stg` / branch `main`
- 方法: 読み取り専用 SQL（SELECT のみ）。RLS は ops 用 GUC `SET app.bypass_rls='on'` で session 内 bypass（migration `006_accounts_rls_ops_bypass` 由来の既存機構。**DB への書き込みなし**。ただし下記の通り credential 変更は発生している — 旧記述「credential 変更なし」は誤りで 2026-10-07 訂正）
- 接続: `.env.staging` の DB_HOST は廃止済み AWS RDS を指し解決不能だったため、`pscale role create … --inherited-roles pg_read_all_data --ttl 4h` で TTL 付き読み取り専用 role `emr111-evidence-ro` を新規発行して接続。**これは新規 credential の発行 = 外部 credential mutation であり、読み取り専用ではないコントロールプレーン操作**（承認済み ops 操作として実施。既存 credential 無変更・4h TTL で自動失効、失効以降は接続不可。別途明示的 revoke は TTL 失効をもって完了扱い）

- 2026-10-05 追記: staff_id の行レベル記載はレビュー指摘を受けて除去（集計値のみ残す）。個別スタッフの特定が必要な場合は監査クエリで再取得すること

## 判定（EMR-111）

| 観点 | 結果 |
|---|---|
| 全4院で「認証できるアカウントが存在する」 | ⚠️ **過去実績あり・現在の認証可否は UNKNOWN** — 証拠は過去の監査イベントのみで現在ログイン smoke 未実施。clinic 3/4 は約3週間前の成功1件ずつで、その後のパスワード/アカウント状態変化を排除できない（旧「✅ PASS」は過去実績を現在の健全性と同一視しており 2026-10-07 訂正） |
| 全アカウントが認証可能か | ⚠️ 未検証 — 126 active staff アカウント中 114（90%）は成功監査記録なし（best-effort 監査のため上限値・実値 UNKNOWN、§3 ※2）。API smoke は未実施（STG のデモ共通パスワードは `SEEDLOGIN_DEMO_PASSWORD` シークレット注入であり `password123` 等のコード定数は STG では認証されないため、監査証跡ベースで評価） |

## 使用クエリ（抜粋）

```sql
SET app.bypass_rls = 'on';
-- 2026-10-07 訂正: created_at は timestamptz のため ::date は session TZ 依存だった。
-- 本来の JST 境界は以下のように AT TIME ZONE 'Asia/Tokyo' を噛ませる必要がある。
-- 収集時のセッション TZ が UTC だった場合、JST 00:00–08:59 のイベントは前日に帰属するため、
-- 本レポートの初回/最終ログイン「日付」および日別バケットはその範囲で ±1 日ずれ得る（件数・distinct 数は不変）。
SELECT clinic_id, count(*), count(DISTINCT actor_id),
       min(created_at AT TIME ZONE 'Asia/Tokyo')::date, max(created_at AT TIME ZONE 'Asia/Tokyo')::date
FROM audit_logs WHERE action='auth.login.success' GROUP BY clinic_id;
SELECT s.clinic_id, s.id, al.n FROM staffs s
JOIN (SELECT actor_id, count(*) n, max(created_at AT TIME ZONE 'Asia/Tokyo') l FROM audit_logs
      WHERE action='auth.login.success' GROUP BY actor_id) al ON al.actor_id=s.id
WHERE s.deleted_at IS NULL;
```
