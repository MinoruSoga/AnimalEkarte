# EMR-111: 全クリニック ログイン健全性チェック（STG）

- 収集日時: 2026-10-04 (JST)、STG PlanetScale `animalekarte-stg` / branch `main`
- 方法: 読み取り専用 SQL（SELECT のみ）。RLS は ops 用 GUC `SET app.bypass_rls='on'` で session 内 bypass（migration `006_accounts_rls_ops_bypass` 由来の既存機構。DB 書き込み・credential 変更なし）
- 接続: `.env.staging` の DB_HOST は廃止済み AWS RDS を指し解決不能だったため、`pscale role create … --inherited-roles pg_read_all_data --ttl 4h` で TTL 付き読み取り専用 role `emr111-evidence-ro` を新規発行して接続（既存 credential 無変更・4h で自動失効）
- 監査ソース: `audit_logs`（`action='auth.login.success' / 'auth.login.failure' / 'auth.logout'`、`resource='auth'`、`actor_id`=staffs.id、`clinic_id`=ログイン時に resolve された main clinic）。`accounts` に `last_login` 列はなく、監査テーブルが唯一の認証証跡
- PII 方針: staff_id（=合成 email `stg-staff-<id>@example.test` の数値部）のみ記載。氏名・メール・パスワード・トークンは記録しない

## 判定（EMR-111）

| 観点 | 結果 |
|---|---|
| 全4院で「認証できるアカウントが存在する」 | ✅ PASS（各院 ≥1 件の成功実績あり。clinic 3/4 は9月中旬に1件ずつのみ） |
| 全アカウントが認証可能か | ⚠️ 未検証 — 126 active staff アカウント中 114（90%）は成功実績なし。API smoke は未実施（STG のデモ共通パスワードは `SEEDLOGIN_DEMO_PASSWORD` シークレット注入であり `password123` 等のコード定数は STG では認証されないため、監査証跡ベースで評価） |
| ギャップ | staff `40000039`（clinic 2, active, account 未 link）、`11000003`（inactive だが account active・失敗8件）、clinic 3/4 のローカルスタッフ実ログイン皆無 |

## 使用クエリ（抜粋）

```sql
SET app.bypass_rls = 'on';
SELECT clinic_id, count(*), count(DISTINCT actor_id), min(created_at)::date, max(created_at)::date
FROM audit_logs WHERE action='auth.login.success' GROUP BY clinic_id;
SELECT s.clinic_id, s.id, al.n FROM staffs s
JOIN (SELECT actor_id, count(*) n, max(created_at) l FROM audit_logs
      WHERE action='auth.login.success' GROUP BY actor_id) al ON al.actor_id=s.id
WHERE s.deleted_at IS NULL;
```
