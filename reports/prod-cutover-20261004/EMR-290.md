# EMR-290: 生存ペット判定を status 対応に修正（deceased_at のみ判定の解消）

- 実施日: 2026-10-05（JST）
- ブランチ: `emr-290-cutover`（worktree `AnimalEkarte-emr290`、base `origin/main`）
- 対象: アプリ側の生存ペットフィルタ。**データ修正・マイグレーション・deceased_at 捏造は行わない**（EMR-108 の方針に従い、値を埋めるのではなくアプリの判定を直す）。

## 1. バグの内容

生存ペットの絞り込みが `pets.deceased_at IS NULL` のみを見ており `pets.status` を無視していた。
`status='deceased'` かつ `deceased_at IS NULL` の旧移行レコード（STG で約7,485件確認）が
「生存ペット」として LIFF 予約のペット候補・生存頭数・各種配信対象に混入していた。

## 2. 適用した判定ルール

`sharedkernel.ValidatePetNotDeceased`（BUG-001）と同じ OR 契約に統一した:

- 死亡: `pets.status = 'deceased'`（`deceased_at` の有無を問わない）または `pets.deceased_at IS NOT NULL`
- 生存: `pets.status <> 'deceased'` かつ `pets.deceased_at IS NULL`

Go では `p.Status == model.PetStatusDeceased || p.DeceasedAt != nil` を除外条件に、
SQL では `deceased_at IS NULL AND status <> 'deceased'` を生存条件に使用した。

## 6. 意図的に未変更のフィルタ（review-needed / ambiguous）

以下は「生存のみに絞る経路ではない」または死亡表示・履歴参照が意図のため変更していない:

- **履歴・医療記録の JOIN**: 死亡ペットの診療履歴・検査記録は正規データであり deceased フィルタを掛けない。
- **staff 依存カウント**: ペット紐付け削除ガードのうち deceased_at を見ないことが明示コメント済みの経路。
- **飼主・ペット管理一覧 / IncludeDeceased=true 経路**: 死亡ペットの表示が仕様（一覧上で「死亡」表示）。
- **フロントエンド既存ガード**: reception/appointment カード等は `petStatus === 'deceased'` で既に status 対応済み（deceased_at NULL の死亡ペットも従来通り死亡扱い）。
- **書き込みガード**: `sharedkernel.ValidatePetNotDeceased` は当初から status OR deceased_at の OR 契約で、変更不要。
- **frontend の新規変更なし**: LIFF 予約のペット選択は backend（`livingPets` / health card）で完結しており、FE 側に deceased_at のみの生ペット選択ロジックは存在しないことを確認済み。

- `TestRealDB_RecordsSelectedClinicBGrantAIsolation/images_grantB_nonempty` の main 上既知不良は別途調査対象（本 PR スコープ外）。
