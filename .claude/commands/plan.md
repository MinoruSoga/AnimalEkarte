# 実装計画

$ARGUMENTS の実装計画を作成してください。

## 手順

1. `planner` エージェントを起動して以下を実施:
   - 要件の明確化・言い直し
   - リスクと依存関係の特定
   - フェーズ分割した実装ステップの作成
   - 複雑度の評価（High / Medium / Low）

2. 計画をユーザーに提示

3. **確認を待つ** — ユーザーの明示的な承認（「はい」「進めて」等）なしにコードに触れるな

## 出力フォーマット

```
# 実装計画: [機能名]

## 要件確認
[何を作るか・なぜ必要か]

## フェーズ
### Phase 1: [名前]
- [具体的なステップ]

### Phase 2: [名前]
- [具体的なステップ]

## 依存関係・リスク
- [HIGH/MEDIUM/LOW] [リスク内容]

## 複雑度: [High/Medium/Low]
- Backend: [時間見積もり]
- Frontend: [時間見積もり]

---
承認しますか？（はい / 修正: [変更内容] / 別アプローチ: [代替案]）
```

## 注意

- **コード変更禁止** — ユーザーが計画を承認するまでファイルに手を触れるな
- 承認後は `/implement` または `/tdd-workflow` で実装に進む
