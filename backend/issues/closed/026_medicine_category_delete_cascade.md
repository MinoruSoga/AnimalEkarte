# [BE-026] 薬剤カテゴリ削除時の子アイテム処理

## 概要

薬剤マスタのカテゴリ（`parent_id = NULL`, `price = 0`）を削除する際、
子アイテム（`parent_id = <カテゴリID>` を持つ薬剤）の扱いが未定義。

現状の `DELETE /v1/masters/medicines/{id}` はシンプルに単一レコードを削除するが、
カテゴリを削除した場合に子アイテムが孤立する（`parent_id` が存在しないIDを参照）。

## 期待する挙動

カテゴリ削除時には以下のいずれかの仕様を決定・実装する：

**案A（推奨）: 子を未分類に昇格**
- カテゴリ削除時、`parent_id = <削除対象ID>` を持つ全薬剤の `parent_id` を `NULL` にセット
- 子アイテムが「未分類（ungrouped）」として表示される

**案B: 子ごと削除（カスケード削除）**
- カテゴリと子アイテムを一括削除
- 確認ダイアログで「子アイテムX件も削除されます」を通知

**案C: 子がいる場合は削除を拒否**
- 子アイテムが存在するカテゴリの削除を 422 Unprocessable Entity で拒否
- エラーメッセージ: 「このカテゴリには{N}件の薬剤が含まれています。先に薬剤を移動または削除してください」

## 現在の挙動

- カテゴリ削除 → 子アイテムの `parent_id` が存在しないIDを参照 → フロントエンドで孤立アイテムとして扱われる
- DB外部キー制約が無ければサイレントに孤立、FK制約があれば500エラー

## 影響エンドポイント

```
DELETE /v1/masters/medicines/{id}
```

## 実装場所

```
backend/internal/service/medicine_service.go

```
