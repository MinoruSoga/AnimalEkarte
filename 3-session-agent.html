並行化・統合ルール

  • 単一writer: canonical integration worktreeのproduction / central surfaceはSession Aだけが変更する。
  • 独立worktree: B/CはAが公開した同一tipから開始し、同じworktree・branch・未commit差分を共有しない。Dはexact candidate treeを検証する。
  • largest-ready: file・symbol・callerだけでなく、business fact・table・write owner・DI・transaction / lock・route / RBAC・gateまで非競合な候補だけを並行化する。固定domain順は作らない。
  • central surface: backend/cmd/api/main.go、backend/docs/api.yaml、handler.go、master_routes.go、service.go、repositories.go、route snapshot、OpenAPI drift、lint inventory、manifest、ADR-006、boundary map、BE-refactor.mdとcross-cutting packageはA専有。
  • 共有DB: Docker / DB-backed testはAのglobal leaseで直列化する。-p 1はprocess間の競合を防がず、別worktreeだけでもCompose project・DB・bind mountは分離されない。Docker checkはcontainer sourceとcandidate tree / 対象file hashの一致を証明し、証明できない結果は合格根拠にせず、Aが統合したexact tipで再実行する。
  • handoff: base commit、candidate commit / tree hash、path allowlist、structural / behavior区分、共有面の変更要求、scoped検証結果、未解消事項を必須とする。Dがcandidate tree hashを固定して検証し、Aとのtree一致と反証結果が揃うまで統合しない。
