S1 — #249 検査機能条件付き

  • legacy 相当 CSV は 1,324,612 行中 1,323,933 行で field ID が空。ID-only pivot は不可。読み取り専用の visibly-unmapped 表示と mapping/backfill review を先に行う。
  • reference range は clinic ownership を DB で強制できる schema にし、species は既存 animal_species_id を正本にする。
  • lab import の自動 commit は最後。初期 auto_commit=false、実機形式確認、代表データの手動照合、権限付き enable、停止・通知・監査を必須とする。
  • #211 の A1+A2/A6 は実装済み。A6 は checkup_type_fields → checkup_types 複合 FK であり、exam_results ではない。残りは USER の DB 適用確認と臨床確認。

S2 — カルテ・飼主安全境界を先に固定

  • #237 は correlated EXISTS を使い、JOIN する全 master を medical_records.clinic_id で再度 scope する。result と count は同じ条件を使う。
  • #238 は条件付き OPS ではなく確定 backend bug。inactive 種別を公開一覧と直接予約 API から拒否し、既存予約表示は残す。
  • #234 は既存の危険理由記録工程を確認して一本化を先に判断。理由は owner-facing DTO からキーごと除外し、院内 UI は touch/focus/keyboard でも1操作で確認可能にする。
  • #235 は既存 upload path を再利用し、確定済みカルテでは drop UI・handler・BE の全境界で追加を拒否する。

S3 — 会計・医院間リンクBlock

  • #251 は surgery、hospitalization、vaccine、hotel、training を含む全書込経路を棚卸ししてから BE/FE の分類 contract を決める。根拠のない other default は使わない。
  • #247 は現行締め表の単純移植を禁止。discount・tax・insurance・refund・端数・件数の定義を決め、動的な支払方法列と row/column/grand total の保存則を共通 helper で保証する。
  • #239 は明示 search → 手動 link/unlink → 最小履歴を先に検証し、候補自動化は最後。全 request ID の clinic scope、専用権限、custom RLS、transactional audit、owner/pet 整合を実装条件とする。
  • #212 は current phase から外し、正式 CI baseline と PO の coverage policy 決裁後に高リスク repository test へ分解する。

依存・実行ルール

  • migration: 作成直前に実ファイル最大+1を再計算する。監査時点の最大は 002（現在作るなら 003）。#249・#234・#239・#250 を含め、作成と integration は単一担当が直列化する。
  • 並列化: 独立 worktree／checkout と file ownership を使い、単一 integration owner が順に取り込む。S2 owners と #239、S1 examinations と #239 は重なる。同一 dirty worktree で blind git pull しない。
  • 哲学: 要件ごとに一人の責任者と業務目的を確定し、削除→簡素化→高速化→自動化の順で判断する。確認ダイアログを安全装置にせず、二重入力・二重管理を増やさない。
  • 責任者: 公開 Issue から access-controlled 台帳上の一人へ一意に解決できることを開始条件とする。「現場」「担当部門」だけでは着手しない。
  • 横断規約: 仕様機能を推測追加しない。ただし clinic isolation、input validation、audit atomicity、API/docs/type sync、既存 security/verification gate は Issue の書き漏れでも省略せず、先に Issue を修正する。
  • 外部操作: scoped verification のみ自動実行。push、本番操作、credential・billing 変更は明示依頼なしに行わない。
