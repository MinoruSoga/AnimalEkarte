全セッション共通の運用ルール

  • ブランチ: main 直接（feature branch 禁止）。commit 直前に必ず git pull で HEAD 確認（並列セッションのコミット衝突防止）。
  • 検証: 各 Issue 記載の scoped コマンドのみ自動実行。フルテスト・フル lint・build は自動実行禁止（必要ならユーザーに手動実行を依頼）。
  • push: ユーザー所有アクション — エージェントは依頼があるまで push しない（旧 BE_todo「OPS-PUSH-GATE」は台帳再編で廃止・現行正本 = todo.md 運用規約。2026-07-16 更新）。
  • 哲学: 確認ダイアログでの安全対策禁止／二重管理・二重入力の新設禁止／仕様外の推測実装禁止（Issue に書いていないことは作らない）。
  • 個人名: Issue・コミットに個人名を書かない（バックログシート No.X 質問者欄参照の形式を維持）。
  • 詰まったら: Issue 本文の file:line が行ドリフトしていたら関数名・定数名で再特定（HEAD 1570778e 基準で記載）。docs 再編（7/16）で Issue 内の旧 docs パスは移動済み — docs/ERD.md→docs/architecture/erd.md、docs/adr/→docs/architecture/adr/、screens 系→docs/spec/screens/、docs/tasks/→削除（git 履歴参照）。api.yaml の正は backend/docs/api.yaml。
