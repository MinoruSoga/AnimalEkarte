このファイルがやらないこと
① Issue の受け入れ条件を複製しない。条件・仕様・議論の正本は各 GitHub Issue の本文とコメント。
② Issue の state を持たない。open / closed は gh issue list --state open の実測が正。本 view の一覧が実測とずれたら実測が正しい。
③ ローカル残タスク（TASK-* / SD-* / SCEN-*）を持たない。正本は todo.md。ID 体系は本 view と無関係。
④ 決裁を持たない。PO 判断・USER 操作待ち・記入フォームの正本は q&a.html。
⑤ 件数・commit hash を固定値で埋め込まない。ドリフトの温床になる。数えるときはその場で実測する。

運用

  • Issue がクローズされたら本表から行を削除する。完了記録は GitHub Issue と git 履歴が正本であり、本 view に履歴を残さない。
  • 分類が変わったら書き換える。特に「依存待ち → 着手可能」への遷移（先方データの到着など）を見落とさない。
  • 着手するときは Issue 本文を読む。本 view の「次のアクション」は着手順を決めるための要約であって、受け入れ条件ではない。
  • 新しい Issue が立ったら行を足す。ローカルの残作業（TASK-* 等）は足さない — それは todo.md の領分。
  • 並行実行の排他は AGENTS.md の packet claim protocol（git branch claim/<ID>）に従う。claim の解放は USER 専権。
