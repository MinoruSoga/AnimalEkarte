全セッション共通の運用ルール

  • ブランチ: main 直接（feature branch 禁止）。commit 直前に必ず git pull で HEAD 確認（並列セッションのコミット衝突防止）。
  • 検証: 各 Issue 記載の scoped コマンドのみ自動実行。フルテスト・フル lint・build は自動実行禁止（必要ならユーザーに手動実行を依頼）。
  • push 前: BE_todo の OPS-PUSH-GATE を通すこと。
  • 哲学: 確認ダイアログでの安全対策禁止／二重管理・二重入力の新設禁止／仕様外の推測実装禁止（Issue に書いていないことは作らない）。
  • 個人名: Issue・コミットに個人名を書かない（バックログシート No.X 質問者欄参照の形式を維持）。
  • 詰まったら: Issue 本文の file:line が行ドリフトしていたら関数名・定数名で再特定（HEAD 1570778e 基準で記載）。
