STG AWS 環境 → Cloudflare 全面移行 調査レポート

Animal Ekarte（動物病院向け電子カルテ）の Staging AWS バックエンド/インフラを Cloudflare ネイティブ構成へ全面移行した場合の、リソース対応関係・移行リスク・JPY 建て費用（STG 実態 / 本番投影の 2 シナリオ）・移行可否の結論を、リポジトリ IaC を一次情報として検証した。結論を先に言う: DB 本体を Cloudflare がホストする経路は依然存在しないが、PlanetScale 提携（2026-06-18）により「Cloudflare 課金・管理に一元化された Postgres」が成立した。推奨は引き続きハイブリッド構成（ただし DB の選択肢が拡大）。

🔄 前回調査（2026-06-28）からの主要な変化（2026-07-04 再調査）

  • PlanetScale 提携（2026-06-18 発表・最重要）: Cloudflare ダッシュボードから PlanetScale Postgres/MySQL を直接作成し、Cloudflare アカウントに課金統合できるようになった（pay-as-you-go は提供中、契約顧客は 2026-07 から）。Hyperdrive 自動連携。「Cloudflare がマネージド Postgres をホストしない」事実は不変だが、調達・課金・管理が Cloudflare で完結する Postgres が成立し、DB 戦略の選択肢が実質 1 つ増えた（§④に案C として追加）。
  • Workers VPC が拡充（public beta）: VPC Services（2025-11 beta）に加え VPC Networks + Cloudflare Mesh 対応（2026-04-14 beta）。Cloudflare Tunnel 経由で AWS VPC 内の private RDS へ Workers から直接到達可能（TCP DB は Hyperdrive 経由）。beta 期間中は無料。「既存 RDS を private のまま Cloudflare 背後に置く」経路の実装手段が具体化した。ただし GA 前であり本番採用は時期尚早。
  • Hyperdrive のキャッシュ挙動変更: STABLE 関数を含むクエリもキャッシュ対象外になった（VOLATILE に加え）。臨床/会計データの陳腐化読み取りリスクが公式側で一段緩和。
  • Containers 機能拡充: exec()（2026-06-18、稼働中コンテナ内プロセス実行 = ./migrate one-shot の代替手段として有力）、カスタムインスタンスタイプ全ユーザ開放（2026-01）、Google Artifact Registry 対応（2026-07-01）。料金表は変更なし。
  • Neon の料金改定（Databricks 買収後）: 月額最低額が撤廃され完全従量制に（2025-12〜）。ストレージ $0.35/GB-月。常時起動 1CU の月額推計は ~$95 で前回と同水準だが、根拠となる体系が変わった。
  • 為替: 161.7 → 161.2 JPY/USD（2026-07-03/04 取得）。JPY 建て金額を全面再計算。
  • 変わっていないこと: Cloudflare 自身がホストするマネージド Postgres は依然として存在しない。D1 は SQLite・10GB 上限で不変。Workers/Containers/R2/D1/DO の料金表も前回から変更なし。AWS 側単価（Fargate/RDS/ALB 東京）も Price List 再取得で実質変更なしを確認。総合 Verdict（全面移行は不可・ハイブリッド推奨）は維持。

総合 Verdict

「STG AWS を丸ごと Cloudflare へ全面移行（DB 含む）」は依然不可能・非推奨。理由はただ一つ — Cloudflare 自身は マネージド PostgreSQL をホストせず、D1(SQLite) への移植は本電子カルテの Postgres 依存（ENUM 型・配列・jsonb・CTE・生 SQL・clinic_id マルチテナント・臨床/会計データ整合性）に対して高工数・高リスクで割に合わない。ただし PlanetScale 提携により「Cloudflare 課金・管理に一元化された外部 Postgres」という中間解が成立し、「実質すべて Cloudflare の管理画面で完結する」構成には近づいた。

現実的な推奨はハイブリッド: エッジ層（DNS/CDN/SSL/WAF）と画像ストレージ（R2）を Cloudflare へ寄せ、DB は外部マネージド Postgres + Hyperdrive で残す（PlanetScale なら課金も Cloudflare に統合可）。最小リスク・最大 ROI の第一手は 「R2 への画像移行」+「既存 AWS スタックの前段に Cloudflare を被せる」。コンピュート（ECS→Containers）の移行は任意で、既に安定動作する Fargate を置き換える積極的理由は薄い。詳細は⑥移行可否。

⚠ 検出した IaC ↔ ドキュメントのドリフト（要報告）

  • RDS エンジン版数: Terraform は engine_version = "16.4" / param family postgres16（modules/rds/main.tf:42,26）だが、root CLAUDE.md と Cost 調査ドキュメント（read-only describe・2026-06-17）は PostgreSQL 18 と記載。IaC と実環境記述が食い違う。移行分析の結論には影響しないが、IaC を権威としつつ実環境版数の確認を推奨。
  • ALB scheme: Cost ドキュメント（2026-06-17 時点）は internet-facing(public IP 2)で計上。現行 terraform.tfvars は alb_internal=true（P2 適用後 = internal）。費用シナリオ①では両状態を併記。
  • AWS 認証: 本調査環境の AWS CLI は有効な認証情報を持たず（InvalidClientTokenId）、実 API での裏取りは不可。棚卸しは IaC を根拠とする。

④ データベース戦略（DB戦略）比較

Cloudflare へ移行する上で唯一かつ最大の論点。2 案を制約・書き換え工数・リスク・推奨度で比較する。

前提事実: Cloudflare 自身がホストするマネージド PostgreSQL は存在しない（2026-07-04 再確認）

Cloudflare の自社 DB 製品は D1（SQLite） と Durable Objects（SQLite）、そして外部 DB を高速化する Hyperdrive のまま。ただし 2026-06-18 の PlanetScale 提携により、Cloudflare ダッシュボード（Storage & databases > Postgres & MySQL）から PlanetScale Postgres を作成し、使用料を Cloudflare アカウントに課金統合できるようになった（Hyperdrive 自動連携・pay-as-you-go 提供中）。DB 本体のホスト先は PlanetScale（AWS/GCP 上）であり「Cloudflare に移す」ことは依然できないが、調達・課金・接続管理の一元化という意味では実質的な前進。

なぜ D1 を不採用とするか（senior judgment）

本電子カルテのスキーマは Postgres 依存が深い — CREATE TYPE ... AS ENUM（migrations/001_init.sql:95 等）、text[]、jsonb、CTE(WITH)を用いる集計 SQL（例: accounting_repository_reports_monthly.go / accounting_repository_reports_close.go）、raw SQL＋Postgres 固有関数を直書きする集計（EXTRACT・:: キャスト等。例: ltv_repository.go）、clinic_id マルチテナント、臨床・会計データの整合性要件。SQLite はネイティブの ENUM・配列を持たず、JSON も方言が異なり、10GB のハード上限（拡張不可・2026-07 再確認）は成長するカルテ/画像メタには非現実的。全 repository 層・全 migration・全型定義を書き換える 30+ 人日の作業を、臨床/会計データの回帰リスクと引き換えに行う合理性はない。よって案B/案C（外部 Postgres + Hyperdrive）を推奨とする。最も低リスクなのは 既存 RDS をそのまま外部 Postgres として Hyperdrive の背後に置く構成（DB 移設すら不要・Hyperdrive の RDS 対応は公式確認済。private RDS のままなら Workers VPC beta の Tunnel 経由も可）。

外部移設する場合の現実解（単一インスタンス・データ <50GB・2026-07-04 取得料金）:

  • PlanetScale PS-40 arm 単一ノード ~$48/月（本体 $28 + ストレージ超過 40GB×$0.50=$20。10GB 込み。CF 課金統合可）— 最安の有力候補。
  • Supabase Pro + Medium ~$75/月（Pro $25 + Medium $60 − $10 compute クレジット）。
  • Neon Launch 常時起動 推計 ~$95/月（2025-12 の改定で月額最低額撤廃・完全従量制。1CU 24/7 = 730h × $0.106 ≈ $77 + ストレージ 50GB × $0.35 ≈ $18。scale-to-zero を許容すれば大幅減）。

HA/SLA が必要なら PlanetScale PS-40 HA(3ノード) $83 + ストレージ超過 3 台分 $60 = ~$143/月、Neon Scale($0.222/CU-h)常時起動+レプリカ推計や Supabase+replica で $150〜250/月。料金出典: planetscale.com/docs/postgres/pricing / neon.com/pricing / supabase.com/pricing（いずれも 2026-07-04 取得）。

⑥ 移行可否（結論・Verdict）と推奨アーキテクチャ

Verdict: 「DB を含む全面 Cloudflare 移行」は依然不可。ハイブリッドを推奨（再調査後も結論維持）。

費用だけ見れば Cloudflare は両シナリオで安い（STG −77%、本番 −45%）。しかし「すべて Cloudflare」を額面どおり実現する経路は存在しない — Cloudflare 自身がホストする Postgres は無く、D1 化は電子カルテの Postgres 依存に対して 30+ 人日・高回帰リスクで割に合わない。したがって DB は外部に残らざるを得ず、定義上「全面移行」は成立しない。ただし 2026-06-18 の PlanetScale 提携により「DB を含め課金・管理を Cloudflare に一元化する」ことは可能になった（DB 実体は PlanetScale ホスト）。「単一ベンダー管理」が目的なら、この構成は実務上「ほぼ全面 Cloudflare」と呼べる水準に達している。

3 つの選択肢と推奨

選択肢 1 — フル Cloudflare 化（Containers + 外部PG+Hyperdrive + R2 + Edge）

条件付き エッジ/コンピュート/ストレージは Cloudflare に集約でき、DB も PlanetScale 経由なら課金・管理は Cloudflare に一元化可能（ホストは外部）。本番 ~¥28,200/月。ネック: Containers の運用実績の浅さ・CPU 課金変動・DO 結合・外部 Postgres 依存。コスト削減は得るが、安定稼働中の ECS を新基盤へ載せ替える移行リスク（10〜25 人日）を負う。戦略的にエッジ統合を狙う場合のみ妥当。

選択肢 2 — ハイブリッド（推奨 ★）

推奨 エッジ層（DNS/CDN/SSL/WAF）と画像（R2）を Cloudflare へ。Go バックエンドは当面 ECS Fargate 継続、または段階的に Containers 評価。DB は外部マネージド Postgres + Hyperdrive（既存 RDS 温存 / PlanetScale で CF 課金統合のいずれも可。private RDS への接続は Workers VPC の GA を待って評価）。R2 の egress ゼロとエッジ無料枠を即取りしつつ、コンピュート/DB の再プラットフォーム化は実証後に判断。低リスクで大半の利得を獲得。

選択肢 3 — 最小手・前段のみ（最速 ROI ★）

第一手として最適 既存 AWS スタックは温存し、(a) 臨床画像を S3→R2（1〜3 人日・egress ゼロ）、(b) 既存 CloudFront の前段に Cloudflare DNS/CDN/SSL/WAF を被せる（1〜2 人日）。コンピュートも DB も触らないため移行リスクほぼゼロで、確実なコスト/運用利得を得る。ここから段階的に選択肢 2 へ進める。

移行の前提・残課題（senior の警告）

  • データレジデンシ/医療コンプラ（重要）: AWS 本番は東京リージョンで患者/飼主 PII の所在を固定できるが、Cloudflare の Workers/Containers はエッジでグローバル実行される。処理場所を地域に固定するには Data Localization Suite（有料アドオン）が必要で、本費用試算には未計上。医療データの所在要件があるなら DLS 採否・費用を意思決定前に確定せよ。
  • WAF の費用: 推奨スタックの "WAF" は無料プランの限定マネージドルールセットを指す。フル WAF（マネージドルール一式・レート制限等）は Pro/Business ゾーンプラン（$25〜200+/月・ゾーン単位）を要し、費用表には含めていない。要件次第で Cloudflare 側コストが上振れる。
  • バックアップ/PITR/DR: RDS の自動バックアップ + ポイントインタイムリカバリ（RPO/RTO）に対し、外部 Postgres(Neon/Supabase)の PITR・DR 能力と費用は別途比較が必要。HA だけでなく復旧要件も EMR では同等に重要。
  • 固定 egress IP: LINE 連携等の IP allowlist がある場合、Cloudflare の egress は固定 IP 設計（専用機能）を別途要する。fck-nat の EIP 安定化が担っていた役割の代替を見落とすな。
  • Hyperdrive のキャッシュ整合: Hyperdrive のクエリキャッシュは陳腐化した読み取りを返し得る。2026 年の変更で VOLATILE に加え STABLE 関数を含むクエリもキャッシュ対象外となり公式側でリスクは一段緩和されたが、臨床/会計の整合性が要る経路では引き続きキャッシュ無効化を明示すべき。また Hyperdrive は LISTEN/NOTIFY・advisory lock・SQL レベル prepared statement 非対応（GORM の既定 prepared statement 設定の確認要）。長時間稼働 Container は GORM でプール可能なため Hyperdrive は必須ではなく任意。
  • 監査ログ保持: 医療系の監査証跡要件に対し Workers Logs の 7 日保持は不足。Logpush→R2/外部 SIEM の長期保管設計が必須。
  • migrate one-shot: 現行は deploy 時に ECS one-shot タスクで ./migrate を実行。Containers では exec() API（2026-06-18 提供開始）で稼働中コンテナ内のプロセス実行・exit code 取得が可能になり、置換設計の主要な穴が埋まった。CI からの起動トリガ設計は依然必要。
  • Cookie 認証: SameSite=None; Secure のクロスドメイン Cookie 認証が、ドメイン/エッジ構成変更後も成立することを検証せよ。
  • Containers の成熟度: 2026-04-13 GA から約 3 ヶ月。GA 後も exec()・レジストリ対応等の基盤機能が毎月追加されている段階であり、本番電子カルテを初期採用者として載せる運用リスクを過小評価しないこと。
  • Workers VPC は beta: private RDS へ Workers から到達する経路（VPC Services / VPC Networks + Tunnel）は公開 beta で無料提供中だが、GA 前で API 変更があり得る。GA 時に料金が設定される可能性も高く、本費用試算には未計上。本番採用は GA 後に判断。
  • PlanetScale 採用時の固有論点: Postgres ストレージは 10GB 込み・超過 $0.50/GB/インスタンス（HA は 3 ノードに課金）。バックアップは 12 時間毎で、RDS の PITR（秒粒度）との差を EMR の RPO 要件と突き合わせること。コントラクト顧客の課金統合は 2026-07 開始。
