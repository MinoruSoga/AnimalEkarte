## 継承契約

<a id="requirement-fr-common-ui-state"></a>
### FR-common-ui-state — 状態と可読性

[状態正本](../design-states.md)のdefault／hover／active／focus-visible／disabled／readonly／loading／invalid／selectedを維持。キーボードフォーカスを不可視にせず、loadingはラベルを保持してスピナー・aria-busy・操作抑止を併用。readonlyはdisabledと意味が違い、読める値を維持する。sentinelを色だけで示さない。44pxタッチ目標とdense例外は正本の条件を使い、全画面を無条件に縮小しない。

色値はdesign-system、寸法・余白等はDESIGN、状態はdesign-states、配置方向はdesign-token-layers。PALETTE→C／STATE→STYLE／BADGE等の責務を維持し、Tailwindの静的文字列制約を理由にしたL2の値重複を欠陥としない。raw色を使うcanvas等の明示例外は保持する。

<a id="requirement-fr-common-ui-primitives"></a>
### FR-common-ui-primitives — 部品の操作境界

- [Badge](../components/badge.md)は識別用で、クリック操作はButton等へ。非色cueを維持。
- [Button](../components/button.md)は既定type=button、loading中に操作を起動せず、アイコン単独には名前を付ける。
- [Dialog](../components/dialog.md)はタイトル・説明・focus復元・ESC等の契約を保持。確認必須操作はAlertDialog。X占有領域を入力や操作ボタンへ重ねない。閉じる操作そのものに業務取消・保存・削除の意味を与えない。
- [Input](../components/input.md)／[Select](../components/select.md)等の必須入力には必須マークを示し、未入力・検証エラーは赤枠と文字メッセージで対象欄を識別できるようにする。Backlog Phase1 No.86 F87:G87、2026-10-15曽我回答が根拠。既存の任意項目を必須化せず、色だけに頼らない。invalidの文字説明とlabel接続を保持。Selectの選択肢取得中制御は親の責務。空文字value禁止。検索式選択は適切な検索部品へ。
- [Table](../components/table.md)の行全体onClickは禁止。明示した行内actionを使い、ヘッダ意味論・空／読込表示と既存例外を保つ。
- [Tabs](../components/tabs.md)は同一データの切替。別ページ遷移にはナビを使い、disabled理由を補う。

<a id="requirement-fr-common-ui-context"></a>
### FR-common-ui-context — 患者文脈・離脱・共有範囲

PatientInfoCard利用フォームはtrimming/checkups/examinations/hospitalization/vaccinations。カルテは[EMR-412の採択判断（2026-10-15 Q1→X13、#679採用）](https://github.com/MinoruSoga/AnimalEkarte/pull/679)に従い、MedicalRecordStickyHeaderがPatientInfoCardを内包する。属性表示をカードへ渡し、hideStaff/hideReservationTypeを用い、来院種別・診療日・担当医の操作はStickyHeader側へ維持する。[現行カード契約](../screens/common-dialogs.md#11-患者情報カード-patientinfocard)を参照し、同一部品未使用という旧現状記述は採用しない。欠損年齢・性別・去勢避妊を不明として示し、speciesがあれば実値を出す。onOwnerClickはカルテの既存caller条件・現在認可を維持し、新たな画面や利用権限へ開放しない。StaffSelectionModalはカルテ専用、PropertyFilterのdeferは利用側の責務という境界を保つ。

NavigationBlockerはdirty時のSPA内遷移、併用useUnsavedChangesはブラウザ離脱を担当する。ガードの存在は全writerの永続保存済みを意味しない。OwnerSearchModalの汎用変更確認と、OwnerForm側の会員区分／値引差の警告を混同しない。飼主の付替えを許可する対象・金銭影響・医院scopeはD03/D04/C04の正本へ渡す。

左メニューの各項目には画面の役割・説明を用意し、マウスホバーとキーボードフォーカスのどちらからも確認できる。[Backlog Phase1 F74:G74（No.73）](https://docs.google.com/spreadsheets/d/17jaFBv7NmbPzk88lZx94vFxa_G1shGNX2O_lFGt4QdQ/edit#gid=0&range=F74:G74)、2026-10-15曽我回答が根拠。説明を読むだけで画面遷移や保存を起動せず、既存のフォーカス可視性・メニュー表示権限を維持する。対応完了の原文報告を今回の実機合格にしない。

<a id="requirement-fr-common-ui-pet-selection"></a>
### FR-common-ui-pet-selection — 選択と作成の分離

予約作成・各カルテ作成時の患者選択は、ペット名・飼主名・よみ・電話番号を扱う単一の横断検索欄へ統一する。飼主の姓と名は空白の有無を吸収するが、ペット名と飼主名の2語は空白で区切り、両者の連結入力を対象にしない。予防接種の飼主検索でも姓名間の空白を吸収する。各一覧の検索述語の完全統一はPhase2で、既存の画面固有検索・認可・ページングを一律変更しない。根拠はBacklog Phase1 No.74・77・81（F75:G75、F78:G78、F82:G82）の2026-10-15回答。

対象はmedical-records/hospitalization/trimming/examinations/checkups/accounting/vaccinations。検索はsearch・owner_id=owners.id・動物種マスタID、20件サーバページングを維持し、検索の発火は[10/19明示実行](#owner-pet-explicit-search-20261019)へ。旧300ms debounceは旧文書/限定的な実装観察として区別し、現在全callerの未追従と断定せず、住所検索は追加しない。通常は利用機能create、checkupsはmedical-recordsのcreateかつeditという既存例外を維持し、C04で再照合する。

死亡個体は死亡表示付きで選択できるが、この選択可の適用範囲は上記7機能であり、予約作成を含む共通の検索操作の範囲（前々段）とは区別し、予約フォームでの死亡ペット選択はこの選択可の対象外とする。新規未来予約・死亡後の新しい臨床実施は許可しない。生前診療の後日入力・誤記訂正・退院・精算は[C03の追加承認](clinical-safety.md#requirement-fr-common-safety-patient)に従い、死亡状態を維持した理由／履歴付きの専用経路として区別する。カルテselectorは当該ペットの一覧へ渡す。未知生死statusは選択fail-closed。死亡選択可を全フォームでの無制限な臨床操作可へ広げない。

特記はペットdanger_levelと飼主is_dangerousを別概念として扱う。ペット高／中は形状アイコンとPopover、メモ空は内容未登録。飼主は代替名「特記」の形状アイコンでPopoverなし。スタッフ向けで、分類が分かる文言を画面・aria-label・titleへ出さず、owner/LIFFへ出さない。一般の非色cue規則を理由に機微な分類語を追加しない。

## 入力中のEnterによる誤保存を防ぐ（2026-10-17本人確認）

入力中のEnterを、本人が意図していないフォーム送信・保存確定へつなげない。全入力欄に一律「Enterを2回押す」操作を要求する方針にはしない。対象画面・入力欄、IMEが原因かどうか、既に実装修正済みかは未特定であり、特定画面で発生・再現・解消したという事実を補わない。

原要望は2026-09-15 16:56:45 JSTの城東PC（SLK-291、ts1789459005.162369）の「エンターを一回押すと入力確定してしまうのでエンター2回で確定にしてほしい」、19:30:30 JSTの曽我返信は「こちら修正対応を行います」。本人Sentinel_fd16cb27f1b4819192fee859e0ed3d7b「保存されてしまうということでは？」を受け、「入力中のEnterで誤保存しないこと」と整理し全入力欄に一律Enter2回を要求しない方針を確認、2026-10-17 21:52:54 UTCの本人Sentinel_245605c234d08191913aba96a2c85a4b「そうですね」で承認された。旧文言から全アプリのEnter回数仕様やIME原因を推測する解釈は、この本人確認に置き換える。

[通常カルテの既決自動保存](../domains/medical-records/lifecycle.md#medical-record-agreement-autosave-20261015)は維持する。入力変更に伴う正規の自動保存と、意図しないフォーム送信・明示保存の発火を区別し、保存通信があるという理由だけで誤保存と判定しない。複数行入力の改行、候補の選択・確定、既存のキーボード操作を一律禁止しない。保存ボタン等へフォーカスした明示的な実行まで禁止する意味にせず、入力部品内の操作とフォームの保存確定を区別する。

対象画面・入力欄と、変換中／変換確定後・候補選択中等の条件、保存操作の種類、イベントの伝達・制御、具体的な操作回数は実態調査・設計で照合する。今回の承認だけで「1回目は必ずIME変換、2回目は必ず保存」と確定しない。臨床記録・会計等の既存保存契約、認可・競合検査・状態保護は維持し、実装や実機合格とは分ける。

<a id="requirement-fr-common-ui-interaction-consistency"></a>
### FR-common-ui-interaction-consistency — 同じ意味の操作を同じ挙動へ

全画面で、操作の用途・対象・結果が同じ場合は、実行、クリア、状態保持、戻る、エラー時の挙動を共通契約へ揃える。見た目/部品名が同じだけで異なる業務操作を同一化しない。「閉じる」「取消」「クリア」「リセット」「検索」「保存」「再試行」の意味を画面都合で入れ替えない。既存の保存・確定・訂正・臨床安全と現在認可を維持する。

| 操作の意味 | 共通の扱い | 個別業務へ残す境界 |
|:---|:---|:---|
| 明示実行 | 何を対象に実行するかと実行中状態を示し、同一操作の意図しない重複起動を防ぐ | 検索と患者選択/保存/請求/配信は別。副作用のある操作の二重実行防止は各ownerの契約へ |
| 検索入力の消去 | 入力中文字列を消すだけでは適用済み条件/結果を変更しない | 検索ボタンによる空条件適用、既存明示リセットと区別。項目値のclearや業務取消とは別 |
| 明示リセット | 操作が示す既存対象だけを解除し入力中/適用済みを合わせる | 医院・日付・患者・独立filterを無断全解除しない。新ボタンを全画面に必須化しない |
| 状態保持・戻る | 同じ一覧の詳細から戻る場合、適用済み検索/医院/患者/日付等の文脈を保持。未適用入力を勝手に適用しない | メニューから開く日付初期値等は[既決一覧契約](#list-filter-contract-20261017)の対象/例外を維持。保存先が未選定なら実装工程で方式を選ぶ |
| 閉じる・取消 | 閉じるだけで業務取消/削除/保存を起動しない。失敗・競合時は入力と対象を保持して結果を示す | 自動保存済みカルテのタブclear/複製取消、確定済会計訂正等は各ownerの目的別処理。全画面の保存方式やUndoへ統合しない |
| エラー・再試行 | 未取得/取得中/真の0件/失敗/認可拒否/結果不明を区別し、元の対象と適用条件で再試行する | 書込結果不明を検索retryで救済しない。各ownerの結果照会/訂正と分ける |

### FR-common-ui-explicit-business-search — 業務一覧と飼主・ペット選択

[適用台帳](interaction-scope.md)のL/M/H/S行が対象。業務一覧は通常の診療/会計一覧、管理マスタ/タグ/顧客集計、および保存済み業務履歴の一覧にある既存キーワード欄を含む。サーバ検索か現在ページ内の絞込みかは発火契機と別であり、双方とも検索ボタンで実行する。N行にはキーワード欄を新設しない。E行の入力補完・診療項目候補・記事探索等は用途別の既存契約で、今回一律に検索ボタンへ変えない。

先の[入力/適用分離と4AC](#owner-pet-explicit-search-20261019)を全対象へ適用し、検索入力変更・300ms待機・blur・IME確定だけではAPI送信/ローカル絞込み/URLの適用条件を変えない。「検索」の明示起動で検索欄一組を適用し、ページングを持つ画面は検索条件変更時に先頭ページへ戻す。キーボードによる検索ボタン起動は可、入力欄Enterの新しいshortcutは採用しない。既存の候補確定/改行/正規自動保存を一律禁止しない。

既存の独立filter・sort・page・tab・医院切替の適用タイミングは維持し、再取得/再計算には適用済み検索語を使う。入力中Bを持つ状態で他filterを変えてもBを混入しない。初回表示/URL直達は既存適用条件で取得し、毎回ボタンを押すまで初回一覧を出さない方式にはしない。詳細復帰も適用済み値から復元する。未適用入力の永続化は必須にしない。

検索中も入力文字と旧結果の所属条件を保持して識別し、最新の適用条件/対象/医院scopeの要求だけを採用する。失敗を0件/未納なし/在庫なし/空きへ変換しない。失権時は旧結果を操作根拠にせず、認可外を隠す。候補選択では未適用入力との不一致中、取得中/失敗/対象不明の結果から新しい選択確定をしない。検索だけで患者/記録の付替え・link・保存・会計・印刷・送信を起動しない。

空文字/空白正規化/最小文字数/ANDやカナ等の述語、取得上限、医院/患者範囲、日付、ページング、コピー可否は各画面の既存契約を維持する。ページ内絞込みを全件検索へ拡張せず、現在ページ内/上限付きはその範囲を示し、未取得の他ページまで0件と断定しない。`useDeferredValue`は適用後の描画最適化として利用可能だが、入力だけで検索を適用する根拠にはしない。旧debounce/リアクティブ検索の記載は旧文書/旧実装観察に限る。現HEAD全caller適合は未確認。
