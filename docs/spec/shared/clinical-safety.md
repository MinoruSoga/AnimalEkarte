## 正本・適用順

[全体要件§2.1](../specification.md)の臨床安全は[業務効率の思想](../../product-philosophy.md)より優先する。安全手段の選択は効率化の検討対象でも、安全性自体を削らない。具体的な保存・臨床状態・薬量条件は[D03正本](../domains/medical-records/lifecycle.md)と[技術契約](../../design/domains/medical-records/technical-spec.md)。本書から他ownerに未承認の一律確定ロックや新職種を導入しない。

<a id="requirement-fr-common-safety-patient"></a>
### FR-common-safety-patient — 患者文脈と死亡ゲート

識別表示を伴う死亡個体の選択と、新規予約・死亡後に実施する新しい臨床行為の禁止を区別する。生前の診療の後日入力・誤記訂正・退院処理・精算は、死亡登録を取り消さず理由と履歴を保持して行える（質問 Sentinel_2b63d8f5aad88191aa2b4dff79fb5ac2／回答 Sentinel_45be2cab0fe4819188c7c0f9a211358c）。既存記録の閲覧・許可済み追記を含め、通常の新規予約ゲートへ一律に流して拒否しない。対象患者・生前の元事実／実施日・訂正又は精算対象を確認し、不明な実施時点を推測しない。金銭・在庫・通知への自動副作用は各ownerの既決境界を保持する。未知status・患者／医院／関連の照合失敗を正常へ置換しない。実際の操作例外は各D正本。staff向け特記をowner向け情報へ漏らさない（[患者選択](../screens/00-pet-selection.md)）。

<a id="requirement-fr-common-safety-finalize"></a>
### FR-common-safety-finalize — 確定・訂正と安全性

旧FR IDを保持し、[2026-10-15のD03最新合意](../domains/medical-records/lifecycle.md#medical-record-agreement-autosave-20261015)へ同期する。通常カルテの医師確定ボタンと旧finalizedだけの通常編集拒否は置換し、診療終了後も通常編集できる。自動保存を含む既存hybridを維持し、以前の保存版・追記・必要監査を保持する。タブクリアは開いた時点、履歴複製取消は対象複製の直前を基準に、自動保存済み値も履歴付きで復元する。他タブ・他者版・後続実行を無警告で巻き戻さず、元履歴の削除・物理削除・金銭／在庫の逆実行へ変換しない。

確認ダイアログだけで安全性を成立させず、サーバ側の対象／現在版／依存・認可・必要ログを検査する。患者取り違え等の目的別訂正、D07検査確定やD11見積承認後の独自保護、精算確定歴がある予約の通常Undo停止は維持する。診療終了は会計待ちへの状態操作であり、記録・請求・入金の確定ではない。スタッフ向け履歴の掲載は診療終了を条件とし、途中保存や入金で代用しない。

<a id="requirement-fr-common-safety-evaluation"></a>
### FR-common-safety-evaluation — 未評価・不明と安全判定の分離

評価不能時の理由付き手入力はD03の合意条件と医師確認に従う。評価可能な絶対上限超過を確認で解除しない。通信・認可・患者／薬剤照合の失敗を「未設定だから手入力可」へ変換しない。薬量の数値・対象薬・種・単位・出典の医師承認は別工程で、ここでは承認しない。未完了プランは診療終了時に警告し、終了権限のあるスタッフが確認すれば未完了でも終了できる。自動保存時はこの警告を出さず、取得失敗の完了不明と区別し、確認・終了だけで実施済みへ変更しない。

<a id="requirement-fr-common-safety-audit"></a>
### FR-common-safety-audit — 意味のある変更を追えること

臨床・会計・権限の重要変更は明示された監査経路でactor・時刻を追跡する。全241テーブルの一律自動監査とはしない。integrityが必要な経路は必要監査失敗時にfail-closed。同一txの有無と選定仕様／現行実装差は[共通技術接続](../../design/shared/integration-contracts.md)で分ける。担当医を編集actorの代用にせず、確認医師・編集者・担当・指名は別概念を維持する。

<a id="requirement-fr-common-safety-automation"></a>
### FR-common-safety-automation — 自動化の停止・失敗・監査

業務状態を変える自動化は停止手段・失敗通知・手動代替と追跡可能性を持つ。手動ownerのuse caseを再利用し、定義された17トリガーやAPIキー保存をLステップ再開の証拠にしない。#259等の既存稼働停止条件を解除しない。自動化による便利さを理由に未確認の臨床値・資格・同一個体・配信対象を推測しない。

## 未確認・仕様完成の残件

全ownerの具体的なAC／権限／状態／ID／版／監査／競合契約をowner対応表とX01〜X08で照合し、一般原則の再掲だけでなく対象操作の成功・拒否・失敗／結果不明時条件を独立レビューした。患者context・D20公開範囲・原本保持・旧版更新の指摘は正本へ反映済み。基準da38895d時点の文書指摘は解消済み。追加9点の承認後の死亡境界・入力者と担当医・通知の適用を各ownerへ反映・独立文書レビュー済みで、文書整理を全業務承認へ変換しない。臨床数値の医師承認、実機・実装・運用／法的適合は別工程であり、新たに見つかる仕様不足を対象外へ隠さない。
