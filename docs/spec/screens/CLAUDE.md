## 📝 仕様書の記述ルール

1.  **情報の鮮度**: 画面変更や新機能追加の際は、速やかに該当ドキュメントを更新し、ソースコードとの乖離を防ぐ。バッククォートで言及したコンポーネント名・フック名・ファイル名はローカル必須ゲート（`make ci` 内の `scripts/check-docs-symbol-drift.sh`）が実在を機械検査する。実在しない名前はローカルゲートを失敗させる。
2.  **臨床安全の明文化**: ミスを防ぐためのバリデーション、警告表示、データ保護（NavigationBlocker）の仕様を必ず記載する。
3.  **アクセシビリティ**: キーボード操作やスクリーンリーダーへの配慮、意味的カラー（Destructive Red等）の使用基準を明記する。
