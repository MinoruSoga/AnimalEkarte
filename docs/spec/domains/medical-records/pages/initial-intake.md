<a id="initial-intake-scope"></a>
## 範囲・入口・保存先

通常カルテの独立した「問診」タブで初診時の回答を入力し、保存後に同じ患者の記録として参照できる。問診タブと診察／治療プランの統合は不採用。既存9タブ、[自動保存・タブ開始時へのクリア・履歴複製直前への取消](../lifecycle.md#medical-record-agreement-autosave-20261015)を維持し、保存ボタン方式や医師確定ボタンへ変更しない。

D03は問診時点の回答と出所を所有する。飼主・ペット属性の正本はD04、確認済みの検査結果はD07、接種実績はD08。問診からこれらの正本を書き換えたり実績を生成したりしない。保存時は医院・患者・カルテ・編集権限を照合し、担当医とは別の実編集者と変更履歴を保持する。以前の回答は現在回答で消さず、診療終了後も通常編集と以前の版保持を両立する。

<a id="requirement-fr-medical-records-structured-initial-intake"></a>
### FR-medical-records-structured-initial-intake：初診問診を入力・参照できる項目として持つ

既往歴、接種／投薬歴、注射・内服後異常、感染症検査歴を区別し、上表の臨床項目に回答状態と詳細の記録先を持つ。種別の違いを保持し、新しい必須入力や医学的適応の制約は追加しない。

- 「あり／はい」「なし／いいえ」「わからないという回答」「未入力」を区別する。未取得・取得失敗は別の読取状態。原紙に不明欄がなくても空欄を「なし」としない。
- 年、年月、概略時期、日付が分かる場合を区別し、分からない月日を1日・当日で補完しない。自由文の原表現を保持する。
- 異常歴の薬等が現マスタに見つからない場合も原記述を保存できる。名称一致で現薬剤ID・アレルギー原因を自動確定しない。
- 複数の病歴・接種／投薬・検査等を一件へ圧縮しない。新しい件数上限・問診回答の必須件数は設けない。

<a id="requirement-fr-medical-records-intake-provenance"></a>
### FR-medical-records-intake-provenance：自己申告と確認済み事実・以前の回答を区別する

回答内容には同医院・患者・当該カルテ、回答／聞取時点、実編集者・記録時刻、元資料／回答の出所、保存版を対応付ける。出来事の時期と今回の入力日時は別。飼主申告・原紙転記・既存記録参照を識別し、実際に確認していない結果を「確認済み」にしない。

FeLV／FIV等の自己申告検査歴はD07の院内保存結果・確認済み他院結果とは別。D07結果ID／版が確認できる場合だけ対応参照を付け、問診保存だけで結果を作成・確定・上書きしない。申告と結果が食い違う場合は両者の出所・時点を保持し、陰性・陽性の優先順位をここで決めない。

過去回答は参照可能にし、今回へ複製する場合も元患者・カルテ／保存版と複製対象を対応付ける。コピーだけで今回確認済み・今回投薬済みへ更新しない。項目選択・上書き確認・複製直前取消は既存契約へ従い、D04属性・D07結果・D08接種・予防薬実績を一緒に巻き戻さない。

## 技術・未決の扱い

[技術契約とtrace](../../../../design/domains/medical-records/technical-spec.md#medical-record-intake-prevention-contract)へ接続。項目対応・時期精度・出所の区別は採用要件を安全に実現する設計で、追加の業務質問ではない。原紙の全選択肢の新マスタ化、薬用量・禁忌判定、自動移行／外部取込、配信同意変更は範囲外。利用開始前に全6頁の入力・読戻しと旧データの欠損保持を検証する。
