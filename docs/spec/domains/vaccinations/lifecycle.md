<a id="fr-vaccinations-record"></a>
## FR-vaccinations-record：一接種一記録を二つの入口で共有する
独立フォームとカルテ内フォームは同じ接種資源を扱う。独立新規は患者を選択し、カルテ内新規は保存済みカルテIDと患者を指定する。カルテ内に別系統の接種台帳や架空のnested vaccinations APIを設けない。カルテ外側の保存ボタンでは接種保存しない。

一回の送信は一接種。複数のワクチン／予防薬を同じ患者・同日に順次登録でき、名称・lot1〜4・次回予定・備考・担当・カルテ帰属を各行で保持する。バッチの部分成功をこの仕様から導かない。接種済み実績と将来の次回予定は別で、予定を登録して実施済みにしない。担当医属性と実編集actor、認められた医師の確認を分離する。

<a id="fr-vaccinations-schedule"></a>
## FR-vaccinations-schedule：次回予定を種類別設定または手入力へ統一する
2026-10-15の6点確認（Sentinel_4230d91e7dd88191b67f30714ed073ba）に対するユーザー「ok」（Sentinel_ae272463dc248191b51fbef540e04109）の第2項により、独立フォームとカルテ内フォームの次回日は「ワクチン種類ごとの設定または手入力」に統一する。入口だけで異なる固定既定値を適用しない。設定に基づく候補と入力した日付を識別し、手入力値を黙って上書きしない。2026-10-20の本人回答（[EMR-430](https://app.plane.so/baritechllc/browse/EMR-430/)）により、次回予定日の初期値はワクチン種類ごとの設定を使い、設定がなければ空欄とする。一律1年後では補完しない。既存の明示手入力・過去接種の保存済み次回日は自動上書きしない。具体的な間隔数値の臨床承認や、その他の新たな優先順位は追加確定しない。

接種日は必須、未来日は不可。有効なワクチンマスタを選ぶ。次回予定を指定する場合は実接種日より後とする。通常の独立新規フォームでは既存の本日以降条件を維持し、下記の過去接種後日入力だけを区別する。次回日の新規必須化や通常入力への日付制約の全面解除は追加しない。

<a id="vaccination-retrospective-next-date"></a>
### 過去接種を後日記録する場合の次回日
2026-10-15の6点確認（Sentinel_8fcd9be0b3d081918f0e47e2a6f06025）に対するユーザー回答（Sentinel_0ebd3189f3408191ae0f69b158fcd353）の「4 ok」により、過去の接種を後日記録するときは、当時の次回予定日が入力時点で既に過ぎていても履歴として残せる。実接種日・当時の次回予定日と現在の入力時刻を分け、期限経過だけを理由に保存拒否・今日以降への置換・現在設定での再計算をしない。実接種日より後という整合条件は保持する。

これはD03の過去専用入力、および承認済みの死亡後生前分記録に接続する限定した後日入力である。通常新規入力の本日以降条件、未来接種日の拒否、患者／医院・権限・原記録／理由／履歴の保護を全面解除しない。親が診療終了済み又は旧finalizedであることだけで通常入力／編集を拒否せず、過去専用入力・死亡後生前分記録に必要な確認と履歴は維持する。専用経路の未実装を通常CRUDでの制約解除で代用しない。

現行の標準候補3weeks／4weeks／1year／other、独立既定1year／カルテ内既定4weeksは旧UI実装の観察であり、今回選定した統一目標や医学的推奨値ではない。両入口への適合は未確認。選択マスタ／候補／手動値が患者に適切かは医師が確認する。種による候補絞込み・種不一致拒否が現行未実装であることも、異種の接種が安全／承認済みという意味ではない。

<a id="fr-vaccinations-correction"></a>
## FR-vaccinations-correction：訂正・削除・同時操作で別の接種を変えない
編集／削除は対象接種IDと現在の医院・患者・カルテ帰属・grantを確認する。現行の死亡ペット編集／削除拒否は通常画面の観察である。2026-10-15の死亡後取扱い確認（Sentinel_2b63d8f5aad88191aa2b4dff79fb5ac2）に対するユーザー「ok」（Sentinel_45be2cab0fe4819188c7c0f9a211358c）により、生前に行った接種の後日入力・誤記訂正は死亡状態を戻さず理由・履歴付き専用経路で可能にする。元記録・実接種日と現在の入力時刻・actorを分け、実施時点不明なら確認する。死亡後の新たな接種や未来の予約／実施は許可せず、死亡状態取消・通常CRUDで代用しない。未保存入力を保護し、保存失敗では入力を保持する。保存成功後だけフォームを初期化し、再取得で同日の複数行を独立表示する。単一行削除で同日の他の記録を消さない。

紐付くカルテが診療終了済み又は旧finalizedであることだけを理由に、認可された通常入力／編集を一律拒否しない。[最新のD03接続](#vaccination-normal-edit-autosave)へ従い、変更前後・actor／時刻等の履歴を保持する。患者取り違え、死亡後の生前分後日入力、過去専用入力、復元は各専用経路と既決の理由／履歴保護を維持する。記録自体の削除権限や条件を通常編集の回答から緩和しない。通常patient FK PATCHで付け替えない。専用経路未実装を通常APIで代用しない。競合時は古い値で上書きせず再取得する。送信結果不明は照会し、同日複数許可を無制限の再送重複許可にしない。

<a id="fr-vaccinations-history"></a>
## FR-vaccinations-history：履歴の範囲と公開先を明確にする
一覧は実施日・全文をAPIへ送り、担当医絞込みは取得済み最大100件内。終了日省略はJST当日。既定は次回日昇順、未設定末尾、ユーザー列ソートを優先。編集リンクはカルテ紐付きなら該当タブ／接種ID、未紐付きなら独立詳細。viewとedit/deleteを分け、閲覧リンクだけで編集権限を与えない。

同じ保存済み接種・次回予定をカルテ履歴、健康表示、レポートの認可済みprojectionへ渡す。後日入力で保持した当時の次回日も保存事実として表示し、期限経過を理由に現在の推奨日へ書き換えない。取得不能・非開示・未設定を区別し、全件取得していないのに全履歴と断定しない。表示成功は飼主への公開／送信成功ではない。D20の2026-10-15承認（Sentinel_7a67fd30e47c819192cd36d416f0a2bf）は本人に紐付く生存ペットの保存済み接種実績を対象とし、親カルテfinalizedや新しい接種承認操作を要求しない。未保存・取消／削除は非公開、訂正保存後は更新する。検査・健診結果へ公開範囲を拡張しない。

<a id="fr-vaccinations-master-delivery"></a>
## FR-vaccinations-master-delivery：マスタ・期限通知・課金を別の責務へ接続する
名称・有効状態・間隔・価格等のワクチン項目管理は既存診療マスタに接続し、接種編集権限でマスタ全開放しない。過去の保存事実を現在マスタで推測置換しない。当時名称／間隔／価格のsnapshotがない旧値は未確認とし、D03／D10の保存時参照境界で扱う。

期限接近通知はD15のvaccine_deadline_60d／30d等の設定・配信判断が所有する。受付の自動アラートがあるとは記載しない。接種保存とタグ同期・配信成功を別に報告し、失敗した配信を直すために接種を再作成しない。死亡・退会／公開認可・現owner／pet scopeはD04/D15/D20側で再照合する。接種保存だけで課金済み／在庫減算済みとしない。

## 引継ぎ・完成条件
業務の保存単位、独立／カルテ入口、同日複数、次回日、訂正保護、履歴範囲と受け手を整理済みと判定する範囲。次回日の種類別設定または手入力への統一は最新承認を反映した目標で、実装適合は別に確認する。設定なしの初期値は2026-10-20の本人回答により空欄と確定。具体間隔の臨床承認・その他の新たな優先順位は追加確定しない。種フィルタ追加・全履歴検索の改善は未承認の追加機能として今回の必須項目にしない。医師による製品／対象種／具体的接種間隔の確認、現権限・旧snapshot、全writer／版／監査／receipt適合、実機受入・通知運用は完了外。D03の完了済み保存§2と確定／訂正境界を変更しない。


D21 Owner Reportの接種履歴sectionはスタッフ閲覧専用で、接種情報の印刷・共有を同画面から追加しない。最新採用の[予防薬専用処方箋・年間投薬表](../../screens/39-owner-report.md#owner-report-preventive-output)だけがD21の限定印刷例外であり、D03の予防薬管理とD08の接種実績／証明書を区別する。D21一般レポート全体や本sectionへの出力許可に拡張しない。
