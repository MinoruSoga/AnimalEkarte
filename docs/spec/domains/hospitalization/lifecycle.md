## 目的・対象範囲

臨床入院とホテル宿泊を別業務として、予定から実際の受入開始、専用記録、ケージ・世話、退院／退室まで追跡する。入院3画面＋ペット選択＋ケージ／プランマスタの7製品ルートを対象とする。

詳細画面の正本は[一覧](../../screens/07-hospitalization-list.md)・[詳細／デイリーカルテ](../../screens/08-hospitalization-detail.md)・[登録／編集](../../screens/09-hospitalization-form.md)、マスタは[ケージ](../../screens/settings/master-cage.md)・[入院プラン](../../screens/settings/master-hospitalization-plan.md)。語彙は[オントロジー](../../ontology/hospitalization.md)、保存／競合／現行差分は[技術契約](../../../design/domains/hospitalization/technical-spec.md)。

## 担当者・権限・前提

hospitalization:viewで一覧／詳細、createで新規と日次追加・ケア追加、editで変更・チェックイン・退院、deleteで削除。退院は状態遷移であってdeleteを要求しない。ケージ連結はmaster-hospitalization:editであり、患者移動のeditとは別。

現行ボードは在室・非死亡・canEditのときだけカードから開ける。viewのみの利用者はリスト入院Noから詳細参照（死亡時リンクなし）。このUI差を「全閲覧禁止」「全カードから閲覧可」に変更しない。医院／患者／飼主・死亡状態・現在権限は保存時に再確認する。現行の死亡時詳細リンク抑止は、下記の承認済み生前分後日入力／訂正・退院／精算への専用導線とは分けて適合確認する。

## 契機・入口・出口

臨床入院は「予定入院予約」と「診察後の入院決定」の両入口。同じ入院に合流させる。ホテルは予約受入と実滞在が別で、予約の成立だけで実際の入室／退室を確定しない。退院／退室と会計作成・会計確定・入金も別結果である。

## 状態遷移・引継ぎデータ

<a id="requirement-fr-hospitalization-entry-and-start"></a>
### FR-hospitalization-entry-and-start

[入院開始の合意正本](../../screens/settings/master-reservation-type.md#requirement-fr-reservation-types-inpatient-start-confirm)を継承する。予定入院は指名医師未定可。来院後、入院担当医決定済みの状態でスタッフが入院開始を明示確定し、その時点で入院記録を作る。診察した医師／予約指名医師から自動確定しない。記録作成失敗なら開始未確定・理由表示・同じ対象で再試行する。

ここでは既存FRを再承認／再採番しない。本節のIDはD05の受け手として継承境界を束ねる識別子。予約だけで開始・予定日の到来だけで開始・通常カルテを入院記録へ無断変換は不可。同じ入院の二重登録防止はペットと日付の近似だけで別滞在を同一視することではない。

<a id="requirement-fr-hospitalization-hotel-stay-capacity"></a>
### FR-hospitalization-hotel-stay-capacity

ホテルの医院別同時宿泊頭数・期間全体の判定、状態別計数と同一宿泊の二重計上防止は[計数正本](../../line/reservation-spec.md#hotel-counting-boundaries-1826)へ、延泊超過は[正本](../../line/reservation-spec.md#hotel-extension-over-capacity)へ従う。

予約済み／滞在中を同一宿泊単位で数え、取消・未来院・退室済みは除外。同時刻の退室と入室の予定接触だけでは重複にしない。実未退室は予定超過後も滞在中として数える。延泊は変更期間全体を再判定する。超過時は実滞在を保持し責任者の調整まで延泊確定を保留、例外承認で超過確定しない。予定終了による自動退室・他予約の自動取消をしない。

ホテルに医師指名／医師シフト／通常予約の同日制約を適用しない。ケージ空きと頭数上限は別概念。上限未設定・超過時はLINE確定不可・医院相談。入退室日時の休診日／時間外制限は[日時正本](../../line/reservation-spec.md#hotel-entry-exit-hours-1826)へ。滞在途中の休診日だけでは拒否しない。

### 担当の最新訂正（2026-10-15）

根拠: ユーザー Sentinel_5b14560fa7308191a92a2882c517a23d「1 指名は必須ではない　担当って担当医師のことですよ」。責任担当1名必須・医師以外スタッフ可という先の提案は不採用。ここでいう担当は担当医師で、指名は必須ではない。実際にケアを記録するactorとは別概念。旧予約正本のホテル「予約で指名医師を選ばない」という入口条件を、今回の回答だけで新たな指名機能追加へ変更しない。指名の任意性を、入院開始時の担当医決定という既存の臨床入院条件の撤回にも広げない。宿泊側の担当医師の保存方式・交代の履歴は設計として分け、人数や必須条件をこの回答から追加推定しない。

<a id="requirement-fr-hospitalization-distinct-plans-and-records"></a>
### FR-hospitalization-distinct-plans-and-records

2026-10-15の6点確認（Sentinel_4230d91e7dd88191b67f30714ed073ba）に対するユーザー「ok」（Sentinel_ae272463dc248191b51fbef540e04109）の第1項により、入院中の治療プランは元の診療内容・金額明細を履歴に残し、追加・変更・中止できる。現在の内容と元の内容、変更の経過を識別し、中止を履歴の削除に置き換えない。ケアプランは継続ケアの項目で、日次記録（バイタル・ケアログ・スタッフメモ）とも別である。完了後は既存の理由付き専用訂正へ従い、本合意で通常更新へ開放しない。

- 現行は新規登録時の空でない治療プラン行だけ親POSTに同梱し、編集は読取専用／PATCH・DELETE拒否。これは履歴付き追加・変更・中止の目標と異なる現行実装であり、対応済みではない。
- 追加・変更・中止は対象の入院／プラン・元履歴との関係、変更内容、入力者、記録時刻を保持する。プラン保存や中止を実施記録・会計確定・入出金・在庫の使用／戻しに置き換えない。金銭・在庫の実処理は各所有領域へ従う。
- ケアの投薬／処置はマスタ参照必須。持ち物itemだけ手入力「その他」を選べ、名称・単価・trim後1〜500文字の理由を要する。手入力⇔マスタの変更は不要となる参照／理由を消し、混在させない。
- 現行のデイリーログは時刻・値／内容・メモの独立入力で、ケアプランとの自動対応・実施者欄はない。担当スタッフや入力者を実施者として推定しない。
- 入院フォームの概算と会計請求は別。入院側の一括割引欄を新設せず、D10の請求計算を流用したように表示しない。
- 同じ患者の通常診療記録は独立して保持する。入院デイリーログの保存を通常カルテ確定としない。

<a id="requirement-fr-hospitalization-cage-allocation"></a>
### FR-hospitalization-cage-allocation

ケージは任意で、未割当患者はボード末尾の専用欄へ表示。未割当を空きケージ数へ加算しない。未変更は保持、明示解除はclear、選択変更は新IDという送信の違いを維持する。

空きへの移動も使用中同士の交換も表示時割当を照合する。競合したら一方だけ動かさず、最新ボードを確認して再操作。連結代表／構成員を含むスワップは現行不可。構成ケージへの新規割当は拒否、連結グループ占有なら代表への重複割当も拒否する。

ケージ連結は同医院・有効・未連結・非占有で一階層。占有確認は表示filterから独立したadmitted/reserved全件。未取得／取得失敗を空きとみなさない。連結代表の単価表示・利用についてはケージ正本を維持するが、現行退院会計が日数・ケージ単価から自動積算するという意味ではない。

<a id="requirement-fr-hospitalization-discharge-and-billing"></a>
### FR-hospitalization-discharge-and-billing

退院は入院中から明示的に行い、再チェックインの通常操作は設けない。予約中からの退院は画面上非表示。退院済み記録の閲覧・保持と、再入院の新たな業務は別である。

会計へ進む選択ありでは退院と会計／請求明細作成を整合させ、成功時は結果の会計IDへ進む。選択なしでは退院状態のみ更新して一覧へ戻る。会計作成は精算／支払確定を意味しない。ケア明細はsource=hospitalizationとして会計へ渡し、手入力ケア理由は請求側の「会計手入力理由」へ転記しない。

現行はCarePlanItem一件の単価・数量1を渡し、入院プランmasterのper_day/per_night・体格・日数による料金自動積算は行わない。治療プラン概算やケージ単価を追加で二重請求しない。D10の最新税・割引・保険・確定／取消／再請求の正本を優先し、現行の固定税率変換・取消会計soft-deleteを目標ルールへ昇格しない。

<a id="requirement-fr-hospitalization-delete-and-preserve"></a>
### FR-hospitalization-delete-and-preserve

親の治療プラン・日次記録・ケアプラン参照がある削除は既存ガードで拒否する。治療プランありはUIでも削除ボタンを抑止。参照を取り除く目的で記録を破壊しない。現行の死亡患者登録・更新・チェックイン拒否は通常操作の観察である。2026-10-15の死亡後取扱い確認（Sentinel_2b63d8f5aad88191aa2b4dff79fb5ac2）に対するユーザー「ok」（Sentinel_45be2cab0fe4819188c7c0f9a211358c）により、死亡登録を取り消さず、生前に実際に行われた診療の後日入力・誤記訂正、既存滞在の退院処理・生前分の精算を、理由と履歴を残す専用経路で行える目標とする。対象・実施時点・元記録・理由・入力者／確認者・入力時刻を照合し、実施時点が不明なら生前の実施を推測せず確認を要する。死亡後の新たな医療行為、未来の予約／実施は許可しない。原記録・確定履歴を保持し、自動返金・在庫巻戻しを行わない。 通常チェックイン・新たな入院実施は拒否し、生前分の後日記録と退院／精算を区別する。精算の実処理はD10へ。専用経路の実装適合は未確認で、汎用PATCHや削除で代替しない。

## 追加合意: 訂正・ホテル料金

2026-10-15追加合意: 提示文「完了後の誤りは原記録を残して理由付き訂正とし、返金や在庫を自動で戻しません。宿泊料金・必要前金・取消料はスタッフが個別確認して入力し、日数による自動課金や取消時の自動請求・返金は設けません。」を残り方針として再確認し、ユーザーが「ok」と回答（Sentinel_7a67fd30e47c819192cd36d416f0a2bf、確認文 Sentinel_8d0032ca45b881919b3d2ceb5339f792）。業務方針の承認であり、実装・実機PASSではない。

責任担当1名必須・非医師可の旧案は撤回済み。担当医師／指名非必須の修正を維持する。

<a id="requirement-fr-hospitalization-special-correction"></a>
### FR-hospitalization-special-correction

完了後の記録・退院誤りは原記録を保持し、理由付きの専用訂正として扱う。通常の削除・巻戻しで原記録を失わせない。訂正対象と原記録への関連、変更内容、理由、操作者、時刻を識別できる履歴を保持する。実滞在に影響する訂正はD01の頭数計数と再照合する。会計の訂正・返金はD10、在庫は所有領域へ引き継ぎ、訂正だけでは自動返金・在庫巻戻しを行わない。具体API・権限・版制御の適合は技術差分として検証する。

<a id="requirement-fr-hospitalization-hotel-manual-pricing"></a>
### FR-hospitalization-hotel-manual-pricing

宿泊料金・必要前金・取消料はスタッフが個別確認して入力する。日数による自動課金や取消時の自動請求・返金は設けない。入力した必要前金は受領済み残高を意味せず、実際の入出金と残高はD10が所有する。預り金の同医院・元飼主単位、予約参照任意の境界を維持する。全予約一律前金必須、固定額・受領期限、新たな自動徴収条件は本合意から推定しない。

## 異常系・保存・取消

| 状況 | 期待する扱い | 禁止する誤認 |
|:---|:---|:---|
| 入院開始記録の失敗 | 開始未確定、入力と同じ入院IDを保持、理由を出して再試行 | 予約成功だけで入院開始済み |
| 結果不明／遅延成功 | 状態・記録・会計IDの結果照合まで再作成停止 | timeout後に別IDで作成 |
| ケージ競合 | 409で原子的拒否、再取得 | 古いボードを正として強制上書き |
| 占有取得失敗 | 連結・空き確定表示を止める | 0件／空きとして扱う |
| 退院会計の失敗 | 同一txの状態・会計・明細はrollback。結果不明は別 | 会計失敗を隠して退院成功表示 |
| 退院済みへの再操作 | 元結果と既存会計を照合、通常再チェックインをしない | 二回目失敗を根拠に初回を失敗扱い |
| 延泊定員超過 | 実滞在保持、調整待ち、全期間再判定 | 実績消去・自動退室・他予約取消 |
| 親削除拒否 | 依存を表示／確認して操作中止 | 治療プランの原記録・変更履歴を消して親削除 |

## 未決事項・関連仕様・根拠

D01は予約受付・頭数、D02は分類表示と専用遷移、D03は通常記録、D10は請求・入出金・確定履歴、D14はスタッフ所属／有効性、C04は認可、C05は保存・監査。ホテルの担当をD14の医師シフトへ付替えない。

実装差は技術契約へ列挙した。画面に書かれた従来チェックインPATCH／日付編集未送信と、合意した開始時記録・延泊の契約を区別する。全writer／旧値適合・本番利用・実機性能は未確認。PR670 / 41fcf3eb0a8befb7c0b5f613d1df749a60e30be8を静的参照した。
