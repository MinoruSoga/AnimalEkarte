## 担当者・権限・前提

請求訂正・取消・返金は権限のあるスタッフが理由付きで行う。実際の職種／権限識別子のmapping、訂正・取消の確認段階等は未確認。返金は第三群で金額による追加承認なしを合意済みで、総額上限・理由・方法と返金権限の検査は維持する。現在のgrantを新しい全操作の認可へ無条件転用しない。医院・飼主・ペットの分離と原記録保護を維持する。価格・割引・保険・支払方法のマスタ変更は[第六群の権限契約](#requirement-fr-accounting-master-authorized-maintenance)に従い、会計を操作できることだけでマスタ変更を許可しない。

### FR-accounting-owner-selected-charges：飼主単位の選択と元請求への回収

同じ飼主の複数ペットをまとめて会計でき、当日分と過去の未請求分を選択して合算できる。元のペット・診療等の明細情報を保持し、まとめるために一つのペット／カルテへ付け替えない。

<a id="accounting-posthumous-settlement"></a>
死亡登録後でも、生前の診療に係る未請求分の精算・既存請求の回収・誤記訂正・退院精算を、死亡状態を取り消さず理由と履歴付きで行える。質問 Sentinel_2b63d8f5aad88191aa2b4dff79fb5ac2／回答 Sentinel_45be2cab0fe4819188c7c0f9a211358c が根拠。元患者・実施した診療／滞在・元明細・請求と飼主帰属を確認し、生前実施か不明な新しい臨床事実を会計で補わない。死亡登録だけで請求取消・返金・在庫返却・予約再開を起こさず、既存の認可・金額上限・原子保存・再送条件に従う。主飼主変更後も過去請求・預り金は元飼主に残し、この精算経路で資金移管しない。通常の死亡個体の新規予約／実施ゲートとは区別する。

2026-10-22の[限定参加契約§4.1](../../../work/emr/emr-540-308-462-506-selected-handoff-20261022.md#posthumous-selected-participation)で、結果照会は認証医院・同一actor・保存済み元対象anchorから解決した対象への現在`accounting:view`とし、失権/元対象解決失敗時は非開示と選定した。mutationは既存金融write grantを維持する。一般506 wire等の未選定・製品実装/受入未完は同追補で区別し、この参照で実装済みとはしない。

受領・配賦と方法/日時誤記訂正の[506技術候補一覧](../../../work/emr/emr-506-fund-wire-design-candidates-20261022.md)は未採択で、既決業務を変更しない。候補route/金額・ID wire/tokenの検討とAPI/実装・受入完了を区別する。

過去の確定済み未納は未請求候補とは別。払う額は自由に決められるが、元の確定済み請求を作り直さず、入金を元請求へ紐づけて残額を管理する。新しい請求と過去分回収を一度に扱う場合も、それぞれの請求帰属を保持する。第二群で[古い請求からの充当・スタッフ変更と釣銭](#requirement-fr-accounting-oldest-payment-allocation)、[予約への前金](#requirement-fr-accounting-reservation-advance)を合意した。自由な支払額の合意を全額回収の強制へ戻さない。第三群で飼主単位の預り金と予約紐づけ任意、同じ飼主の別予約・別ペット会計への確認付き利用を合意。超過入金を預り金へ無断で自動繰越しない。

<a id="requirement-fr-accounting-receivable-partial-zero"></a>
### FR-accounting-receivable-partial-zero：請求確定と入金状態を分ける

全額未納・一部入金でも請求を確定でき、残額は後日回収できる。請求額・入金履歴・残額を管理する。複数の支払方法を併用する決済と、後日回収を伴う部分入金は別の概念。請求確定を全額入金済みと表示しない。

0円会計は実際の明細と無料・割引等の理由／根拠を残し、架空の入金を作らない。明細のない請求は確定不可。明細0件と明細あり0円を区別し、詳細は[第十群](#accounting-empty-rounding-master)へ。根拠入力の具体形式は技術設計とする。通常の入金だけの例では10,000円請求に3,000円入金なら残額7,000円、後日2,000円入金なら残額5,000円で、請求を再作成しない。

<a id="requirement-fr-accounting-reasoned-financial-correction"></a>
### FR-accounting-reasoned-financial-correction：訂正・取消・返金を区別する

権限のあるスタッフが理由付きで請求訂正・取消・返金を行い、元記録と履歴を残す。返金額は入金済み額から返金済み額を差し引いた範囲内。返金方法を指定する。実際に返金していない操作を返金済みとしない。

請求取消だけで返金や在庫返却を自動処理しない。第二群で請求減額と実際の返金を別操作とした。支払方法の誤記訂正は金額を動かさず履歴を残す。第三群で元がカードでも現金等の別方法返金を認め、金額による追加承認は設けず、返金権限のあるスタッフが理由付きで行う。総額上限・方法指定・原記録と履歴の保持は維持する。決済サービスへの自動返金連携や規約適合は今回の承認／保証に含めない。取消後の再請求は[第八群](#accounting-rebill-and-collection)の元明細選択・確認、新請求番号と元取消請求への関連付けに従う。返金の上限を請求総額だけから算定して未入金分まで返金可能としない。

<a id="accounting-cash-method-correction-unknown-pair-20261023"></a>
2026-10-23追加承認：カード等から現金へ支払方法の誤記を訂正する際、実受領額は既知だが当時の預かり額・釣銭額が不明なら、両方を不明（null）のまま理由付きで訂正してよい。理由は必須、実受領額と実授受日時を変更せず、原記録と訂正履歴を保持する。不明額を0へ自動補完せず、新しい受領・返金等の金銭移動を作らない。方法訂正だけで日時を変更しない既決条件を維持する。これは過去取引の方法誤記訂正に限る許可で、新受領の現金入力要件を緩和しない。本人回答 Sentinel_25ecf76d14a481918e055ba259c80988「はい」が根拠。詳細wire/reader/CAS/adapterの採択・実装/受入完了を意味しない。

訂正後の料金に対して未払額と返金必要額を表示し、実際に返金したときに方法と金額を記録する。通常請求への入金だけの例：10,000円全額入金後に9,000円へ減額すると、未払0円・返金必要1,000円。減額だけでは返金済みにならず、1,000円を実返金して初めて返金済みとなる。10,000円請求に3,000円入金後、9,000円へ減額なら未払6,000円で返金不要。料金訂正・返金必要・未実行返金・返金済みを区別する。入金・実返金・前金充当の帰属は別記録として保持し、未充当前金を請求の入金済み額へ混ぜない。

<a id="requirement-fr-accounting-post-close-separate-movement"></a>
### FR-accounting-post-close-separate-movement：締め後差分と金銭移動

締め後も元の締め記録を保存して訂正差分を追加する。金額訂正と実際の入金・返金を別々に記録し、金額だけの訂正を現金の移動にしない。[締め内部](../../cash-register.md)はD12の責務。元の請求日を変えず、今日の実際の入金・返金は今日の入出金として扱う。前金の実受領日／実返金日も保持し、後日の充当日を再受領日としない。期間・区分・差額照合の内部詳細を本書で決めず、元締めの取消／再開という新経路も追加しない。

<a id="requirement-fr-accounting-calculation-snapshot"></a>
### FR-accounting-calculation-snapshot：会計時点の根拠と手修正・併用

会計時点の価格・割引・保険等の計算根拠を保存し、マスタ変更だけで過去会計が変化しない。単価の手修正と複数割引の併用を認める。旧マスタ値／現在値／手修正値の区別を保持する。

第二群で割合割引→金額割引の順を合意。税・保険をまだ適用しない割引段階だけの例：10,000円に10%と500円を適用すると10,000→9,000→8,500円。保険の対象項目・割合・上限はスタッフが確認・修正でき、会計時点の確認／修正値を保持する。第七群で資格・残限度の外部画面等によるスタッフ確認と、結果・保険負担額をAnimalEkarteに記録する窓口会計運用へ範囲を明確化した。

第三群で複数割合は合算し、その後に金額割引を適用、割引後の保険対象金額を基準に保険を適用する。割引段階だけの例：10,000円に10%＋20%と500円なら30%引きで7,000円、その後500円引きで6,500円。全額が保険対象で上限がかからない50%保険の単純例では、その6,500円が保険算定の対象となる。この例は割引後の対象額を示し、会社／商品別の自動給付算式を確定しない。今回の保険負担額は[第七群のスタッフ確認・記録](#accounting-insurance-window-scope)に従い、独自の自動算定を要件にしない。税と値引き端数は第五群の契約へ従う。

第四群で明細ごとと会計全体の両方の割引を使えると合意。合算率100%超・商品金額超の値引きは入力エラーではなく警告にする。超過を承認して進められ、その場合の請求額はマイナスにせず0円を下限とする。超過条件だけで保存・確定を拒否せず、実際の割引値と0円となった根拠を保持する。

<a id="accounting-calculation-order"></a>
#### 第五群：明細値引き・全体配賦・税の計算契約

1. 税抜入力の価格と値引きは以下の税抜基準で計算し、飼主向け料金は税込で表示する。税込入力は[入力額維持の追加契約](#accounting-input-gross-preservation)を優先し、単純な税抜換算・丸め・再加算で元の税込額を減らさない。税区分・適用税率は明細に対応するマスタ由来の会計時点の値を保持する。全診療・物販を一律の税率と決めつけず、非課税等の区分も課税行と混同しない。
2. 値引率は明細行ごとの割合であり、同じ会計に異なる率が共存する。画面見出しの率を全行へ無条件に一律適用しない。明細単位の割引を先に適用し、その結果を会計全体割引の基準額にする。複数割合の合算は同じscope内だけで行う。各明細scopeと会計全体scopeの率は混ぜず、各scopeで「割合の合算→割合値引き額の1円単位四捨五入→定額値引き」の順を用いる。四捨五入するのは割合値引き額であり、割引後残額や各割合を個別に丸めて合計しない。
3. 会計全体の値引き額を、明細割引後の対象税抜額に比例して各明細へ配賦する。各配賦額を1円未満切捨てし、残りの円は小数部分が大きい明細から1円ずつ配る。配賦合計は実際に適用する会計全体値引き額に一致させる。同率端数の順序を固定して再計算可能にする技術案は[技術仕様](../../../design/domains/accounting/technical-spec.md#accounting-fifth-design)へ。配賦後も元行の税区分・保険対象区分を保持する。
4. 合算率100%超または対象額超の値引きは警告し、承認して続行できる。入力した割引条件を消さず、実適用額は当該scopeの対象額までに制限し、超過分を他明細へ回さない。明細割引後の額と会計全体割引後の額は0円を下限とし、負額請求を作らない。会計全体の対象額が0円なら実値引き・配賦とも0円とし、0除算しない。配賦端数の1円調整は超過値引きの転用と区別する。
5. 値引き・配賦後の税抜額を請求書単位・税率ごとに合計し、その合計に対する消費税額の1円未満を一度だけ切り捨てる。明細ごとに税を丸めて合計しない。飼主向け税込料金表示と、確定した請求書の税率別税額を区別し、表示用の明細税込額から請求書税額を逆算しない。
6. 保険は既決どおり値引き後の保険対象金額を基準とし、対象外行を混ぜない。今回の保険負担額は第七群のスタッフ確認・記録による。会社／商品別の税抜／税込基準・上限・端数等を扱う自動給付算定は今回の対象外で、将来の自動化時に確認する。今回の税計算契約から、保険給付が課税標準を減額する等の新ルールを推定しない。

税抜入力の値引き前税抜明細額は第十群に従い、単価×数量の積の1円未満を行ごとに四捨五入して確定する。割合値引き額・配賦・税率別税の丸めとは別段階。全体割引除外の初期値／設定欠落時の意味と会計追加後のmaster変更は[第十群](#accounting-empty-rounding-master)へ。全体割引除外から明細値引きの禁止を推定しない。

<a id="accounting-insurance-and-exclusion"></a>
#### 第六群：複数保険会社と品目マスタの全体割引除外

窓口精算は複数の保険会社を扱う。アニコムはユーザーが挙げた例であり、一社限定でも採用会社・商品一覧の確定でもない。今回の資格・残限度と保険負担額は[第七群のスタッフ確認・記録](#accounting-insurance-window-scope)による。会社／商品別の自動給付算式は将来の対象で、今回の窓口会計の完了条件にしない。既決の割引後保険・スタッフによる確認修正と計算根拠保存を維持し、会社名だけから同じ算式を全商品へ適用しない。オンライン請求の着手や自動連携も追加しない。

会計全体の割引から除外する品目を品目マスタで指定できる。会計時点の指定を根拠として保持し、除外行は全体割引の対象額合計と配賦先の双方から外す。除外行の全体割引配賦額は0円、行の明細割引後金額を全体割引で減らさない。全行が除外なら対象額0円として実全体値引き・配賦とも0円とし、請求には除外行の金額と適用税を保持する。これは全請求0円の意味ではない。品目マスタの全体割引除外と保険対象外・税区分は別設定で、明細値引きを一律禁止する合意にも広げない。

例：明細割引後の税抜A1,000円・B2,000円でBを全体割引から除外し、全体100円引きならAへ100円、Bへ0円を配賦し、残額は900円・2,000円。Bの税区分・保険対象根拠は保持する。マスタ変更だけで保存済みの除外指定・配賦・帳票を変更しない。第十群で除外初期値／設定欠落時は対象外にしない、追加済み明細へのmaster変更は自動反映せずスタッフの明示的再適用と合意。物理schema・移行手順は後続実装で、既存明示設定や保存済み金額を初期値で上書きしない。

- 新請求の確定には実際の対象明細が必要。0件なら確定しない。無料・全額割引等の0円会計でも明細と理由／計算根拠を残し、架空入金を作らない。入力途中の空状態とは別。過去未納だけの回収や預り金受領に空の新請求・架空0円明細を要求せず、既決の元請求への入金／独立した預り金受領を維持する。
- 税抜入力の値引き前税抜明細額は会計単価×数量の積を各行で1円四捨五入する。非負額の0.5円は切上げ。単価や数量を先に整数化せず、複数行を合算してから丸めない。その整数円額へ第五群の明細値引き→全体値引き／配賦→税率別集約を適用する。割合値引き額の四捨五入と税額切捨ては各段階で維持し、臨床数量・投薬量を変更しない。
- 例：101円×0.5＝50.5円→51円。明細10%引きは5.1円→5円、残46円。全体割引なし・税10%の単独行なら税4円、税込50円。1円×0.5の2行は各1円、計2円。積合計1円を丸める方式で代用しない。1円×0.49は0円になるが行と元値・積・丸め根拠を残す。請求全体0円の理由を無料等へ偽って置き換えない。
- 元単価／数量・丸め前の積・丸め規則・明細額をsnapshotへ対応させる。再請求は選択した元snapshotと確認条件に既決計算を適用し、元取引／過去帳票を新しい丸めで上書きしない。料金訂正は既決の理由・履歴・金銭操作分離に従う。
- 全体割引除外の初期値は対象外にしない。既存データに設定がない場合も同じ意味。明示的に対象外と設定済みの値をfalseへ初期化せず、保険対象外・税区分・明細割引と分ける。設定欠落の補完だけで確定済み会計の料金／配賦／帳票を再計算しない。
- 会計追加済み明細は、その後masterの価格・税・割引／除外等が変わっても自動変更しない。編集中でも追加時点の値を保持し、最新masterへ追従するならスタッフが対象を明示して再適用する。前後値・計算結果・元明細／master参照を追跡し、手修正や再請求の元snapshotを無断で上書きしない。会計上の再適用はmaster編集権限や新受領を与えない。
- 確定済み会計／旧帳票は再適用の名目で直接書き換えず、必要な変更は訂正・取消／再請求へ接続する。保存時に医院／飼主・現在認可・対象版／状態を再検査し、別編集／確定後に古い確認で保存しない。再送・結果不明でも重複請求・入金・預り充当を作らない。具体実現は技術仕様へ。

### FR-accounting-master-authorized-maintenance：管理者と許可されたスタッフのマスタ変更

価格・割引・保険・支払方法のマスタ変更は管理者に加え、その対象の変更権限を付与されたスタッフにも許可する。無権限スタッフ、閲覧権限だけのスタッフ、通常の会計操作だけが許可されたスタッフへ一律に変更を認めない。管理者も所属医院の範囲・現在認可・原記録保護を守る。特定の職種名だけで変更可否を決めない。

変更時に対象マスタと操作権限・医院scopeをサーバー側で検査し、対象・変更前後・操作者・時刻を監査へ対応させる。マスタ編集権限と個別会計での手修正、権限グループの付与／変更、削除等の別操作を同一の許可にしない。実際のgrant／職種mappingと失効時の扱いはC04と照合し、現行grantを自動で追加・変更する承認ではない。マスタ変更後も会計時点の価格・割引・保険・支払方法の参照と履歴を保持し、保存済み会計や旧帳票を現値で上書きしない。

### FR-accounting-oldest-payment-allocation：古い請求から充当・変更可能

過去未納への入金は古い請求から自動充当し、スタッフが配分を変更できる。A8,000円がB5,000円より古く今回5,000円を払うなら、初期配分はAへ5,000円（A残3,000円・B残5,000円）。スタッフがA2,000円・B3,000円に変更したらその配分を元請求へ記録する。合計入金額を配分変更だけで増減しない。

現金の通常請求回収で請求残額を超えて受け取った分はお釣りとして返し、請求へ過大充当しない。残額3,000円に5,000円を預かったら入金は3,000円・釣銭2,000円。飼主単位の預り金受領は別操作で、この釣銭規則を預り金除外に使わない。第三群で同日請求は作成順に充当し、保存後の配分変更も理由と履歴付きで可能とした。再配分で入金実額・実受領日を変更せず、元配分と変更後の配分を保持し、請求訂正後の残額と整合する。

現金以外で残額3,000円に実入金5,000円なら、実入金5,000円・請求への充当3,000円・未払0円・返金必要2,000円を区別する。お釣り扱いにせず、方法付きの実返金を別に記録する。未実行の2,000円を返金済みや預り金へ自動転用しない。新規請求と過去未納回収を同じ操作で扱い、請求ごとの支払額を指定できる。新請求と選択した元請求の帰属を保持し、古い請求順／同日作成順の初期配分・スタッフ変更を維持する。詳細は[第八群](#accounting-rebill-and-collection)へ。訂正後の既存配分の再確認UI・実現方式は設計残件。釣銭と後日の返金を混同しない。

<a id="requirement-fr-accounting-reservation-advance"></a>
### FR-accounting-reservation-advance：飼主単位の預り金・前金の受領・充当・返金

第三群で第二群の予約必須条件を更新した。預り金を飼主単位で管理し、予約参照は任意に保持する。ホテルなどの前金は予約も記録できるが、予約がなくても受領でき、同じ飼主の別予約・別ペットの会計にも利用できる。全ホテル予約で前金必須という意味ではない。第八群で自動失効なし・同じ医院／飼主の範囲と確定した。別医院への移行・別飼主への譲渡は今回は対象外。FRの既存識別子は互換参照のため維持し、業務の範囲は本節の最新合意に従う。

医院・飼主、任意の元予約、受領額／方法／実受領日、充当先請求・予約／ペット参照と額／充当日、実返金額／方法／実返金日を追跡する。受領・未充当残・利用可能額・充当・実返金を区別する。未充当残は受領累計−有効充当額−未充当分の実返金累計。有効充当額は充当累計から会計取消または減額で解除・残高復元済みの額を差し引く。充当済み分を請求側で実返金した額を未充当分の実返金へ重ねて控除せず、既実返金分を取消で二重に復元しない。受領した飼主への帰属は、別予約／別ペットへ充当しても付け替えない。会計時に充当先と金額を確認し、未充当残を請求へ無断で自動充当しない。

受領と充当は別。5,000円を預かり、最終会計8,000円へ5,000円充当したら、追加支払前の未払は3,000円、未充当残は0円。充当時に5,000円をもう一度現金入金として二重計上しない。実受領日を充当日に書き換えない。同じ残を別予約・別ペットの会計と返金で重複使用しない。

キャンセルや料金変更で余った分は返金できる。5,000円受領・確認された最終料金3,000円なら3,000円充当・未充当残2,000円を保持し返金できる。料金変更や予約キャンセルだけで実返金済みにしない。権限・理由・方法と実返金記録を保持し、返金済み分を再充当／再返金しない。未実行返金の表示と利用可能額が同じ残を二重に約束しないよう技術側で競合・現在残を検証する。第四群で会計取消時は充当済み預り金を元飼主の残高へ戻し、実返金は別操作と合意。未返金の預り金5,000円から3,000円充当し残2,000円の会計を取消したら、3,000円を戻して残高5,000円、実返金は0円のまま。復元は新受領ではなく元受領・充当・取消・復元の履歴を保持する。繰り返し取消や既に返金／復元済みの額を二重に戻さない。第八群で減額時も解除する充当分を元飼主残高へ戻すことと、自動失効させないことを合意した。併用時の確認・内訳と既実返金の保護は[第八群](#accounting-deposit-reduction)に従う。

ホテル固有の必要額・受領タイミング・キャンセル料はD05。2026-10-15の追加合意では料金・必要前金・取消料をスタッフが個別確認入力し、日数による自動課金や取消時の自動請求／返金を行わない。預り金の受領・充当権限mapping、資金内訳不明時の業務方針は第九群の記録確認・内訳／理由登録まで返金確定不可へ従う。具体的な確認UI・保存形式は設計残件。同じ医院・元飼主の帰属を維持し、ペット／予約の飼主変更や名寄せ等を預り金移管の承認にしない。預り金受領だけで請求確定・予約完了・通常診療終了Undoの停止を発生させない。最終会計確定時は既決の確定歴境界へ従う。

<a id="requirement-fr-accounting-document-and-aged-debt"></a>
### FR-accounting-document-and-aged-debt：請求書・領収書と過去未納

月次未納の4列・実受領のみの当月入金・非入金の調整内訳と追加3ACは[月次帳票正本](pages/unpaid-list.md#unpaid-monthly-source-adoption)へ従う。2026-10-16の承認は既存FRの拡張で、実返金の新規方針や税額変更を含まない。

請求書と実際に受け取った金額の領収書を分ける。再発行は再発行と表示し、訂正前の帳票も履歴に残す。請求10,000円・実入金3,000円の場合、請求と受領した3,000円を区別し、全額受領した領収書を出さない。

未納一覧は今月売上がなくても過去未払いのある飼主を表示する。今月の売上有無を理由に未納を除外しない。検索／期間filter・基準日の詳細は別途設計するが、従来の「期間内売上ありのみ」を目標仕様として残さない。

第三群で預り金／前金受領時は受領証、最終会計には預り金充当額と今回の入金額、返金時には返金額・方法・元取引番号を表示する。各取引を番号で追跡し、再発行でも元番号を維持する。再発行の履歴・版は別に残し、元番号維持を履歴上書きとしない。前金充当を新たな実受領とする帳票は出さない。第六群で帳票は飼主名宛てとし、明細をペット別に区分すると合意した。元明細のペット参照を保持し、同飼主の複数ペットを一つの患者として表示しない。訂正・部分返金の帳票には元の取引と今回の変更額を区別して表示する。請求訂正による増減と実際の返金額・返金必要額も混同しない。例えば10,000円請求を9,000円に訂正した場合は元10,000円・今回減額1,000円を分け、実返金未実行なら返金済みと表示しない。入金10,000円から今回1,000円を実返金する場合は元入金と今回実返金1,000円を別に表示し、元入金を9,000円へ書き換えない。

宛名・元ペット別明細・元取引・今回差分と既決の取引番号／再発行履歴を対応させる。ペットに紐づかない料金は飼主宛て帳票の「共通料金」別枠へ表示し、架空のペットや任意の実在ペットへ付け替えない。元明細・医院／飼主帰属・税区分・割引根拠を保持する。番号の書式・採番方式、具体的な紙面配置・ページ分割、発行操作の権限／保存形式は技術残件。

## 異常系・保存・取消

[会計確定歴による通常Undo停止](../../workflows/reservation-to-record-flow.md#accounting-finalization-undo-boundary)を維持する。未納・部分入金・0円でも会計確定歴があれば通常Undo不可。返金・取消・削除後も確定歴を消さない。未保存入力は会計確定ではない。複数ペットをまとめても、正確な予約／記録との対応を失わない。

[カルテ保存正本§2](../medical-records/lifecycle.md#hybrid-sync)と[最新の通常編集・自動保存／復元](../medical-records/lifecycle.md#medical-record-agreement-autosave-20261015)へ従う。カルテ訂正・過去入力・復元から請求・返金・在庫を自動巻戻ししない。金銭処理の成否は会計側で確認し、カルテ保存成功や画面遷移で代用しない。

再送・競合・結果不明・監査の技術案は[保存契約](../../../design/domains/accounting/technical-spec.md#accounting-operation-contract)を参照。未決の配分・計算条件に依存する操作は推測で実行できる仕様にしない。

## 釣銭の手動修正と実受領・請求充当の整合（Backlog No.30）

釣銭の手動修正は、釣銭だけを書き換えた結果を無条件に保存して会計完了にする操作ではない。預かった現金と実際に返す釣銭から実受領額を確認し、今回の請求への充当・残額と、過受領がある場合の扱いを整合させてから完了する。預かり額の訂正は実際の受領に基づき、数字だけを合わせる架空の訂正にしない。

例として、請求8,000円・預かり10,000円の釣銭を1,500円へ手動修正すると実受領は8,500円になる。請求額との500円の違いを未確認のまま会計完了にせず、預かり額が誤入力だったのか、実際に過受領したのか、その扱いを確認して整合させる。500円を自動で売上増額・値引き・入出金・預り金へ振り替えて帳尻を合わせない。

根拠は[Backlog Phase1 No.30 F31:G31](https://docs.google.com/spreadsheets/d/17jaFBv7NmbPzk88lZx94vFxa_G1shGNX2O_lFGt4QdQ/edit#gid=0&range=F31:G31)の「お釣り金額は自動計算に加えて『手動修正』に切り替えられ、レジ実機の実際のお釣りに合わせて変更できます」と、質問Sentinel_d352d57330288191a78ecc97c5f1f0c4への本人Sentinel_429ebc6aa11481918b5b293d7244527fの2026-10-17 22:22:48 UTC「ok」。同質問は上記8,000円／10,000円／1,500円の例を示し、「単に釣銭だけ書き換えて会計完了にはせず、預かり額の訂正や過受領分の扱いを確認して、金額の整合を取ってから完了する仕様でよいですか？」と確認した。旧回答の実装済みという表記は今回の実機合格の証拠にはしない。

[現金回収・非現金超過・元請求への充当](#requirement-fr-accounting-oldest-payment-allocation)、[飼主単位の預り金](#requirement-fr-accounting-reservation-advance)、[金額訂正と実入出金の分離](#requirement-fr-accounting-post-close-separate-movement)を維持する。通常の現金超過は釣銭として返し請求へ過大充当しない。非現金超過は釣銭扱いにせず、実入金・充当・返金必要額・実返金を区別する。預り金受領／充当／返金は別の既決操作であり、手動釣銭修正から無断で起動しない。既存の古い請求順・同日作成順とスタッフ配分変更、未納・返金・締めの実受領契約も維持する。

<a id="accounting-excess-receipt-resolution-20261017"></a>
### 過受領の訂正・返金・了承付き預り金登録

質問Sentinel_1fea062beadc8191b1df5c012530d995に対する本人Sentinel_6bc33b35ef8c8191aecfc315fafc7e83の2026-10-17 22:29:04 UTC「ok」を根拠に、過受領の整合は次の業務処理で行う。これらの採否をUI／保存設計の未決へ戻さない。

- 入力ミスなら、実際の預かり額・返却額へ訂正する。実際の受領・返却がない訂正を、新しい現金移動として記録しない。
- 実際に多く受け取ったなら返金する。実返金は既存の返金契約で記録し、返金未実行を返金済みとしない。同じ返却を釣銭修正と実返金の両方で重複して控除しない。
- 飼主の了承を得て預かる場合は、同じ医院・飼主に属する既存の預り金として明示的に登録する。差額を自動預り金化せず、了承のない預りや自動売上加算はしない。

各実際の現金受領・返却は1回だけ記録し、同じ資金を預り金へ対応づけるための架空の追加入金を作らない。例えば請求8,000円に対し、釣銭後の実受領が8,500円で飼主了承のもと500円を預かる場合、同じ8,500円の実受領を請求8,000円と預り金500円へ対応づける。別に500円をもう一度現金受領した扱いにせず、締めの実入金は重複して9,000円にならない。預り金の後日の充当も再受領ではない。

500円を実返金する場合は、その実返金を一度だけ扱い、釣銭後の実受領と返金の関係を保持する。実受領を返金後の額へ書き換えたうえで同じ返金を重ねて控除する等の二重計上をしない。金額訂正、実受領・実返金、請求への充当、預り金の残高を区別し、未納・部分入金、現金／非現金超過、実受領日・実返金日、理由／権限／履歴の既決を維持する。

今回確定した業務処理を実現するUI配置・確認導線・了承や元資金への関連の保存形式は設計事項であり、採用の再質問は不要。具体的なDB・会計記録方式を本追記で固定せず、元の実入出金と配分・預り残高が照合できるようにする。売上増額・値引き・架空入出金による帳尻合わせと、未確認のままの完了は引き続き不可。
