## 0. 本書の位置づけ

ノア動物病院では、林先生のCPM戦略「3年で売上倍増」を実現するため、カルテシステム × Lステップ連携を構築します。

本書は、その連携にあたって**カルテシステム側で実装が必要な項目**を整理したものです。すでに実装完了されている集計機能（顧客ごとの年間売上ランキング、来院回数、最終来院日分類）の上に、Lステップへの自動連携機能を追加する形になります。

## 1. 設計の基本方針

### 1-1. 役割分担

```
カルテシステム：判定する場所
  ・顧客状態（CPM、上位20%、休眠予備軍）の判定
  ・健診/予防/専門検診の履歴管理
  ・売上・来院・会計の管理

Lステップ：配信する場所
  ・カルテからのタグを受け取る
  ・タグを使ってセグメント配信
  ・ファネル分析・クロス分析を実行

突き合わせ：効果を見る場所
  ・配信履歴と来院履歴の突き合わせ（四半期実施）
```

**重要：** Lステップで顧客状態を再計算しません。カルテで判定した結果を、Lステップにタグとして渡す設計です。

## 2. カルテ側で必要な集計・判定機能

### 2-1. 既に実装完了している集計（要仕様確認）

以下は曽我様より実装完了のご連絡をいただいた機能です。Lステップ連携にあたり、仕様の詳細を確認させてください。

| 機能 | 仕様確認したい点 |
|------|---------------|
| 顧客ごとの年間売上ランキング | 「年間」の定義（直近12ヶ月／暦年／会計年度）、複数拠点をまたぐ飼い主の合算ロジック、CSV出力可否 |
| 顧客ごとの来院回数 | 集計期間の指定方法（過去365日／四半期／月次）、複数拠点をまたぐ来院の扱い |
| 最終来院日での期間別分類 | 期間の閾値（3ヶ月／6ヶ月／1年）が固定か可変か、120日／180日／220日／240日の閾値設定が可能か |

### 2-2. 追加実装が必要な判定機能

#### A. CPMステージ判定

飼い主単位で5ステージを自動判定し、Lステップにタグとして渡します。

| ステージ | 判定基準（仮） |
|---------|------------|
| CPM1_出会い | 初診から30日以内、来院1回 |
| CPM2_これから | 来院2〜3回／365日、健診履歴0〜1回 |
| CPM3_コア | 来院3〜5回／365日、健診履歴あり |
| CPM4_スポット | 来院1〜2回／365日、最終来院90〜220日 |
| CPM5_ノア | 来院6回以上／365日、または年4回健診達成、または上位20% |

判定頻度：日次または週次

**注：** 判定基準の細部（CPM3／CPM4の境界、CPM5の主従関係等）は林先生確認後に確定します。仮ロジックで実装し、実データを見ながら調整する想定でお願いします。

#### B. 上位20%判定

| 項目 | 仕様 |
|------|------|
| 判定軸 | 過去365日の累計診療費 |
| 判定単位 | 飼い主単位 |
| 判定頻度 | 月次 |
| 連携タグ | `LTV_上位20` |

**確認事項：** 飼い主単位の定義（同一飼い主が複数拠点を利用している場合の合算ルール）

#### C. 休眠予備軍判定

最終来院日からの経過日数で4段階のタグを付与。

| 経過日数 | 連携タグ |
|---------|---------|
| 120日超 | `VISIT_120日超` |
| 180日超 | `VISIT_180日超` |
| 220日超 | `VISIT_220日超` |
| 240日超 | `VISIT_240日超` |

判定頻度：日次

#### D. 健診・予防履歴判定

カルテの診療コードを参照し、以下のタグを自動付与・解除します。

| タグ | 判定基準 |
|------|---------|
| `HLTH_健診あり` | 過去365日に健診コードあり |
| `HLTH_健診未受診` | 過去365日に健診コードなし |
| `HLTH_年4回候補` | 年2回以上来院＋健診履歴あり |
| `PREV_ワクチン期限` | 接種日から期限60日前 |
| `PREV_フィラリア未完了` | 過去365日にフィラリア検査・処方なし（犬のみ） |
| `PREV_ノミダニ対象` | ノミダニ予防履歴なし |

判定頻度：日次〜月次

#### E. 動物種事実タグ

飼い主が登録しているペットの動物種に応じて自動付与。

| タグ | 判定基準 |
|------|---------|
| `PET_犬あり` | 飼い主のペット登録に犬がいる |
| `PET_猫あり` | 飼い主のペット登録に猫がいる |

**注：** 飼い主が犬猫両方を飼育している場合は両方付与（非排他）。Lステップ既存の「犬専用／猫専用／犬猫両方」（飼い主選択タグ）とは別管理。

#### F. その他のタグ

| タグ | 判定基準 |
|------|---------|
| `PET_シニア対象` | 犬猫7歳以上（猫は10歳以上で別扱い検討中） |
| `LTV_フード購入あり` | 過去365日にフード・サプリ購入履歴あり |
| `HLTH_専門検診候補` | 年齢・診療履歴に応じて専門検診（歯科・皮膚耳・眼科・腎臓ドック等）の対象 |
| `EXCL_配信停止` | 死亡・転院・配信停止希望 |
| `EXCL_配信注意` | クレーム対応中・慎重対応 |

```
EXCL_配信停止
EXCL_配信注意

```

合計：23個

### 3-2. タグ命名の意図

接頭辞方式（CPM_、LTV_、VISIT_、PET_、HLTH_、PREV_、EXCL_）を採用しています。

理由：
- Lステッププロプランの**クロス分析機能**でタグを探しやすくする
- 配信時のセグメント条件を整理しやすくする
- 将来タグが増えた時にも管理しやすい構造を維持する

### 3-3. 連携頻度

| データ | 連携頻度 | 理由 |
|------|--------|------|
| `EXCL_配信停止`（死亡・転院） | リアルタイム or 日次 | 誤配信防止 |
| LINE ID紐付け | リアルタイム or 日次 | 配信対象化 |
| `PET_犬あり`／`PET_猫あり` | 日次 | 犬猫別配信に必要 |
| `CPM_*` | 日次または週次 | ステージ別配信に必要 |
| `VISIT_*` | 日次 | 休眠予防配信に必要 |
| 次回来院推奨日 | 日次 | 再診リマインドに必要 |
| `PREV_ワクチン期限` | 日次〜週次 | 期限通知 |
| `HLTH_*` | 週次〜月次 | 一斉配信用 |
| `LTV_上位20` | 月次 | ランキング判定の都合 |
| `HLTH_年4回候補` | 月次 | 戦略配信用 |

### 3-4. 連携方式

LステップAPIを利用したタグの自動付与・解除。

詳細仕様：
- API連携プロプラン（八王子・城東センター両アカウント、月額11,000円×2）
- 連携方向：カルテ → Lステップ（タグ付与・解除）
- 戻し方向：Lステップ → カルテ／集計DB（配信履歴、四半期分析時）

#### API情報の共有スケジュール

| 拠点 | API有効化 | API情報の確認方法 |
|------|---------|-----------|
| 八王子 | 4/30有効化済み | Lステップの「API連携」画面からご確認ください |
| 城東センター | 5/5申込予定 | 5/5以降に有効化、Lステップの「API連携」画面からご確認ください |

**実装着手のお願い：** API情報の共有スケジュールに合わせて、**八王子先行・城東は5/5以降**で実装を進めていただけますと幸いです。

## 4. 配信トリガー（個別自動配信）

カルテのイベントをトリガーに、Lステップで自動配信を発火させます。

### 4-1. トリガー一覧（14種類）

#### 関係構築・診療継続関連（7種類）

| トリガー | 配信名 | 目的 |
|---------|-------|------|
| 初診登録当日 | 初診お礼 | 関係構築の最初の接点 |
| 初診日＋3日 | 初診後体調確認 | 不安解消・離脱防止 |
| 初診日＋7日 | 初診後フォロー | 関係構築 |
| 次回来院推奨日3日前 | 再診リマインド | 治療継続率向上 |
| 健診実施日翌日 | 健診後フォロー | 結果説明補足・次回案内 |
| ワクチン接種日基準（期限60日前・30日前） | ワクチン期限通知 | 個別タイミング最適化 |
| 生年月日当日 | 個別誕生日配信 | パーソナルな関係維持 |

#### 休眠予防関連（3種類）

| トリガー | 配信名 | 目的 |
|---------|-------|------|
| 最終来院日120日経過 | 休眠予防（軽い接触） | 軽度離脱の予防 |
| 最終来院日180日経過 | 休眠予防（中程度） | 再来院促進 |
| 最終来院日220日経過 | 休眠直前 | 240日休眠を防ぐ最終アプローチ |

#### 予防・物販関連（4種類）

| トリガー | 配信名 | 目的 |
|---------|-------|------|
| `PREV_フィラリア未完了`タグ付与時 | フィラリア予防案内 | 季節予防の個別案内・売上向上 |
| `PREV_ノミダニ対象`タグ付与時 | ノミダニ予防案内 | 個別予防案内・売上向上 |
| 前回フード購入から30日経過 | フード継続購入リマインド | フード継続率向上・売上向上 |
| サプリメント購入後の継続タイミング | サプリメント継続案内 | サプリ継続率向上・売上向上 |

### 4-2. 配信時の除外条件

各配信について、以下を除外条件として設定します。

| 配信 | 除外条件 |
|------|---------|
| 全配信共通 | `EXCL_配信停止` |
| 再診リマインド | すでに予約済みの場合 |
| 休眠予防（120/180/220日） | すでに次回来院推奨日が登録されている場合 |
| 健診後フォロー | `EXCL_配信注意` |
| ワクチン期限通知 | `PREV_ワクチン期限`タグが解除されている（既に接種済み）場合 |
| フィラリア予防案内 | `PREV_フィラリア未完了`タグが解除されている場合 |
| ノミダニ予防案内 | `PREV_ノミダニ対象`タグが解除されている場合 |
| フード継続購入リマインド | フード購入から30日以内に再購入があった場合 |
| サプリメント継続案内 | サプリメント購入から指定期間内に再購入があった場合 |

### 4-3. 配信衝突の優先順位

複数配信が同日に発火する場合の優先順位ルール：

#### 優先順位（高 → 低）

| 優先度 | 配信タイプ | 内容 |
|------|----------|------|
| 1（最優先） | 治療・予防関連 | 再診リマインド、ワクチン期限通知 |
| 2 | 休眠予防 | 休眠220日 > 休眠180日 > 休眠120日 |
| 3 | 予防・物販関連 | フィラリア・ノミダニ予防案内、フード・サプリ継続案内 |
| 4 | 関係性維持 | 個別誕生日 |
| 5 | 既存の一斉配信 | プレミアムフライデー、季節健診告知、専門検診告知、お知らせ系 |

#### 衝突時の処理ルール

- **同一飼い主に1日複数配信が発火する場合、上位優先度を残す**
- **優先度1〜4が発火したら、優先度5の同日配信は翌日以降に延期**
- **優先度1が複数発火した場合は両方配信**（緊急性が高いため）
- **休眠予防は最も日数が長いものを採用**（220日と180日が同時発火なら220日のみ）
- **予防・物販関連は1日に複数発火した場合、1つに絞って配信**（過剰な営業感を避けるため）

### 4-4. 配信時間帯

| 配信タイプ | 配信時間 |
|---------|---------|
| 個別自動配信（全種類） | 朝10時固定 |
| 既存のチーム配信 | 従来通り（変更なし） |

#### 補足

- 運用開始後、開封率・反応率を見て調整する想定
- 必要に応じて配信タイプ別に時間を変える可能性あり（例：誕生日配信を夜19時に変更等）

## 8. スケジュール

林先生の本番稼働期限・既存運用との整合性を踏まえ、以下のフェーズで進めたいと考えています。

### 拠点別実装方針

| 拠点 | 実装着手時期 | 備考 |
|------|----------|------|
| 八王子 | API有効化でき次第（4/30以降） | 先行実装 |
| 城東センター | 5/5以降 | API有効化後 |

**最終納期について：** 本仕様書をご確認の上、**八王子・城東それぞれの実装期間と最終納期をご提示いただけますと幸いです**。

### フェーズ1（運用開始時）

- 既に実装完了済みの集計機能の仕様確認
- CPMステージ判定、上位20%判定、休眠予備軍判定の追加実装
- カルテ→LステップへのCPMタグ・上位20タグ・休眠タグの自動連携
- LINE ID紐付け、配信除外、次回来院推奨日の運用開始
- 個別自動配信（初診後フォロー、再診リマインド、休眠予防）の発火

### フェーズ2（運用安定後）

- 健診・予防タグ判定の精緻化
- 配信トリガーの拡張（健診後フォロー、ワクチン期限通知、個別誕生日）
- 受付・診療側の入力項目追加（予約経路、推奨理由）

### フェーズ3（余裕ができたら）

- 専門検診候補タグの精緻化
- 配信効果分析（クリック者と非クリック者の比較等）
- 来院動機・紹介元等の追加入力項目
