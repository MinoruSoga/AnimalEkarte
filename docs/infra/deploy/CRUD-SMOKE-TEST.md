# ステージング環境・スモークテスト手順書 (Smoke Test Guide)

> **Animal Ekarte**: デプロイ直後の基本動作とデータ整合性の最終確認
> **最新更新**: 2026-05-21

---

## 1. テストの目的
本テストは、デプロイ完了直後のステージング環境において、主要な 3 系統（医院・権限・スタッフ）の機能が、インフラ・DB・API の各層で正しく連携して動作することを確認するために実施します。

---

## 2. 準備：検証用ログイン
検証には `system_admin` 権限を持つアカウントを使用します。

```bash
# 環境変数のセット
export API_V1=https://api.stg.noah-karte.com/api/v1
```

---

## 3. テスト項目

### A. 医院 (Clinics) 系統
1.  **一覧表示**: `ClinicMasterSettings` 画面で、自身が所属する医院が正しく表示されるか。
2.  **編集・保存**: 既存医院の電話番号等を変更し、保存後にリストが自動更新されるか。
3.  **マルチテナント**: 管理者権限（`scope=all`）で全医院が取得でき、一般スタッフ（権限なし）では取得できないか。

### B. 権限グループ (Permissions) 系統
1.  **新規作成**: 「テスト用グループ」を作成し、特定のリソースにのみ閲覧権限を付与。
2.  **反映確認**: スタッフにそのグループを割り当て、期待通りに画面メニューが表示/非表示になるか。
3.  **保護確認**: `system_admin` グループの削除が物理的にブロックされているか（403/409 エラー）。

### C. スタッフ (Staffs) 系統
1.  **新規登録**: 新しいスタッフを登録し、初期パスワードの生成ダイアログが表示されるか。
2.  **ログイン検証**: 発行された ID で実際にログインできるか。
3.  **削除保護 (FK)**: 既にカルテやシフトが紐付いているスタッフを削除しようとした際、適切な警告（409 Conflict）が表示されるか。

---

## 4. 合格基準 (Pass Criteria)
- 全ての API リクエストが期待通りのステータスコード（200, 201, 204 等）を返す。
- フロントエンドの UI にバリデーションエラーやトースト通知が適切に表示される。
- **監査ログ**: `audit_logs` テーブルに、上記の全操作が実行者 ID と共に記録されていること。

---

## 5. 異常発見時のアクション
不具合が発見された場合は、即座に **[ロールバック]** を判断し、`docs/infra/deploy/README.md` のトラブルシューティング手順に移行してください。
