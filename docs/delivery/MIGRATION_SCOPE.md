# 旧カルテからの移行範囲（医院向け）

> **目的**: 旧カルテ（システムイン）から新カルテへ何が移行され、何が移行されないか、医院側で何を準備するかを一覧で示す。
> **読者**: 先方管理者・各医院の責任者。
> **タイミング**: 本番環境の準備を始める前、および移行後の確認時。
> **版**: 第2版・作業途中の中間版（2026-10-13）。移行処理の修正方針を反映したが、修正後の移行データの再生成と、新カルテ側での取込前の確認がまだ終わっていないため、「確定待ち」の行が残る。件数・金額は書かない方針に改め、前版にあった件数を取り除いた。
> **注意**: この文書は本番の切替日を示さない。10/20 は本番環境の構築開始日で、現場がその日に切り替わるわけではない。切替日は、構築と移行データの確認の状況を見てあらためて案内する。

## 1. 見方

| 表記 | 意味 |
|:---|:---|
| 移行される | 旧カルテの内容が新カルテに入る |
| 移行されない（医院が登録） | 新カルテに入らないため、医院が本番で登録する |
| 移行されない（不要） | 新カルテに該当する機能が無い、または旧カルテにデータが無い |
| 確定 | 方針が決まっている |
| 確定待ち | 方針の合意、実装、データ確認のいずれかが未完了。各行の「状態」で「未合意」（方針が未決定）と「未実装・確認がまだ」（記載済みの方針の実装・検証待ち）を区別する。未合意の案は承認済みの契約ではない。確定後にこの表を更新する |

「確定」は方針が決まっていることを示す。実際に移行された内容は、移行後の確認で確かめる。

この一覧に載っていない項目は、まだ調べていない。

## 2. マスタ（診療項目・料金など）

| 項目 | 扱い | 移行後の状態 | 状態 |
|:---|:---|:---|:---|
| 診療項目・処置の名称 | 移行される | 名称・別名・備考・旧カルテの分類・並び順が入る | 確定 |
| 診療項目・処置の料金 | 移行される（予定） | 料金を入れる方針で移行処理を修正済み。負の料金は空にする方針 | 確定待ち（修正後のデータでの確認がまだ） |
| 診療項目・処置の税区分・手術の区分・所要時間 | 税区分・手術の区分は移行予定、所要時間は未対応 | 税区分は旧カルテの記録に合わせて入れ、手術の区分は旧カルテの一部の分類に限って「手術」となるよう、移行処理を修正済み。所要時間は入らない。会計に使う前に確認が必要 | 確定待ち（修正後のデータでの確認がまだ。適用税率の記録方法は、税区分の向きの修正とは別に未合意） |
| 薬剤 | 薬剤マスタへ取り込む（時期は後日） | 旧カルテに薬剤専用のマスタは無く、診療項目の中に含まれている。内服・外用・注射・フィラリア予防薬など、薬剤に明らかに当たる分類を薬剤マスタへ取り込む方法を設計した。本番環境の構築開始（10/20〜）の時点では間に合わず、診療項目として入る。薬剤マスタへ移す時期は、準備ができ次第案内する。薬剤か診療項目か判断が割れる項目（点滴・麻酔・投薬など）は、一覧で医院に確認する。回答がない項目は診療項目のまま移行する | 確定待ち（薬剤マスタへの取り込みが未実装） |
| 療法食・フード・用品 | 移行される | 商品マスタへ名称・単価・税区分が入る。分類は一律「その他」。税区分は旧カルテの会計データに合わせるよう移行処理を修正済みで、負の単価は空にする方針。療法食・フードの一部は旧カルテで診療項目に入っており、診療項目として移行される（料金は上の「診療項目・処置の料金」と同じ扱い） | 確定待ち（修正後のデータでの確認がまだ） |
| ワクチン | 名称は移行される | 料金は、小数を扱う方法の合意がまだなく、移行処理にも入っていない。対象の動物種・在庫との紐付けも未確認。非課税のワクチンは料金を空にする方針 | 確定待ち（料金の扱いが未合意・未実装。動物種・在庫の紐付けは未確認） |
| スタッフ | 移行される（履歴用） | 過去の記録に担当者として表示するための名簿。ログインはできず、予約の担当にも出ない。ログイン用のアカウントは別途発行する | 確定 |
| 予約区分 | 移行されない（医院が登録） | 旧カルテに該当するマスタが無い。標準の5区分（診察・お手入れ・ワクチン・健診・ホテル）は、本番環境の構築時にこちらで用意する。テスト環境で登録した区分は引き継がれない | 確定 |
| トリミングのコース・オプション | 移行されない（医院が登録） | 旧カルテに該当するマスタが無い。テスト環境で登録した内容は引き継がれない | 確定 |
| 診療項目の原価・点数・値引き率 | 現状は移行されない | 新カルテは販売価格のみを持つ。必要かどうかを再確認している | 確定待ち（要否の確認がまだ） |
| セット項目（まとめて登録する組み合わせ） | 移行されない（不要） | 現在の新カルテにはセット項目に当たる機能が無い | 確定 |

## 3. 診察・会計などの履歴

| 項目 | 扱い | 移行後の状態 | 状態 |
|:---|:---|:---|:---|
| 飼主 | 移行される | FAX・2つ目のメールアドレス・勤務先に関する項目は現状入らない（再確認中）。重複した飼主は「同一飼主連携」で整理する | 確定待ち（一部項目の扱いの再確認と、修正後のデータでの確認がまだ） |
| ペット | 移行される | 体重は、単位付きの値だけを入れる方針で移行処理を修正済み | 確定待ち（修正後のデータでの確認がまだ） |
| カルテ（診察記録・問診・診察方針・バイタル） | 移行される | 移行時に確認が必要と判定された記録は、取り込まれない場合がある。範囲を集計中で、救済する方向で検討している。問診の担当者は、旧カルテに担当者が記録されている一部の記録にだけ入る（旧カルテのデータで確認した性質） | 確定待ち（取り込めない記録の範囲の集計・確認がまだ） |
| 会計・支払 | 移行される | 旧カルテの会計には保険・割引を記録する項目が無い。支払の保険・割引の項目の扱いは、修正後のデータと取込結果で確認する（会計明細の保険適用の印は入る）。支払方法は現金とカードの2種類。確認が必要と判定された記録は取り込まれない場合がある。八王子は元データの一部が不完全で、件数が変わる可能性がある | 確定待ち（修正後のデータでの確認がまだ。明細の税率の記録方法は調整中） |
| 見積 | 移行される | 旧カルテに有効期限が記録されていないため、有効期限は空で入る方針。確認が必要と判定された明細は取り込まれない場合がある | 確定待ち（修正後のデータでの確認がまだ） |
| 検査 | 移行される | 検査の結果値は入る。旧カルテの検査は種類を区別せず同じ構成で記録されているため、すべて同じ種類として入る方針 | 確定待ち（修正後のデータでの確認がまだ） |
| ワクチン接種の履歴 | 移行される | 確認が必要と判定された記録は、取り込まれない場合がある | 確定待ち（修正後のデータでの確認がまだ） |
| 予約の履歴 | トリミングの過去予約のみ移行される | 一般診察の予約履歴は移行の対象にならない | 確定 |
| ペットの写真・添付ファイル | 移行されない（不要） | 旧カルテのデータには写真のファイル名しか無く、画像そのものは入っていない。新カルテにはペットの写真を保存する機能も無い。カルテへの添付ファイルに当たるデータも、旧カルテに見つからなかった | 確定 |

## 4. 移行されないもの

次は新カルテに受け皿が無い、またはデータが無いため、移行されない。

- DM の発送履歴
- 帳票の出力履歴
- 同意書の発行履歴
- 投薬管理表（年ごとの投薬チェック）
- 旧システムの画面設定・メニュー・ログイン情報

## 5. 医院にお願いしたいこと

1. テスト環境で登録した予約区分・トリミングコースの控えを残しておく。名称・所要時間・料金・LINE予約への公開の有無が分かればよい。スクリーンショットでよい。
2. 本番環境でのマスタ登録は、最初の管理者アカウントを発行した後に始める。時期は別途案内する。
3. 移行後に確認する（時期は別途案内）: 診療項目・薬剤の料金と税区分、ワクチンの料金、ペットの体重、飼主・ペットの件数と代表データ。
4. 薬剤か診療項目か判断が割れる項目（点滴・麻酔・投薬など）の一覧を、後日お渡しする。どちらで扱うかを選んでもらう（時期は別途案内）。回答が届かない項目は診療項目として移行する。回答がなくても移行全体は進む。

薬剤・診療項目・料金の一覧を医院から共有してもらう必要は、現時点ではない。移行後の確認で不足が見つかった場合に、あらためて相談する。

## 6. 更新予定

「確定待ち」の項目は、各行に記した未合意の方針の合意、未実装部分の実装、修正を反映した移行データの再生成と、新カルテ側での取込前の確認が終わり次第、この表を更新する。医院への確認事項（§5-4）の回答を待つことは、移行やこの表の更新の前提ではない。回答が届いた項目は、その内容に合わせて行を更新する。
