# 画面仕様・UI 設計ディレクトリ (Screens & UI Design)

> **目的**: システムを構成する全画面の機能要件、UI コンポーネント、および画面遷移仕様の管理。

---

## 📂 ディレクトリ構成

- **`README.md`**: 全画面のインデックスと業務カテゴリ別の分類。
- **`00〜99-*.md`**: 個別画面の詳細仕様。項目定義、ユーザーアクション、技術的留意点を網羅。
- **`settings/`**: マスタ設定や環境設定に特化した、高度な管理機能の仕様群。
- **`images/`**: 仕様書内に埋め込まれる画面キャプチャおよびワイヤーフレーム。
- **`common-dialogs.md`**: 全画面で共有されるダイアログや複雑な UI 部品の共通仕様。

---

## 📝 仕様書の記述ルール

1.  **情報の鮮度**: 画面変更や新機能追加の際は、速やかに該当ドキュメントを更新し、ソースコードとの乖離を防ぐ。バッククォートで言及したコンポーネント名・フック名・ファイル名は CI（docs-symbol-drift ジョブ、`scripts/check-docs-symbol-drift.sh`）が実在を機械検査する — 実在しない名前を書くと CI が落ちる。
2.  **臨床安全の明文化**: ミスを防ぐためのバリデーション、警告表示、データ保護（NavigationBlocker）の仕様を必ず記載する。
3.  **アクセシビリティ**: キーボード操作やスクリーンリーダーへの配慮、意味的カラー（Destructive Red等）の使用基準を明記する。
