# トリミング一覧 仕様書 (Trimming List)

## 概要
- **画面の目的**: 院内で実施されるトリミング施術の予約・実績・進捗管理。
- **URLパターン**: `/trimming`
- **アクセス権限**: 認証済ユーザー全員（`ResourceTrimming` 権限が必要）

---

## 1. 画面構成

### 1.1 高機能検索・フィルタ (`PropertyFilter`)
- **施術日指定**: 施術が行われた、または予定されている期間での絞り込み。
- **ステータスフィルタ**: 「予約」「進行中」「完了」による進捗状況の抽出。
- **全文検索**: 患者名、飼主名、スタイル要望キーワードによる検索。
- **トリマー指定**: 担当スタッフによる絞り込み。

### 1.2 施術管理テーブル (`DataTable`)
トリミング室の業務フローに最適化された情報表示。

| カラム | 説明 |
|:---|:---|
| **診療日** | 施術実施（予定）日。 |
| **飼主名** | オーナー名。 |
| **ペット名** | ペット名とペット番号。 |
| **種** | 動物種。 |
| **体重** | 個体の体重。 |
| **スタイル希望** | 今回の主要な要望の抜粋。 |
| **担当** | 施術を担当するスタッフ名。 |
| **ステータス** | 進捗状況を示すカラーバッジ。 |

---

## 2. 主要な運営連携

- **予約管理との統合**: 予約カレンダー (`/reservations`) で作成されたトリミング枠は、当日自動的にこの一覧の「予約済」として出現します。
- **会計への連携**: 記録されたコース・オプション料金は、会計作成時に「未請求明細」API（`billing_item_repository` がトリミング明細を UNION で統合取得）経由で会計側に取り込まれます。施術完了を契機に会計ドラフトを push 送信する仕組みではありません。

---

## 3. 技術仕様

### 3.1 描画の最適化
- **遅延フィルタリング**: `useDeferredValue` により、多数の過去実績を検索する際も軽快な操作感を維持。
- **透過インジケータ**: フィルタ処理中は `FilteringIndicator` により状態を通知。

### API連携
| メソッド | エンドポイント | 用途 | 必須権限 | 必須アクション |
|:---|:---|:---|:---|:---|
| GET | `/api/v1/trimmings` | 条件に応じた施術記録の一括取得 | `trimming` | `view` |
| DELETE | `/api/v1/trimmings/:id` | 施術記録の論理削除 | `trimming` | `delete` |
