# カルテ登録・編集フロー仕様

## カルテID確定タイミング
- カルテ新規作成ページ（`/medical-records/new?petId=X`）の時点では、クライアントサイドのメモリ上でのみデータが保持される（未保存状態）。
- 最初の「保存」ボタン押下（React 19 `formAction`）が成功した時点で、バックエンドでレコードが作成され、カルテIDが確定する。
- 確定後、URL は `/medical-records/:id` に `replace` ナビゲーションされる。

## 保存仕様（ハイブリッド方式）
保存ボタン押下時、以下の 2 段階の保存処理が実行されます。

1. **メイン保存**: `useActionState` を使用したフォーム全体の送信。
   - 保存対象: `medical_records` 本体、`inquiries` (問診) 等の基本データ。
2. **サブ保存（タブ別）**: メイン保存の成功を検知後、**現在アクティブなタブ**固有のデータを追加保存する。
   - 目的: 複雑なリレーションを持つサブテーブル（診察プラン、見積書等）の整合性を保つため。

| タブ | メイン保存対象 | サブ保存（Post-Save）対象 |
|------|--------------|-------------------------|
| 問診 | `medical_records` + `inquiries` | なし |
| 診察/治療プラン | `medical_records` | `clinical_plans` + `treatments` (算定項目) |
| 治療 | `medical_records` | `treatments` (処置記録) |
| 予防接種 | なし（行単位保存） | なし |
| 定期健診 | なし（行単位保存） | なし |
| 検査 | なし（行単位保存） | なし |
| 見積書 | `medical_records` | `estimates` |
| 会計(医師確認) | `medical_records.status` | 会計確定 API (`confirm`) |

## 保存後の挙動
- 保存成功後はページ・タブに留まる（リスト画面には遷移しない）。
- `isDirty` フラグがクリアされ、`NavigationBlocker` の警告が解除される。
- 成功時はトースト通知が表示される。
