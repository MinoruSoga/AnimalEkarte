# Lステップ × 電子カルテ連携 要件定義書

> **クライアント**: ノア動物病院  
> **作成日**: 2026年4月  
> **ステータス**: Q&A確定済み・実装フェーズ計画済み

---

## 1. 概要・背景

ノア動物病院は、LINE公式アカウントの配信ツールとして **Lステップ** を運用している。現状、カルテと連携がなく、すべてのタグ付けや配信トリガーが手動運用になっている。本連携により、カルテ側のイベントをLステップに自動反映させ、飼い主へのリマインダ・フォロー配信を自動化する。

### 解決する課題

| # | 課題 | 規模・影響 |
|---|------|-----------|
| 1 | **ワクチンリマインダの手動運用** | 犬54件+猫52件のリマインダを2週間ごとに手動コピー作成。最大の作業負荷 |
| 2 | **タグ付けが飼い主のキーワード入力に依存** | スタッフが毎回口頭説明。入力漏れが配信セグメントの欠損を生む |
| 3 | **検査結果・証明書の個別送信が手動** | PDFを1件ずつLステップにアップロード→個人トークで手動送信 |

## 2. 連携アーキテクチャ（Q&A確定）

### 2.1 タグ連携方式（Q1）

**カルテ → Lステップ API（タグ付与・解除）**

カルテ側のイベント発生時に、LステップAPIを呼び出してタグを付与・解除する。カルテのデータをそのままLステップに渡す「データ連携」ではなく、イベント駆動の「タグ操作」として実装する。

```
カルテイベント発生
  → カルテバックエンド（Go）
    → Lステップ API: タグ付与/解除
      → Lステップ側でシナリオ自動起動
```

### 2.2 個別メッセージ送信方式（Q2）

**カルテ → LINE Messaging API（直送）**

スタッフによる個別送信（PDF、画像、テキスト）は、LステップAPI経由ではなく、**LINE公式アカウントのMessaging API直送**として実装する。カルテ画面からの操作でPush Messageを送信する。

### 2.3 月間配信数カウント（Q3）

- **Messaging API経由の送信**（Push / Multicast / Broadcast / Narrowcast）: 月間配信数にカウントされる
- **LINEチャット画面からの手動送信**: カウントされない
- カルテからの個別送信はMessaging API経由のため、月間配信数に含まれる点を病院側に周知する

**根拠（LINE公式ヘルプ）:**
- [Message limits（広告対象計算ルール）](https://help2.line.me/official_account_jp/web/?contentId=20011745)
- [Types of messages that count as broadcasts](https://help2.line.me/official_account_jp/web/?contentId=20013941)

### 2.4 配信制御の責任分担（Q9）

- **カルテ側の責務**: イベント発生時にLステップAPIでタグを付与・解除する（起点のみ）
- **Lステップ側の責務**: タグ条件に基づくシナリオ起動・停止・配信制御

Lステップの「1ユーザーに複数シナリオが同時実行できない」制約は、カルテ側がシナリオを直接起動せずタグ操作に限定することで回避する。

### 2.5 拡張性（Q5・Q6）

タグや配信シナリオは後から追加・変更できる設計とする。既存Lステップタグ（健診の季節別タグ、証明書送付済タグ等）も、カルテ操作をトリガーに自動で付与・切り替えできる。

## 7. CPMステージ管理

> **方針**: カルテ側でデータ計算 → Lステップにタグ付与。Lステップ側でステージ条件に基づき配信を制御。  
> カルテ画面へのステージ表示・240日アラートUI・月次レポートは **カルテシステム完成後に別途検討**（Phase 6以降）。

### 7.1 ステージ定義

| ステージ | 判定基準 | 必要なカルテデータ |
|---------|---------|----------------|
| **出会いファミリー** | 来院1回のみ / 最終来院から240日未満 / 累計医療費2万円未満 | 来院回数、最終来院日、累計医療費 |
| **これからファミリー** | 来院2〜3回 / 初診から90日以内に再来院あり / 累計医療費2万〜5万円未満 / 離脱240日未満 | 来院回数、初診日、最終来院日、累計医療費 |
| **コアファミリー** | 年間2回以上来院 / 在籍180日以上 / 累計医療費5万円以上 / 離脱240日未満 | 年間来院回数、初診日、最終来院日、累計医療費 |
| **スポットファミリー** | 高額単発（3万円以上） / 90日以内再来院なし / キャンペーン・緊急中心 ⚠️ 単回来院費の追跡設計が必要（Section 18参照） | 来院回数、診療費（単回・累計両方）、最終来院日 |
| **ノアファミリー** | 在籍1年以上 / 年3回以上来院 / 累計医療費8万円以上 / 予防・健診継続 / 紹介実績or定期購入あり | 初診日、年間来院回数、累計医療費、健診受診履歴、紹介実績 |

### 7.2 ステージ移行ロジック（カルテ側で計算 → タグ切り替え）

| 移行 | 条件 | タグ操作 | 移行時の自動配信（Lステップ側） |
|------|------|---------|--------------------------|
| 出会い → これから | 初診から90日以内に再来院 | `cpm_encounter` 解除 → `cpm_growing` 付与 | フード・予防案内の配信開始 |
| これから → コア | 年2回来院到達かつ累計医療費5万円超 | `cpm_growing` 解除 → `cpm_core` 付与 | 健診教育ステップ配信開始 |
| コア → ノア | 年3回以上来院、在籍12ヶ月超、累計医療費8万円以上 | `cpm_core` 解除 → `cpm_noah` 付与 | 院長メッセージ、限定案内配信 |
| スポット → これから/コア | 90日以内に再来院 | `cpm_spot` 解除 → 条件に応じて付与 | 通常の来院フォロー配信へ移行 |
| 240日未接触（全ステージ共通） | 最終来院日から240日経過 | `cpm_dormant` 付与 | 段階的再活性配信（180日/210日/240日） |
| 休眠 → 復帰 | 240日以上経過後に来院 | `cpm_dormant` 解除 → データ再判定でステージタグ付与 | 来院フォロー配信へ復帰 |

### 7.3 CPMステージの計算タイミング

来院完了（会計確定）時に自動再計算する。処方薬記録（BE-009）はCPMDataのフィールド（来院回数・累計診療費・来院日）に影響しないため、CPMステージの再計算トリガーにはならない。

> **実装注意（✅ 確定済み）**: **ローリング12ヶ月**（`visited_at >= NOW() - INTERVAL '365 days'`）を採用。カレンダー年方式は1月1日に全員の年間来院回数が0回にリセットされCPMステージ降格が大量発生するため不採用。BE-004・BE-011に反映済み。詳細は Section 18 参照。

## 8. 健診対象者抽出（Q7: バッチ連携方式）

健診・検診の種類別配信は、「タグを種類×犬猫で大量作成」するのではなく、**カルテ側で対象者リストを抽出してLステップに一括連携する**方式を採用する。

### 対象健診・検診の種類

| 種類 | 対象動物 |
|------|--------|
| 健診（春） | 犬・猫 |
| 健診（夏） | 犬・猫 |
| 健診（秋） | 犬・猫 |
| 健診（冬） | 犬・猫 |
| 歯科検診 | 犬・猫 |
| 皮膚・耳検診 | 犬・猫 |
| アドプリット検診 | 犬・猫 |
| 眼科検診 | 犬・猫 |
| 腎臓ドック | 犬・猫 |

### 抽出・連携の流れ

1. カルテ管理画面で「健診種類 × 動物種別 × 最終実施日の範囲」を条件に対象者リストを抽出
2. 抽出した飼い主のLINE IDリストをLステップAPIに送信してタグを一括付与
3. Lステップ側でタグ条件に基づき健診案内を配信

## 10. 飼い主のLINEユーザーID管理

タグ連携・個別送信いずれも、飼い主のLINE User IDが必要。

- `owners` テーブルに `line_user_id` カラムを追加（nullable）
- LINE User IDの取得方法: LステップのwebhookまたはLINEログイン連携（別途設計）
- LINE ID未連携の飼い主は連携対象外としてスキップ（エラーにしない）

## 11. 設計原則・制約

| 原則 | 内容 |
|------|------|
| **イベント駆動** | カルテ側はイベント発生時のみLステップAPIを呼ぶ。バッチ同期は原則行わない（健診対象者抽出・休眠検知・ノーショウ検知を除く） |
| **タグ競合の回避** | 同一カテゴリのタグは付与前に旧タグを解除する（例: `cpm_XXX`は1つだけ保持） |
| **冪等性の確保** | 同じイベントが複数回発生しても同じ結果になるよう実装する。重要イベント（来院完了等）は `event_uuid` を冪等性キーとして保持 |
| **LINE ID未連携の扱い** | LINE User IDが未登録の飼い主はスキップ。エラーログのみ記録し処理を継続 |
| **月間配信数の管理** | Messaging API経由の送信はすべてカウント対象。スタッフへ周知が必要 |
| **Lステップ制約の回避** | カルテはタグ操作のみ。シナリオの起動・制御はLステップ側に委ねる |
| **拡張性** | タグ定義や連携ロジックをハードコードせず、設定ファイルまたはDBで管理できる構造にする |
| **タイムゾーン** | すべての日付・時刻処理は **JST（Asia/Tokyo, UTC+9）固定**。タグの `YYYY-MM-DD` も JST 基準 |
| **ペット死亡時の配信停止** | `pets.deceased_at` が設定された場合、該当ペット関連のすべてのタグを解除。全ペット死亡時は飼い主のすべての配信タグを解除（**人道的事故防止のため最優先**）|
| **オプトアウトの尊重** | `owners.lstep_opt_out = true` の飼い主にはイベント駆動タグ付与を一切行わない（特定電子メール法・改正個人情報保護法対応）|
| **退会時のクリーンアップ** | 飼い主削除時にLステップ側のすべてのタグを解除（個人情報保護法の保管期間経過後の削除義務）|

## 15. ファイルストレージとセキュリティ

スタッフ個別送信（Section 6 ②）でPDF・画像を送信する際は、LINE側からアクセス可能な公開URLが必要。これに伴うインフラ要件:

- **ファイルストレージ**: AWS S3（推奨）またはローカルディスク（開発環境）
- **公開URL**: 推測不可能な署名付きURL（24時間有効）
- **ファイル管理**: `shared_files` テーブルに登録、7日経過で自動削除（バッチ）
- **アップロード制限**: 10MB（LINE Messaging APIの制限に合わせる）、許可拡張子は PDF/JPG/PNG のみ
- **マルウェアスキャン**: ClamAV連携（オプション）
- **送信時の自動タグ付与**: `vaccine_cert` 用途で送信したら `cert_sent_vaccine_YYYY-MM-DD` タグを自動付与（既存Lステップタグ運用との互換性確保 — Q6）

詳細は `LSTEP-BE-015-file-storage-for-line-send.md` を参照。

## 17. 既存運用からのマイグレーション戦略

ノア動物病院は **犬54件 + 猫52件のワクチンリマインダ** をLステップで稼働中（原文 Section 1）。本連携の本番投入時に以下の段階的移行が必要。

### Phase A: 並行稼働（本番投入後 1ヶ月）
- 既存Lステップリマインダはそのまま稼働継続
- カルテ側からの新タグ付与・配信は `cpm_*` および `vaccine_*_v2_*` のような **接頭辞・suffixを変えたタグ**で実施
- Lステップ側でテスト配信を実施し、新システムの配信精度を検証

### Phase B: タグ統一（本番投入後 1〜2ヶ月）
- Lステップ側で「既存の `vaccine_*_v2_*` を本番タグに昇格」し、既存タグを段階的に廃止
- カルテ側のタグ付与処理を本番タグ名に切り替え

### Phase C: 既存リマインダ停止（本番投入後 2〜3ヶ月）
- 既存の犬54件・猫52件のLステップリマインダをすべて停止
- カルテ起点の新リマインダのみが稼働

### 既存飼い主の初回CPMステージ判定
- 本番投入時に **全既存飼い主に対して一括バッチ** を実行
- カルテDBの過去データから累計診療費・年間来院回数・初診日・最終来院日を集計
- 各飼い主の初回CPMステージを計算してLステップにタグ付与

### 既存LステップタグのマッピングDB
- 既存タグの棚卸し結果を `tag_mapping_config` テーブル（または YAMLファイル）で管理
- カルテ側のイベントから既存タグへの変換を設定で制御（Q6対応）

## 18. 未解決事項・クライアント確認が必要な仕様（2026-04-25 時点）

以下は実装着手前にクライアントと合意が必要な未確定事項。確定後は各タスクファイルに反映する。

### [CRITICAL] ペット死亡時・飼い主オプトアウト時の配信停止（最重要）

動物医療系SaaSとして致命的な品質要件:
- ペットが死亡した飼い主に「ワクチンの時期です」と配信される事故は **絶対に防ぐ必要がある**
- 飼い主が配信停止を希望した場合の意思表示（オプトアウト）も必須

詳細実装: `LSTEP-BE-017-lifecycle-and-optout-handling.md`

### [CRITICAL] Lステップ APIオプション加入の確認

Lステップは独立サービスであり、APIアクセスは**有料の追加オプション**として別契約が必要。ノア動物病院がLステップ APIオプションに加入していなければ、本連携は技術的に実装不可能。

**→ クライアント確認事項**: ノア動物病院のLステップ契約に「APIオプション」が含まれているか。含まれていない場合は加入の意思があるか。費用感の確認。

### [CRITICAL] LINE User IDの取得手段

タグ連携・個別送信すべての前提となるが、取得方法が未定義。選択肢:

| 方法 | メリット | デメリット |
|------|---------|----------|
| **A. LステップのWebhook受信** | 飼い主のLINE友達追加時に自動取得できる | カルテ側にWebhookエンドポイント実装が必要。飼い主とカルテの紐付け手段が別途必要 |
| **B. LIFF（LINE内ブラウザ）** | LINE User IDを確実に自動取得できる | LIFF開発が追加スコープ。飼い主がLIFFにアクセスするフローが必要 |
| **C. CSV手動インポート** | 既存Lステップ管理画面から取得可能な短期回避策 | 自動化されない。常にズレが生じるリスク |

**→ クライアント確認事項**: 現在ノア動物病院のLステップで「飼い主のLINE User ID一覧」は取得できるか。A/B/Cのどれを採用するか。

### [CONFIRMED] 休眠判定の閾値統一（BE-011確定済み）

閾値は **BE-011で確定済み**:
1. Lステップ `cpm_dormant` タグ付与の閾値: **240日**（CPMの定義に従う）
2. 段階的リマインダー配信の閾値: `dormant_180d`（180日）→ `dormant_210d`（210日）→ `dormant_240d`（240日）の3段階
3. 「1年未来院の特別配信」は 365日経過後に `dormant_365d` タグを付与（BE-011確定済み）
4. バッチ実行頻度: **毎夜 02:00 JST**（cronで設定）

> ⚠️ Section 6 の「6ヶ月（180日）」と「1年以上（365日）」はLステップ配信トリガーの説明であり、`dormant_*` タグの段階的付与と対応している。設計は統一済み。

### [CONFIRMED] `ltv_amount_XXXXX` のN値マッピング（BE-004確定済み）

累計診療費タグの区分値は **BE-004で確定済み**（Lステップ側タグ設定の参考情報）:

| タグ | 累計診療費 |
|-----|-----------|
| `ltv_amount_0` | 0〜19,999円 |
| `ltv_amount_2` | 20,000〜49,999円 |
| `ltv_amount_5` | 50,000〜79,999円 |
| `ltv_amount_8` | 80,000円以上 |

> ⚠️ `ltv_amount_1` は存在しない。N値はCPMステージ閾値（2万/5万/8万円）に対応するバケット識別子であり、「万円単位の数値」ではない。上位顧客への特別配信（LTV順ソート）で10万円超の細分化が必要な場合は別途設計が必要（現時点では対応なし）。

### [CONFIRMED] 「年間来院回数」の「年間」計算期間（BE-004確定済み）

**ローリング12ヶ月**（`visited_at >= NOW() - INTERVAL '365 days'`）を採用。BE-004・BE-011に反映済み。

| 方式 | メリット | デメリット | 採用 |
|-----|---------|----------|------|
| **A. ローリング12ヶ月** | 常に最新行動を反映。季節依存なし | 日々変動するため計算コストがやや高い | ✅ **採用** |
| **B. カレンダー年** | 直感的でシンプル | 1月1日に全員が0回リセット → 年初にCPM降格が大量発生 | ❌ 不採用 |

> ⚠️ Lステップ側のシナリオ設計者に「年間来院回数タグはカレンダー年ではなく過去365日で更新される」旨を伝達すること。

### [CONFIRMED] スポットファミリーの「高額単発（3万円以上）」判定仕様（BE-011確定済み）

CPMステージ「スポットファミリー」の条件「高額単発（3万円以上）」は **BE-011のDBクエリ方式（方式B）として確定済み**:

- BE-011 `SyncCPMStageTag` の `CPMData.MaxSingleVisitAmount` フィールドで、`medical_records` テーブルから直近来院の単回最高請求額をDBクエリで集計
- Lステップに `visit_single_high` タグを送出する方式（方式A）は**不採用** — カルテDB内で計算完結し、判定結果（`cpm_spot` タグ）のみをLステップに渡す

| 方式 | 内容 | 採用状況 |
|-----|------|--------|
| A. 単回来院費タグ追加 | `visit_single_high` タグを会計確定時に付与 | ❌ 不採用 |
| B. カルテDB側で直接計算 | BE-011 CPMステージ判定時にDBクエリで `medical_records` から集計 | ✅ **採用済み** |
| C. スポット判定を簡略化 | 「高額単発」条件を省略 | ❌ 不採用 |

> ⚠️ Lステップ側での「高額単発」フィルタは不可能（タグが存在しない）。Lステップが受け取るのは `cpm_spot` タグのみ。

### [CONFIRMED] `visit_count_annual_N` のN値マッピング（BE-004確定済み）

**BE-004で確定済み**（Lステップ側タグ設定の参考情報）。N値は来院回数バケットの下限値:

| タグ | 年間来院回数 |
|-----|-----------|
| `visit_count_annual_1` | 1回 |
| `visit_count_annual_2` | 2回 |
| `visit_count_annual_3` | 3〜4回 |
| `visit_count_annual_5` | 5〜9回 |
| `visit_count_annual_10` | 10回以上 |

### [CONFIRMED] ペット複数頭時のタグ競合（BE-005確定済み）

**BE-005で確定済み:**

| タグ種別 | 複数頭時の方針 |
|---------|-------------|
| `has_dog` / `has_cat` / `has_both` | 生存ペット全頭で論理和（`deceased_at IS NULL` のみ対象） |
| `breed_XXX` | **最初に登録したペットを優先**（複数犬は `breed_mix_dog`） |
| `pet_birthday_MM-DD` | 複数ペット分を**複数タグ付与**（1飼い主に複数誕生日タグあり） |
| `sex_male` / `sex_female` | 最初に登録したペットの性別 |
| `spay_neutered` / `intact` | OR論理 — 1匹でも避妊去勢済みなら `spay_neutered`、全頭未実施のみ `intact` |

> ⚠️ 死亡ペットのタグは `HandlePetDeath`（BE-017）で解除される。集計クエリは常に `deceased_at IS NULL` の生存ペットのみを対象とする。

### [PENDING-CLIENT] CPM「予防・健診継続」の定義（仮実装済み、クライアント確認待ち）

3. フィラリア予防薬の処方
4. ノミダニ予防薬の処方

判定条件は `config/cpm_prevention_criteria.yaml` で外部化済み — クライアント確認後に設定変更のみで対応可能。

### [CONFIRMED] 複数LINE ID対応の制限（設計決定済み）

`owners.line_user_id` は単一カラム設計 — これはアーキテクチャ上の決定事項であり変更しない。

### [LOW] クリニック休業日の前日リマインダ送信時刻

**カルテ側の実装はタグ付与のみ（BE-007確定済み）。** 送信時刻はLステップ管理画面で設定する（カルテ実装には影響しない）。

**推奨設定（Lステップ管理画面）:**
- 平日の予約: 前日 **18:00 JST** に配信
- 月曜の予約: 直前の営業日（通常は金曜または土曜）の **18:00 JST** に配信

**→ クライアント確認事項**: 運用希望の送信時刻（18:00 で問題なければ確認不要）。Lステップ担当者が設定。

自動配信シナリオ「去勢・避妊適齢期案内」のトリガー条件として月齢が必要だが未定義。一般的な目安:
- 猫: 生後4〜6ヶ月
- 犬（小型〜中型）: 生後6〜8ヶ月  
- 犬（大型）: 生後8〜12ヶ月

実装では「犬猫共通で生後6ヶ月を超えたかつ `intact` タグがある場合に案内タグを付与」とする案。要クライアント確認。
