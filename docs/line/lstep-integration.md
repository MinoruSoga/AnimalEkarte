## 1. システム概要

| 項目 | 内容 |
|------|------|
| 連携方向（基本） | Ekarte → Lステップ（一方向同期） |
| 逆流（限定） | 友だち追加・ブロック・同意状態のみ Lステップ → Ekarte (Webhook) |
| 連携キー | `line_customers.line_user_id`（主キー）、Lステップ顧客ID（補助キー） |
| 同期方式 | イベント駆動（即時 + 再試行付き非同期キュー） |

### スコープ

**In Scope**
- **①カルテ連携**: 患者情報（飼い主・ペット）をLステップのタグへ紐づける
- **②セグメントDM配信**: タグ条件で配信対象制御・配信停止/同意フラグ管理

**Out of Scope**
- Lステップ上のシナリオ設計・配信文面の作成（院内運用）
- Lステップ管理画面の操作・設定代行
- 配信結果レポート・分析基盤

### システム構成

```
┌─────────────────────────────────────────────────────────┐
│                     Ekarte Backend                       │
│                                                          │
│  Event Handler ──► LstepSyncQueue ──► LstepAPIClient   │
│       │                  │                    │          │
│  (予約/来院/ワクチン/健診) │           LステップAPI       │
│                    line_sync_logs                        │
└──────────────────────────┬──────────────────────────────┘
                           │ Webhook
                    ┌──────▼──────┐
                    │  Lステップ   │
                    │  タグ管理    │
                    │  顧客属性    │
                    └─────────────┘
```

## 2. カルテから連携するデータ（クライアント要件）

### 優先度：最優先

| データ | 用途 | 備考 |
|--------|------|------|
| ワクチン接種日（犬/猫別） | 次回接種時期のリマインダ自動起動 | 現在手動運用中。最大の作業負荷 |
| 最終来院日 | 未来院リカバリー配信のトリガー | 6ヶ月・1年以上未来院への来院促進 |
| 犬/猫/両方の分類 | 配信セグメントの基本分類 | カルテのペット登録情報から自動判定 |
| 次回来院推奨日 | 次回来院リマインダ | 獣医師が診察時に設定する「○ヶ月後」の日付 |
| 累計診療費・年間来院回数（LTV） | 顧客ランク管理・LTV別ソート | 上位顧客向け特別配信、LTV順抽出 |
| 初診日 | 在籍期間の計算・CPMステージ判定 | CPMステージ移行条件に必須 |

### 優先度：高

| データ | 用途 | 備考 |
|--------|------|------|
| ペット基本情報（犬種/猫種、性別、生年月日、避妊去勢有無） | 年齢別・種別の配信セグメント | 誕生日配信、シニア向け健診案内等 |

| 慢性疾患フラグ | 疾患別の定期受診案内 | CKD、心疾患、皮膚疾患等 |

| データ | 用途 | 備考 |
|--------|------|------|
| 予約キャンセル・ノーショウ | 再予約促進配信 | キャンセル後のフォロー |

## 3. CPMステージ管理

> **方針**: カルテからデータを連携し、Lステップ側でステージを自動判定・タグ切り替え。  
> カルテ画面へのステージ表示・240日アラートUI・月次レポートはカルテシステム完成後に別途検討。

### ステージ定義

| ステージ | 判定基準 | 必要なデータ |
|---------|---------|------------|
| **出会いファミリー** | 来院1回のみ / 最終来院から240日未満 / 累計医療費2万円未満 | 来院回数、最終来院日、累計医療費 |
| **これからファミリー** | 来院2〜3回 / 初診から90日以内に再来院あり / 累計医療費2万〜5万円未満 / 離脱240日未満 | 来院回数、初診日、最終来院日、累計医療費 |
| **コアファミリー** | 年間2回以上来院 / 在籍180日以上 / 累計医療費5万円以上 / 離脱240日未満 | 年間来院回数、初診日、最終来院日、累計医療費 |
| **スポットファミリー** | 高額単発（3万円以上） / 90日以内再来院なし / キャンペーン・緊急中心 | 来院回数、診療費、最終来院日 |
| **ノアファミリー** | 在籍1年以上 / 年3回以上来院 / 累計医療費8万円以上 / 予防・健診継続 / 紹介実績or定期購入あり | 初診日、年間来院回数、累計医療費、健診受診履歴、紹介実績 |

### ステージ移行ロジック

| 移行 | 条件 | 移行時の自動配信 |
|------|------|----------------|
| 出会い → これから | 初診から90日以内に再来院 | タグ昇格、フード・予防案内の配信開始 |
| これから → コア | 年2回来院到達かつ累計医療費5万円超 | 健診教育ステップ配信開始 |
| コア → ノア | 年3回以上来院、在籍12ヶ月超、累計医療費8万円以上 | 院長メッセージ、限定案内配信 |
| スポット → これから/コア | 90日以内に再来院 | 通常の来院フォロー配信へ移行 |
| 240日未接触（全ステージ共通） | 最終来院日から240日経過 | 再活性ステップ配信（180日/210日/240日段階的）。復帰後にステージ再判定 |

## 4. イベント → Lステップアクション マッピング

| カルテ側のイベント | Lステップ側のアクション |
|-----------------|----------------------|
| ワクチン接種を記録 | 次回接種時期の2ヶ月前からリマインダ配信を自動起動 |
| 来院完了を記録 | 最終来院日タグを更新 |
| 健診を実施 | 健診受診タグ付与＋次回健診推奨日を設定 |
| 予約が登録される | 前日リマインダーを配信 |
| 予約がキャンセルされる | キャンセルタグ付与＋再予約促進配信 |
| 処方薬を記録 | 補充推奨日タグを設定 |
| 新規飼い主・ペット登録 | ペット基本情報タグを自動付与（犬猫分類、犬種、生年月日等） |
| 来院・会計データの更新 | CPMステージの自動再判定（累計医療費・来院回数・在籍期間） |

## 6. タグ設計

> タグ一覧はLステップAPI（`GET /v1/tags`）から取得しマッピングに使用。手動共有不要。

### イベント駆動タグ

| イベント | 付与するタグ | 解除するタグ |
|---------|------------|------------|
| 予約作成（初回） | `予約あり` `来院予定` `初診` | — |
| 予約作成（2回目以降） | `予約あり` `来院予定` `再診` | `初診` |
| 予約キャンセル | `キャンセル歴あり` | `予約あり` `来院予定` |
| 来院完了（受付終了） | `来院済` `フォロー対象` `再診候補` | `来院予定` |
| ワクチン接種記録 | `ワクチン接種済` `次回案内対象` | — |
| 健診実施記録 | `健診済` `定期案内対象` | — |
| 次回案内期限切れ | — | `次回案内対象` `定期案内対象` |
| 友だち追加 (Webhook) | `LINE連携済` | — |
| 配信停止 | `配信停止中` | すべての配信対象タグ |

### 属性タグ（患者情報から静的付与）

| 条件 | タグ |
|------|------|
| `pets.species = '犬'` | `犬` |
| `pets.species = '猫'` | `猫` |
| 年齢 < 1歳 | `子犬・子猫` |
| 1歳 ≤ 年齢 < 7歳 | `成犬・成猫` |
| 年齢 ≥ 7歳 | `シニア（7歳以上）` |
| `pets.gender = 'male'` | `オス` |
| `pets.gender = 'female'` | `メス` |
| ワクチン記録あり | `ワクチン管理対象` |
| 健診記録あり | `健診管理対象` |

## 7. API連携仕様

### Lステップ API（Ekarte → Lステップ）

| 操作 | メソッド・パス | タイミング |
|------|------------|---------|
| タグ一覧取得 | `GET /v1/tags` | 起動時・定期同期 |
| タグ付与 | `POST /v1/contacts/{userId}/tags` | イベント発生時（即時） |
| タグ解除 | `DELETE /v1/contacts/{userId}/tags` | 条件変化時 |
| 顧客属性更新 | `PUT /v1/contacts/{userId}` | 飼い主・ペット情報更新時 |
| 顧客検索 | `GET /v1/contacts?line_user_id={id}` | 初回紐づけ時 |

### Webhook受信（Lステップ → Ekarte）

```
POST /api/webhooks/lstep
```

| イベント | Ekarte での処理 |
|---------|---------------|
| `follow` | `line_customers` レコード作成・`LINE連携済`タグ付与 |
| `unfollow` | `is_blocked = true` 更新 |
| `consent_agreed` | `is_consent = true` 更新 |
| `consent_revoked` | `is_consent = false`・配信停止フラグ更新 |

```sql
CREATE TYPE lstep_sync_event AS ENUM ('tag_add', 'tag_remove', 'attr_update');
CREATE TYPE lstep_sync_status AS ENUM ('pending', 'success', 'failed');

CREATE TABLE line_sync_logs (
    id             bigserial   PRIMARY KEY,
    clinic_id      bigint      NOT NULL REFERENCES clinics(id),
    line_user_id   text        NOT NULL,
    event_type     lstep_sync_event NOT NULL,
    payload        jsonb       NOT NULL,
    status         lstep_sync_status NOT NULL DEFAULT 'pending',
    retry_count    int         NOT NULL DEFAULT 0,
    error_message  text,
    created_at     timestamptz NOT NULL DEFAULT now(),
    updated_at     timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_line_sync_logs_clinic_status
    ON line_sync_logs(clinic_id, status) WHERE status IN ('pending', 'failed');
CREATE INDEX idx_line_sync_logs_line_user
    ON line_sync_logs(line_user_id, created_at DESC);
```

## 9. エラーハンドリング・再試行

```
API呼び出し失敗
    ↓
line_sync_logs に status='failed', retry_count++ で記録
    ↓
retry_count < 3 → 指数バックオフで再試行（1分 / 5分 / 30分）
    ↓
retry_count = 3 → status='failed' で停止 → 手動再同期
```

### Q1. タグ連携の方式

**質問**: タグ連携はカルテ側のデータをLステップのAPIに渡す形になるか？ それとも別の連携方法を想定しているか？

**回答**: Lステップ API（`POST /v1/contacts/{userId}/tags`）経由でタグ付与・解除を行う方式で実装する。カルテ側でイベントを検知し、非同期キュー経由でLステップAPIを呼び出す設計。Webhook連携は友だち追加・ブロック・同意状態の受信のみ。

**状態**: 未確認

### Q2. スタッフ個別送信の経路

**質問**: カルテからLINEへの個別メッセージ送信（②スタッフ個別送信）は、LステップのAPI経由か？ それともLINE公式アカウントのAPI直接か？

**回答**: Lステップ API経由を推奨する。Lステップ上に送信履歴が残り、スタッフが一元管理できる。LINE公式API直接の場合、Lステップ側の送信記録に残らず配信管理が分断する。Q3の確認結果によっては再検討。

**状態**: 未確認

### Q3. 個別送信と月間配信数

**質問**: カルテからの個別送信（②）は、LINE公式アカウントの月間配信数にカウントされるか？

### Q9. Lステップ複数シナリオ制約の回避

**質問**: カルテからの配信がLステップのシナリオ枠を使わない方式であれば、1人に複数シナリオを同時に走らせられない制約を回避できるか？

**回答**: 回避できる。カルテからはLステップ APIでタグを付与・更新するだけでシナリオを直接起動しない。シナリオはLステップ側の「タグ条件トリガー」で起動するため、シナリオの優先制御はLステップ側の設定で管理できる。

**状態**: 未確認
