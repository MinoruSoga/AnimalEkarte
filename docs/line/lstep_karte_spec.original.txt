1. 現在のLステップ運用における課題
カルテとLステップの連携を設計するにあたり、現在の運用上の課題を共有します。これらの課題が連携によって解決されることを想定しています。
課題1：ワクチンリマインダの手動運用
犬・猫のワクチン接種リマインダをLステップのリマインダ機能で運用しています。接種日を起点に、約1年後の接種時期の2ヶ月前から段階的にリマインドを配信する仕組みです。現在、犬54件・猫52件のリマインダが稼働中ですが、2週間ごとに手動でコピー・作成する必要があり、大きな作業負荷になっています。
課題2：タグ付けが飼い主のキーワード入力に依存
飼い主にタグを付ける方法が「LINEのトーク画面で特定のキーワードを入力してもらう」ことに限られています。スタッフが毎回「○○と打ってください」と口頭で説明する必要があり、飼い主側にも手間がかかります。キーワードを打たなかった飼い主にはタグが付かず、配信セグメントから漏れてしまいます。
課題3：検査結果・証明書の個別送信
健診の検査結果PDFやワクチン証明書を、スタッフが1件ずつLステップのメディアにアップロードし、個人トークで手動送信しています。日常的に発生する業務であり、効率化が求められています。

	Q1. カルテ側の情報連携
	質問: 上記のタグ連携は、カルテ側のデータをLステップのAPIに渡す形になりますか？ それとも別の連携方法を想定されていますか？
	
	回答: 後者です。カルテ側のデータをそのままLステップに渡す形ではなく、Lステップのタグ情報を参照し、カルテ側のイベントをきっかけに必要なタグの付与・解除を行います。
	
	Q2. 個別メッセージの送信方法
	質問: カルテからLINEへの個別メッセージ送信（②スタッフ個別送信）は、LステップのAPI経由でしょうか？ それともLINE公式アカウントのAPI直接でしょうか？
	
	回答: カルテ画面からの操作でMessaging APIを使って送信する前提です。PDFや画像はURL送付で扱い、必要に応じて個別に送信します。LステップのAPI経由ではなく、LINE公式アカウントのMessaging API直送を想定しています。
	
	Q3. 配信数の扱い
	質問: カルテからの個別送信（②）は、LINE公式アカウントの月間配信数にカウントされますか？
	
	回答: はい。カルテ画面から送信する実装がMessaging API経由であれば、Push / Broadcast / Narrowcast に該当するため、月間配信数にカウントされます。LINE chat messages (sent or received) は broadcast に数えないのは、あくまでLINE公式アカウントのチャット画面での手動送信です。
	根拠: LINE公式ヘルプの Message limits では、LINE chat messages (sent or received) は broadcast に数えない一方、Messaging API の Push / Multicast / Broadcast / Narrowcast は数えると案内されています。あわせて Types of messages that count as broadcasts でも同様の整理がされています。

	https://help2.line.me/official_account_jp/web/?contentId=20013941
	Q4. 段階的な進め方
	質問: 実装の優先順位として、最優先のタグ連携（ワクチン接種日、最終来院日、犬猫分類、次回来院推奨日）からフェーズを分けて進めることは可能でしょうか？
	
	回答: はい。まず最優先のタグ連携から実装します。
	
	Q5. 追加・変更
	質問: 連携するタグや配信シナリオを、病院側で後から追加・変更できる設計は可能でしょうか？ 今後、新しい施策（例：腎臓ドック、新しいキャンペーン等）に応じてタグや配信内容を柔軟に追加していく運用を想定しています。
	
	回答: はい。後からタグや配信シナリオを追加・変更できる前提で設計します。
	
	Q6. 既存タグの自動切り替え
	質問: 現在Lステップで運用中のタグ（健診の季節別タグ、証明書送付済タグ等）を、カルテ側の操作をトリガーに自動で付与・切り替えする連携は可能でしょうか？ 現行のタグ体系に限らず、より効率的な方法があればご提案いただけると助かります。
	
	回答: はい。既存タグも、カルテ側の操作に応じて自動で付与・切り替えできます。
	
	Q7. 健診対象の絞り込み
	質問: 健診・検診の種類ごとの最終実施日に基づく配信対象の抽出は、カルテ側で行ってLステップに連携する設計は可能でしょうか？ タグを種類×犬猫で大量に作るのではなく、カルテ側で対象者リストを抽出して渡す方式が望ましいと考えています。
	
	回答: はい。カルテ側で対象者を抽出し、Lステップに連携します。
	
	Q8. 診療費や来院回数での絞り込み
	質問: 累計診療費や来院回数（LTV）でのソート・抽出機能は実装可能でしょうか？ 上位顧客に絞った施策配信などに活用したいと考えています。
	
	回答: はい。累計診療費や来院回数をもとに対象を絞り込めます。
	
	Q9. 配信の重なり対策
	質問: 現在Lステップでは1人に対して複数シナリオを同時に走らせることが難しく、長期シナリオの実行中に来院フォロー等の別配信を起動できない制約があります。カルテからの配信がLステップのシナリオ枠を使わない方式であれば、この制約を回避できると考えていますが、いかがでしょうか？
	
	回答: はい。カルテ側は起点だけ持ち、配信制御はLステップ側でタグ条件により行います。
