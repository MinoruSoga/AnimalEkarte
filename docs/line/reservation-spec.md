# LINE予約システム仕様書

> **参考元**: 「予約 on ライン」マニュアル 第1.2版（2019年2月7日）
> **対象**: ノア動物病院（NOAH Veterinary Clinic）— 城東センター病院・猫専門病院(Hako bu neco)
> **目的**: 同等機能を持つ予約システムを自作で新規開発する
>
> **構成**:
> - セクション 1〜14: 原典マニュアルに基づく汎用仕様（UIワイヤーフレーム含む）
> - **セクション 15: 実データに基づく実装確定仕様（ノア動物病院向け）** ← 実装時はここを参照
>
> ---
> **⚠️ 2026-04-13 統合リファクタリング最終反映**
>
> LINE予約管理の全機能（カレンダー/コース/スタッフ/スケジュール/顧客管理）は、電子カルテ本体のマスタ設定および予約管理ページに完全統合されました。
>
> 主な変更:
> - 診療メニュー設定 → `/settings/reservation-type`（LINE予約フィールド統合）
> - スタッフ設定 → `/settings/staff`（LINE予約フィールド + 対応不可予約区分統合）
> - シフト休憩時間 → `/shifts`（`shift_entry_breaks` テーブルによる複数休憩管理）
> - 予約カレンダー → `/reservations`（source='line' フィルタ対応）
> - LINE顧客管理 → `/owners/:id`（LINE連携セクション統合）
> - LINE予約専用設定 → `/line-reservation/settings` および `/line-reservation/page-editor`

## 1. システム概要

### 1.1 システム構成

本システムは、電子カルテ本体（Go/Gin WebAPI）を共通バックエンドとし、2つのフロントエンドで構成されます。

| コンポーネント | 役割 | 技術スタック |
|---|---|---|
| **LIFF App**（ユーザー向け） | お客様がLINEアプリ内で操作して予約を行う | React 19, TypeScript, LIFF SDK |
| **管理画面**（病院向け） | 予約状況の確認、マスタ設定、LINE公式アカウント連携設定を行う | React 19, Vite, Tailwind 4 |

### 1.2 動作環境

| プラットフォーム | 要件 |
|---|---|
| iOS | iOS 8 以降 |
| Android | 4.2 (Jelly Bean MR1, API level 17) 以降 |
| LINE | バージョン 7.14 以降 |
| コントロールパネル | Chrome, Edge, IE, Safari 等のブラウザ |

### 1.3 LINE連携

- LINE公式アカウント（channel ID）と店舗を紐付け
- LINEアプリ内で予約画面を表示（LIFF or リッチメニュー想定）
- 顧客のLINE表示名を自動取得し、名前入力のデフォルト値に使用

### 2.1 画面遷移（7ステップ）

```
1. 名前の確認・入力
   ↓
2. スタッフ選択
   ↓
3. コース選択
   ↓
4. 日付の選択
   ↓
5. 時間の選択
   ↓
6. 要望等の入力
   ↓
7. 予約内容の確認 → 確定
```

### 2.2 各画面の詳細

#### STEP 1: 名前の確認・入力

| 項目 | 仕様 |
|---|---|
| 表示名 | LINEで使用中のお名前を初期表示 |
| 初回ユーザー | 本名でない方は本名が分かるように入力を促す |
| 2回目以降 | 前回予約で使用されたお客様情報を表示し、必要があれば修正 |
| 追加入力項目 | 管理者が設定した追加項目（例：電話番号）も表示される |
| ボタン | 「次へ」「戻る」 |

```
┌─────────────────────────────┐
│  お名前の確認・入力            │  ← 画面タイトル（白背景・黒文字）
│                               │
│  ・初めてのお客様...LINEで    │  ← 説明テキスト（箇条書き）
│    使用中のお名前を表示...     │
│  ・二回目以降のお客様...      │
│                               │
│  お名前  [与野 百合    ] 様   │  ← テキスト入力 + 「様」敬称ラベル
│                               │
│  ■ 電話番号                   │  ← 追加入力項目（管理者設定時のみ）
│  [090-0000-9999        ]      │     プレースホルダー付き
│                               │
│  ┌─────────────────────┐     │
│  │     次へ ▶            │     │  ← 緑色プライマリボタン（幅100%）
│  └─────────────────────┘     │
│  ┌─────────────────────┐     │
│  │     ◀ 戻る            │     │  ← 白色アウトラインボタン（幅100%）
│  └─────────────────────┘     │
└─────────────────────────────┘
```

#### STEP 2: スタッフ選択

| 項目 | 仕様 |
|---|---|
| 選択肢 | 「選択せずに予約」＋ 有効状態のスタッフ一覧 |
| 表示内容 | スタッフ名（肩書）、プロフィール画像（設定時） |
| 表示順 | コントロールパネルで設定した順序 |
| 指名なし | 「選択せずに予約」を選択可能 |

```
┌─────────────────────────────┐
│  スタッフ選択                  │
│  ■ スタッフを選択して下さい。  │
│                               │
│  ┌───────────────────── ▶ ┐  │  ← リスト項目（右シェブロン付き）
│  │ 選択せずに予約            │  │     常に先頭に表示
│  └───────────────────────┘  │
│  ┌───────────────────── ▶ ┐  │
│  │ [写真] 島田 弥生          │  │  ← 画像あり: サムネイル + 名前(肩書)
│  │        (チーフアドバイザ)  │  │
│  └───────────────────────┘  │
│  ┌───────────────────── ▶ ┐  │
│  │ 綾部 早苗（アドバイザ）   │  │  ← 画像なし: 名前(肩書)のみ
│  └───────────────────────┘  │
└─────────────────────────────┘
```

#### STEP 3: コース選択

| 項目 | 仕様 |
|---|---|
| 選択肢 | 有効状態の施術コース一覧 |
| 表示内容 | コース名（所要時間）、コメント、画像（設定時） |
| フィルタ | 選択したスタッフが対応不可のコースは非表示 |
| 曜日フィルタ | コースに曜日オプションが設定されている場合、該当曜日のみ表示 |
| 表示順 | コントロールパネルで設定した順序 |

**コース表示名の命名規則:**
```
画像なし: 「{コース名}」 + コメント
画像あり: [サムネイル] + 「{コース名}」 + コメント

曜日オプション付きの場合:
  「【{曜日制限}】{コース名}（{所要時間}分間）」
  例: 「【平日】アフターケア（60分間）」
  例: 「【土曜】無料ケア体験（90分間）」
  コメント行: 「平日の購入者様向け定期アフターケアはこちらです。」
```

```
┌─────────────────────────────┐
│  コースの選択                  │
│  ■ コースを選択して下さい。    │
│                               │
│  ┌───────────────────── ▶ ┐  │
│  │ [画像] 【平日】アフターケア │  │  ← 画像サムネイル + コース名
│  │        （60分間）          │  │     所要時間はコース名に含む
│  │  平日の購入者様向け定期    │  │     コメント（説明文）
│  │  アフターケアはこちらです。│  │
│  └───────────────────────┘  │
│  ┌───────────────────── ▶ ┐  │
│  │ 【土曜】無料ケア体験       │  │

│  │  土曜の無料ケア体験は      │  │
│  │  こちらをお選び下さい。    │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

#### STEP 4: 日付の選択

| 項目 | 仕様 |
|---|---|
| 表示形式 | 月間カレンダー（複数月表示可能） |
| 選択不可日 | グレー背景で表示、タップ不可 |
| 選択不可条件 | 予約受付期間外、店休日、祝日（設定時）、スタッフ個人休日 |
| 表示月数 | 基本設定の「カレンダー表示月数」に依存 |
| 曜日色分け | 日曜=赤、土曜=青、平日=黒 |

```
┌─────────────────────────────┐
│  日付の選択                    │
│  ■ 日付を選択して下さい。      │
│  ※背景がグレーの日は予約受付  │
│    期間外や店体日等のため      │
│    選択できません。            │
│                               │
│       2018年6月               │
│  ◀ 日 月 火 水 木 金 土 ▶    │  ← 前月/翌月ナビゲーション矢印
│              ┃          1  2  │
│     3  4  5  6  7  8  9      │  ← 日=赤文字, 土=青文字
│    10 11 12 13 14 15 16      │     選択不可日=グレー背景
│    17 18 19 20 21 22 23      │     今日=太字
│    24 25 26 27 28 29 30      │     選択可能日=通常表示・タップ可
│                               │
│  ※カレンダー表示月数設定で    │
│    複数月を並べて表示可能      │
└─────────────────────────────┘

カレンダーの状態表示:
  - 選択可能日: 通常テキスト（黒/赤/青）、タップで次画面へ
  - 選択不可日: グレー背景 + グレー文字、タップ無効
  - 曜日限定コース選択時: 該当曜日以外すべてグレーアウト
```

#### STEP 5: 時間の選択

| 項目 | 仕様 |
|---|---|
| 表示内容 | 空きのある時間帯のみ表示 |
| 形式 | 「開始時刻 〜 終了時刻」のリスト |
| 生成ロジック | 営業時間・休憩時間・コース所要時間・既存予約を考慮して自動生成 |
| 空き時間計算 | 2つのモード（後述：予約時間候補の出し方） |

```
┌─────────────────────────────┐
│  時間の選択                    │
│  ■ 時間を選択して下さい。      │
│  ※空きのある時間のみ表示      │
│    しています。                │
│                               │
│  ┌───────────────────── ▶ ┐  │

│  └───────────────────────┘  │     終了時間 = 開始 + コース所要時間
│  ┌───────────────────── ▶ ┐  │
│  │ 10:30 〜 12:00            │  │
│  └───────────────────────┘  │
│  ┌───────────────────── ▶ ┐  │     ← 休憩時間帯はスキップ
│  │ 13:00 〜 14:30            │  │
│  └───────────────────────┘  │
│  ...                          │
└─────────────────────────────┘

※営業開始/終了時刻が個人設定で変更されている場合:
  開始時刻・終了時刻が赤丸で強調表示される
```

### 6.3 基本設定

予約 on ラインの動作を制御する核心設定。

#### 6.3.1 予約を受け付けない日

| 項目 | 仕様 |
|---|---|
| 設定方法 | 曜日指定 ＋ 日にち指定 |
| 動作 | 指定した日はカレンダーでグレーアウト・選択不可 |
| 例 | 日曜を選択 → 全日曜が選択不可 |

#### 6.3.2 国民の祝日

| 項目 | 仕様 |
|---|---|
| 設定方法 | チェックボックス ON/OFF |
| 動作 | ONにすると祝日がカレンダーでグレーアウト・選択不可 |

#### 6.3.3 予約を受け付ける時間帯

| 項目 | 仕様 |
|---|---|
| 意味 | 営業時間 |
| 設定方法 | 曜日ごと or 一括指定 |
| 形式 | HHMM〜HHMM（例：0900〜1800） |
| 動作 | この時間帯内で時間選択リストが生成される |

#### 6.3.4 予約を受け付けない時間帯

| 項目 | 仕様 |
|---|---|
| 意味 | 休憩時間 |
| 設定方法 | 複数指定可能 |
| 形式 | HHMM〜HHMM（例：1200〜1300） |
| 動作 | この時間帯を省いて時間選択リストが生成される |

#### 6.3.5 同日予約制限数

| 項目 | 仕様 |
|---|---|
| 意味 | 同一ユーザーが同一日に予約できる最大数 |
| 動作 | 上限を超えるとエラーメッセージ「両日内に予約できる件数を超えています。別の日をお選びください。」 |

#### 6.3.6 同月予約制限数

| 項目 | 仕様 |
|---|---|
| 意味 | 同一ユーザーが同一月に予約できる最大数 |
| 動作 | 上限を超えるとエラーメッセージ「両月内に予約できる件数を超えています。別の月をお選びください。」 |

#### 6.3.7 予約受付期間

| 項目 | 仕様 |
|---|---|
| 設定方法 | 最大N日前 〜 最短N日前 |
| 動作 | 範囲外の日付はカレンダーでグレーアウト |
| 例 | 最大「30」日前 〜 最短「2」日前 → 2日後〜30日後のみ選択可能 |

#### 6.3.8 カレンダー表示月数

| 項目 | 仕様 |
|---|---|
| 意味 | 日付選択画面のカレンダー表示月数 |
| 設定 | 予約受付期間の最大日数に応じて調整 |

#### 6.3.9 問い合わせ電話番号

| 項目 | 仕様 |
|---|---|
| 表示場所 | 予約画面上 |
| 用途 | 予約に関する問い合わせ先 |

#### 6.3.10 予約通知メールアドレス

| 項目 | 仕様 |
|---|---|
| 動作 | 予約確定時・キャンセル時にメール通知を送信 |
| 送信先 | 設定されたメールアドレス |

#### 6.3.11 要望の具体例

| 項目 | 仕様 |
|---|---|
| 表示場所 | STEP 6「要望等の入力」画面のプレースホルダー |
| 例 | 「化粧水の購入を予定しています。」 |

#### 6.3.12 予約時間候補の出し方

2つのモードから選択：

**モード1: 「予約を受け付けられない空きを許容する」**

| 項目 | 仕様 |
|---|---|
| 動作 | 指定した間隔で時間候補を生成 |
| 設定 | 「時間候補の間隔」を指定 |
| 例 | 60分/90分コースがある場合、30分間隔で候補を生成（10:00, 10:30, 11:00...） |
| 結果 | 短い空き時間が発生する可能性がある |

**モード2: 「予約を受け付けられない空きを極力作らない」**

| 項目 | 仕様 |
|---|---|
| 動作 | 全コース中で最も短いコースが前後に入れられるように候補を生成 |
| 例 | 60分が最短コースの場合、14:00〜15:00が選択されても前後に60分の枠が確保される |
| 結果 | 効率的な時間配分で空き時間を最小化 |

#### 6.3.13 指名なし予約の扱い

| 選択肢 | 動作 |
|---|---|
| 空いているスタッフへ委譲 | 表示順の上位から空いているスタッフの指名として受付 |
| 表示順最上位スタッフへ委譲 | 常に表示順の最上位スタッフの指名として受付 |

#### 6.3.14 ユーザー入力追加項目名

| 項目 | 仕様 |
|---|---|
| 用途 | 名前以外に追加で入力を求める項目 |
| 設定方法 | 項目名を入力（例：「電話番号」） |
| プレースホルダー | 「/」で区切って指定可能（例：「電話番号/例) 090-1234-5678」） |
| 動作 | STEP 1「お客様情報の確認・入力」画面に追加フィールドとして表示 |

### 8.5 管理者権限での予約挿入（手動予約）

電話等、別の手段で受けた予約を手動登録する機能。

## 11. ビジネスロジック詳細

### 11.1 時間枠生成アルゴリズム

```
入力:
  - 営業時間 (business_hours)
  - 休憩時間 (break_hours)
  - コース所要時間 (duration)
  - 既存予約一覧
  - スタッフ個人設定 (override)
  - 時間候補モード (mode)

処理:
  1. スタッフの当日の勤務時間を決定
     - 個人設定がある場合はそちらを優先
     - なければ基本設定の営業時間を使用
  2. 勤務時間から休憩時間を除外
  3. 既存予約の時間帯を除外
  4. 残りの空き時間から、コース所要時間が収まる枠を列挙

  モード別:
    A) 「空きを許容」: 指定間隔で候補を生成
    B) 「空きを極力作らない」: 全コース中の最短時間を考慮し、
       前後に最短コースが入れられる枠のみ生成
```

### 11.2 指名なし委譲ロジック

```
入力:
  - 選択された日時
  - 選択されたコース
  - 委譲モード (空きスタッフ / 最上位スタッフ)

処理:
  A) 空いているスタッフへ委譲:
     表示順の上位から順に、該当時間帯が空いているスタッフを検索
     → 最初に見つかったスタッフに割り当て

  B) 表示順最上位スタッフへ委譲:
     常に表示順1位のスタッフに割り当て
     （空き状況に関係なく）
```

### 11.3 予約制限チェック

```
予約確定前に以下をチェック:
  1. 同日予約制限: 同一ユーザーの当日予約数 < daily_limit
  2. 同月予約制限: 同一ユーザーの当月予約数 < monthly_limit
  3. 予約受付期間: booking_window_min <= 日数差 <= booking_window_max
  4. 休業日チェック: 店休日・祝日でないこと
  5. 時間枠の空き: 選択した時間枠がまだ空いていること
```

### 15.7 DBスキーマ（確定版 — 既存テーブル統合方式）

> **設計方針**: 既存AnimalEkarteのテーブルを最大限活用する。
> 予約データは共通テーブル `appointments` に統合し、カルテ・来院管理と自動連携する。
> スタッフは既存 `staffs`、診療メニューは既存 `reservation_types` を拡張・利用する。

#### 既存テーブルと予約システムの対応

| 予約システムの概念 | 使用するテーブル | 方式 |
|---|---|---|
| 診療メニュー | `reservation_types` | 予約用列を包含 |
| スタッフ | `staffs` | 予約用列を包含 |
| スタッフ非対応コース | `staff_reservation_exclusions` | **新規** M:N中間テーブル |
| シフト/個人設定 | `shift_entries` | 既存をそのまま使用 |
| シフト中の中断時間 | `shift_entry_breaks` | **新規** |
| 予約データ | `appointments` | 共通テーブル（source 列で識別） |
| LINE予約設定 | `line_reservation_settings` | **新規**（clinic_id で UNIQUE） |
| LINE顧客 | `line_customers` | **新規** |
| 飼い主・ペット | `owners` / `pets` | 既存をそのまま使用 |

```sql
-- ============================================================
-- LINE予約システム マイグレーション
-- 既存テーブル拡張 + 新規テーブル4つ
-- ============================================================

-- ============================================================
-- A. 既存テーブルの拡張（ALTER TABLE）
-- ============================================================

-- A0. ENUM型の追加
CREATE TYPE staff_type AS ENUM ('doctor', 'nurse', 'resource');
```

#### リアルタイム同期の仕組み

**LINE予約と本体カルテの予約管理は同一テーブル（`reservation_appointments`）を使用するため、同期処理は不要。データベースレベルで常に一致している。**

```
┌─────────────────────────────────────────────────────────────┐
│                  reservation_appointments                     │
│                    （単一の予約テーブル）                       │
│                                                               │
│  ┌──────────────┐     INSERT/SELECT     ┌──────────────┐    │
│  │ LINE予約      │ ──────────────────→  │              │    │
│  │ (LIFF App)    │ ←────────────────── │              │    │
│  │ source='line' │    空き時間計算       │  同じテーブル  │    │
│  └──────────────┘                      │              │    │
│                                         │              │    │
│  ┌──────────────┐     INSERT/SELECT     │              │    │
│  │ 管理画面      │ ──────────────────→  │              │    │
│  │ (手動予約)    │ ←────────────────── │              │    │
│  │ source='manual│    予約一覧表示       │              │    │
│  └──────────────┘                      └──────────────┘    │
│                                                               │
│  ┌──────────────┐     SELECT                                 │
│  │ カルテ画面    │ ──────────────────→ 同じレコードを参照     │
│  │ (来院管理)    │    reservation_appointment_id FK           │
│  └──────────────┘                                            │
└─────────────────────────────────────────────────────────────┘
```

**同期シナリオ:**

| 操作 | 即時反映先 | 仕組み |
|---|---|---|
| LINE予約確定 | 管理画面の予約状況に即表示 | 同一テーブルへの直接INSERT |
| 管理者が手動予約 | LINEの空き時間から即除外 | 同一テーブルをSELECTで参照 |
| 管理者がキャンセル | LINEの空き時間に即復活 | status='cancelled'で空き枠に戻る |
| LINE顧客がキャンセル | 管理画面の予約状況から即消去 | 同一レコードのstatus更新 |
| スタッフのシフト変更 | LINEの空き日付/時間に即反映 | shift_entriesを共用 |
| 診療メニュー変更 | LINEのコース一覧に即反映 | service_typesを共用 |
| 来院チェックイン | LINE側のマイ予約に即反映 | 同一レコードのstatus更新 |

**ポイント: 「同期」ではなく「共有」。** 別々のデータストアを同期するのではなく、同じデータストアを複数のインターフェースから参照・更新する設計。同期ラグは原理的にゼロ。

**管理画面のリアルタイム更新について:**
- v1: ブラウザリロードまたはポーリング（30秒間隔）で最新データを取得
- v2: WebSocket / Server-Sent Events でプッシュ通知（リロード不要）

### 15.7b テクニカル詳細（既存テーブル統合の補足定義）

既存テーブル統合方式に伴い、以下の詳細ルールを定義する。

#### (1) 予約ステータス・ライフサイクル

既存 `reservation_status` ENUM をそのまま使用する。LINE予約のフローは以下の通り。

```
LINE予約確定 → confirmed（即時確定。承認制はv2）
  ↓
来院（受付） → checked_in
  ↓
診察開始 → in_consultation
  ↓
会計 → accounting
  ↓
完了 → completed

キャンセル（任意タイミング） → cancelled
```

| タイミング | status値 | 操作者 |
|---|---|---|
| LINE予約確定（POST /api/liff/reservations） | `confirmed` | 顧客（LIFF） |
| 管理者手動予約（POST /api/.../reservations） | `confirmed` | 管理者 |
| キャンセル（DELETE） | `cancelled` | 顧客 or 管理者 |
| 来院チェックイン | `checked_in` | 管理者（既存フロー） |
| 以降 | 既存フローと同一 | 管理者 |

※ `pending` はv1では使用しない。v2の承認制導入時に使用する。

#### (2) shift_type → 予約可能時間のマッピング

`shift_entries.shift_type` と予約可能時間の対応ルール:

```
full       → start_time ?? settings.business_hours.start
             ~ end_time ?? settings.business_hours.end
             （全日勤務。start_time/end_timeがあればそちら優先）

morning    → start_time ?? settings.business_hours.start
             ~ end_time ?? settings.break_hours[0].start
             （午前のみ。break_hours の開始時刻が境界）

afternoon  → start_time ?? settings.break_hours[0].end
             ~ end_time ?? settings.business_hours.end
             （午後のみ。break_hours の終了時刻が境界）

off        → 予約不可（時間枠を生成しない）

paid_leave → 予約不可（時間枠を生成しない）
```

**start_time / end_time の優先ルール**:
- NOT NULL の場合 → その値を使用（個別シフトのオーバーライド）
- NULL の場合 → 上記の shift_type デフォルト値を使用

**shift_entry_breaks の適用**:
- `shift_entry_breaks` に中断時間がある場合、その時間帯を予約可能時間から除外
- 中断時間は複数登録可能

**shift_entries が存在しない日**:
- `reservation_settings.business_hours` をデフォルトとして使用
- `reservation_settings.break_hours` をデフォルト中断時間として使用
- 休業曜日・祝日チェックは別途（セクション11.1のアルゴリズム参照）

#### (3) スタッフの施設名導出

スタッフ表示フォーマット: `{施設名}　{名前}({肩書})`

```
施設名 = staff_clinic_assignments WHERE is_main = true
         JOIN clinics ON clinics.id = staff_clinic_assignments.clinic_id
         → clinics.name

肩書   = occupations WHERE id = staffs.occupation_id
         → occupations.name

例: staff_clinic_assignments.clinic_id → clinics.name = "城東センター病院"
    staffs.name = "林 文明"
    occupations.name = "獣医"
    → "城東センター病院　林　文明(獣医)"
```

複数施設に所属するスタッフは `is_main = true` の施設名を表示。

#### (4) スタッフ種別（staff_type）

既存 `staffs` テーブルに `staff_type` カラムを追加する。

```sql
CREATE TYPE staff_type AS ENUM ('doctor', 'nurse', 'resource');
ALTER TABLE staffs ADD COLUMN staff_type staff_type NOT NULL DEFAULT 'doctor';
```

| 種別 | 説明 | account_id | occupation_id |
|---|---|---|---|
| `doctor` | 実在の獣医師 | あり | あり（獣医） |
| `nurse` | 実在の看護師 | あり | あり（看護師） |
| `resource` | 仮想リソース枠 | NULL | 任意 |

- `resource` タイプはカレンダー上で人名ではなくリソース名（「クイックシャンプー①」等）で表示
- `occupation_id` は表示ラベル用（任意）。`staff_type` はロジック制御用

**注意**: このALTER TABLEはセクション15.7のマイグレーションSQLに追加する。

#### (5) service_types の既存データとの突合

マイグレーション時の方針:

```
1. ALTER TABLE で予約用カラムを追加（全て DEFAULT 値付き → 既存データ安全）
2. シードSQLで以下を実行:
   a. 既存 service_types に名前が一致するレコード → UPDATE で予約用カラム設定
   b. 存在しないコース（休憩枠、予約不可 等） → INSERT
3. ON CONFLICT 対応のため、(clinic_id, name) にUNIQUE制約を追加するか、
   アプリケーション層で重複チェックする
```

**v1方針**: シードSQLは手動で clinic_id を指定し、既存レコードの id を確認した上で UPDATE/INSERT を実行する。完全自動化はv2。

#### (6) customer_fields と既存カラムの使い分け

LINE予約時の `reservation_appointments` への格納ルール:

| フィールド | 格納先 | 値 |
|---|---|---|
| 飼い主名 | `customer_fields.owner_name` | STEP 1 入力値 |
| ペットの名前と種類 | `customer_fields.pet_info` | STEP 1 入力値 |
| 電話番号 | `customer_fields.phone` | STEP 1 入力値 |
| 診察内容 | `customer_fields.symptoms` **AND** `notes` | 両方に格納（既存UI互換） |
| 飼い主 | `owner_id` | NULL（v2の紐付け機能まで） |
| ペット | `pet_id` | NULL（v2の紐付け機能まで） |
| 担当医 | `doctor_id` | 選択したスタッフのID（指名なし委譲時は委譲先） |
| コース | `service_type_id` | 選択したコースのID |

```
  1. LIFF起動時に GET /api/liff/settings を呼ぶ

  ※ v1は実質シングルテナント（1つのLIFF URL = 1つのクリニック）
  ※ v2でマルチクリニック対応時にURLルーティングを導入
```

#### (10) reservation_day_option の値定義

service_types に追加する `reservation_day_option` の取りうる値:

| 値 | 意味 |
|---|---|
| `none` | 全曜日で予約受付（デフォルト） |
| `saturday` | 土曜日のみ |
| `sunday` | 日曜日のみ |
| `weekday` | 平日のみ |
| `holiday` | 祝日のみ |

**v1方針**: ノア動物病院の実データでは全コースが `none`（曜日制限なし）。カラムは追加するがv1では使用しない。LIFF APIのコース取得時にフィルタリングロジックを実装しておくが、全コース `none` なので実質無効。

### 15.8b-4 実装詳細の補足

#### 確認番号の採番方法

```
フォーマット: R-YYYYMMDD-NNNN

採番方式: PostgreSQL シーケンス（日次リセットなし）+ アプリ層で日付プレフィックス付与

実装:
  1. reservation_appointments INSERT 時に id が自動採番される
  2. confirmation_number = "R-" + date.Format("20060102") + "-" + fmt.Sprintf("%04d", id % 10000)
  3. confirmation_number は reservation_appointments に格納しない（都度計算）
     → id と date から一意に導出可能なため、カラム追加不要

例:
  id=123, date=2026-04-10 → R-20260410-0123
  id=10001, date=2026-04-10 → R-20260410-0001（下4桁）

注意: 厳密な一意性は id で保証。confirmation_number は表示用。
```

#### LIFF Appの状態管理

```
方式: React state（in-memory）+ sessionStorage バックアップ

理由:
  - URLベース（/step/1, /step/2）は LIFF WebView でブラウザバック時に
    LINE自体が閉じるリスクがある
  - sessionStorage はタブ閉じで消える（予約途中データの永続化は不要）

実装:
  1. useReservationFlow() カスタムフック で全ステップのstateを管理
  2. 各ステップ完了時に sessionStorage に保存
  3. LIFF再起動時（事故的な閉じ→再開）にsessionStorageから復元
  4. 予約完了 or トップページ遷移時に sessionStorage をクリア

state構造:
  {
    currentStep: 3,
    customerInfo: { name: "...", phone: "...", ... },
    selectedCourse: { id: 1, name: "一般診察", ... },
    selectedStaff: { id: 5, name: "林 文明", ... },
    selectedDate: "2026-04-10",
    selectedTime: { start: "0900", end: "0915" },
    requestText: ""
  }
```

#### 管理画面でのLINE予約の視覚的区別

```
予約状況画面（月表示・日表示）での表示ルール:

source='line' の予約:
  - 予約ブロックの左端に 📱 アイコン（またはLINEロゴ色の縦線）
  - ツールチップに「LINE予約」と表示
  - customer_name = customer_fields.owner_name（owner_id が NULL のため）

source='manual' の予約:
  - アイコンなし（従来通り）
  - customer_name = owners.owner_name（owner_id JOIN）

共通:
  - is_staff_delegated=true の場合: スタッフ名の前に「→」矢印を表示
  - status='cancelled' の予約は表示しない（deleted_at IS NULL でフィルタ）
```

#### reservation_customers の更新ポリシー

```
更新タイミング: 予約確定時に毎回上書き

POST /api/liff/reservations の処理内で:
  UPDATE reservation_customers
  SET display_name = ?, real_name = ?,
      additional_fields = ?,
      updated_at = NOW()
  WHERE id = ?

→ 顧客が名前や電話番号を変更した場合、次回予約時に自動反映される
→ 前回入力値の復元（GET /api/liff/profile）は最新の reservation_customers から取得
```

### 15.8c エンドツーエンド・データフロー

#### フロー1: LINE予約の確定

```
1. 顧客がLINEリッチメニューの「予約する」をタップ
   → LIFF URL (https://liff.line.me/1654799214-lJDKL5JQ) が開く

2. LIFF App が liff.init() → liff.getProfile() で LINE user_id を取得
   → GET /api/liff/settings で予約設定を取得
   → status="stopped" ならメンテナンス画面表示して終了

3. STEP 1: GET /api/liff/profile で前回入力値を復元 → 顧客が入力

4. STEP 2: GET /api/liff/courses でコース一覧表示 → 選択

5. STEP 3: GET /api/liff/staffs?courseId=X でスタッフ一覧表示 → 選択

6. STEP 4: GET /api/liff/available-dates?courseId=X&staffId=Y で空き日付表示 → 選択

7. STEP 5: GET /api/liff/available-times?courseId=X&staffId=Y&date=Z で空き枠表示 → 選択

8. STEP 6: 要望入力（任意）

9. STEP 7: 確認画面 → 「予約する」タップ
   → POST /api/liff/reservations

10. バックエンド処理:
    a. SELECT FOR UPDATE で時間枠の空きを再確認
    b. 同日/同月予約制限チェック
    c. staff_id=0 なら指名なし委譲ロジック実行
    d. reservation_appointments に INSERT:
       - source = 'line'
       - status = 'confirmed'
       - line_customer_id = reservation_customers.id
       - customer_fields = STEP 1 の入力値
       - notes = customer_fields.symptoms
       - doctor_id = 選択 or 委譲されたスタッフ
       - service_type_id = 選択コース
       - owner_id = NULL (v1)
       - pet_id = NULL (v1)
    e. reservation_customers の additional_fields を更新（次回プリフィル用）
    f. LINE Messaging API でプッシュ通知送信（非同期）
    g. メール通知送信（非同期）

11. STEP 8: 完了画面表示

12. 管理者が管理画面を開く
    → GET /api/.../reservations?view=day&date=2026-04-10
    → 既存の予約一覧にLINE予約が表示される（source='line' で区別）
    → 来院時: status を checked_in → 以降は既存フロー
```

#### フロー2: 管理者による手動予約

```
1. 管理者が管理画面の予約状況（日表示）を開く
2. 空きセルをクリック → 手動予約入力モーダル
3. POST /api/.../reservations に:
   - source = 'manual'
   - status = 'confirmed'
   - line_customer_id = NULL
   - 入力したスタッフ/コース/日時
4. reservation_appointments に INSERT
5. バリデーションなし（重複チェック・休日チェックなし）
```

#### フロー3: キャンセル

```
A. 顧客自身によるキャンセル（LIFF App）:
   1. マイ予約一覧から選択
   2. DELETE /api/liff/my-reservations/:id
   3. reservation_appointments.status = 'cancelled'
   4. LINE Push通知 + メール通知

B. 管理者によるキャンセル:
   1. 予約状況画面で予約ブロックをクリック
   2. 確認ダイアログ → OK
   3. DELETE /api/.../reservations/:id
   4. reservation_appointments.status = 'cancelled'
   5. source='line' の場合のみ LINE Push通知送信
```

### 15.8d エッジケース・ハンドリング

| エッジケース | 発生条件 | ハンドリング |
|---|---|---|
| **時間枠の競合** | 確認画面→確定の間に他者が同じ枠を予約 | SELECT FOR UPDATE → 409 SLOT_TAKEN → STEP 5に戻す |
| **同日予約制限超過** | 同一顧客が同日に2回目の予約 | 409 DAILY_LIMIT → STEP 4に戻す |
| **同月予約制限超過** | 同一顧客が同月にN回目の予約 | 409 MONTHLY_LIMIT → STEP 4に戻す |
| **メンテナンス中** | status='stopped' の状態で予約試行 | 503 MAINTENANCE → メンテナンス画面表示 |
| **スタッフ全員休日** | 選択日に全スタッフがoff/paid_leave | available-dates で available=false (reason="no_slots") → 選択不可 |
| **空き枠0件** | 選択日の全枠が予約済み | available-times で slots=[] → 「空きがありません。別の日をお選びください。」表示 |
| **コース0件** | 全コースが非表示/非アクティブ | courses で空配列 → 「現在予約可能なメニューがありません」表示 |
| **スタッフ0件** | 選択コースに対応可能なスタッフが0 | staffs で空配列 → 「現在対応可能なスタッフがいません」表示 |
| **LIFF初期化失敗** | LINE外でアクセス/ネットワーク障害 | 「LINEアプリからアクセスしてください」エラー画面 |
| **友だち未追加** | LINE友だちでないユーザー | 「友だち追加してからご利用ください」案内画面 |
| **LINE Push送信失敗** | Messaging API障害/Rate Limit | ログに記録。予約自体は成功させる。リトライは行わない（v1） |
| **メール送信失敗** | SMTP障害 | ログに記録。予約自体は成功させる |
| **過去日のキャンセル** | 過去の予約をキャンセル試行 | 400 Bad Request。過去の予約はキャンセル不可 |
| **既にキャンセル済み** | cancelled の予約を再度キャンセル | 404 Not Found（cancelled はリストに表示されない） |
| **ブラウザバック** | 予約完了後にブラウザバック | 完了画面から戻ると確認画面に戻るが、再送信防止（重複チェック）で409 |

### 15.11 原典からの変更点まとめ

| # | 項目 | 原典 | 実装版 | 理由 |
|---|---|---|---|---|
| 1 | フロー順序 | 名前→スタッフ→コース | 名前→**コース→スタッフ** | 実運用に準拠。コースで絞り込んでからスタッフ選択が合理的 |
| 2 | ステップ数 | 7 | **8**（完了画面追加） | 実運用に準拠 |
| 3 | 追加入力項目 | 1フィールド | **複数フィールド**（JSONB） | 電話番号・飼い主名・ペット情報・診察内容の4項目 |
| 4 | お名前と飼い主名 | 同一 | **別フィールド** | お名前=LINE表示名、飼い主名=実名 |
| 5 | コース種別 | 全て顧客向け | 顧客向け + **管理者専用**（`is_internal`） | 休憩枠・予約不可等の時間ブロック用 |
| 6 | スタッフ種別 | 全て人 | doctor / nurse / **resource** | クイックシャンプー枠・ドックラン等の仮想リソース |
| 7 | 施設名 | 店舗名のみ | **スタッフごとの施設名**表示 | 「城東センター病院 林 文明(獣医)」形式 |
| 8 | 用語 | サロン用語 | 動物病院用語 | 施術コース→診療メニュー、要望→診察内容 |
| 9 | DB設計 | 独立テーブル8個 | **既存テーブル統合** + 新規4個 | 既存 staffs, service_types, reservation_appointments, shift_entries を拡張。カルテ・来院管理と自動連携 |
| 10 | 予約データ | 独立テーブル | 既存 `reservation_appointments` に統合 | LINE予約確定 → カルテの来院予定に自動反映。`source='line'` で区別 |
| 11 | スタッフ管理 | 独立テーブル | 既存 `staffs` に列追加 | スタッフ追加/変更が一元管理。reservation_visible で予約表示を制御 |
| 12 | シフト管理 | 独立テーブル | 既存 `shift_entries` を共用 | シフト登録 → 予約可能時間に自動反映 |
