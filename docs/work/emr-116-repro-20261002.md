# EMR-116 (SLACK-STAFF-SELECT) — 担当者選択不能の stub-free 再現ハーネス結果

- 日付: 2026-10-02
- 対象 unit: UNIT-EMR-116 (campaign emr116-sat-20261002b / attempt ATT-EMR-116-001)
- 検証リビジョン: worktree `/private/tmp/ae-emr-116-r2` detached at `608a5f55ad82372d0e28e2d7ae37a9b36b326aa0` (main 相当)
- ハーネス: `frontend/src/components/shared/ReservationFormModal/ReservationFormModal.staff-select-device.test.tsx`（回帰テストとして残置）

## 目的

iPad / 一部 PC で「担当者（獣医師）を選べない」という申告の再現確認。
`ReservationFormModal.staff-candidates.test.tsx` は `SearchableSelect` を `vi.mock` で
差し替えているため Dialog × portaled Popover × cmdk の実経路は未検証だった。
本ハーネスは製品コンポーネントを一切 stub せず、実物の親 `Dialog` + `Popover` +
`SearchableSelect` + `cmdk` を mount し、
候補 render → 選択 → フォーム値 → 保存 payload → 再表示 を経路別に比較する。

ネットワーク層は msw（`@/testing/mocks/node`）で固定 — コンポーネント stub ではなく
プロジェクト標準の API 境界モック。

## 仮端末条件マトリクス（jsdom / vitest 4.1.11 / user-event 14.6.7）

| 経路 | 条件 | 候補 render | 選択 | フォーム値 | 保存 payload | 結果 |
|------|------|-------------|------|-----------|--------------|------|
| mouse (fine pointer) | matchMedia 既定 (matches=false) + user.click | 対応スタッフのみ表示・非対応は除外 | click → onSelect | trigger が「鈴木」表示 | onSave `{doctor:"11", type:"5"}` | PASS |
| keyboard | trigger.focus → Enter 開放 → cmdk ArrowDown/ArrowUp/Enter | 同上 | cmdk onSelect | 同上 | 同上 | PASS |
| coarse pointer | `matchMedia("(pointer: coarse)").matches=true` + pointerType=touch の pointerOver/Down/Up + click | 同上 | tap → onSelect | 同上 | 同上 | PASS |
| user.pointer TouchA | 同上 + user-event touch デバイス | 同上 | tap → onSelect | trigger「鈴木」 | （選択まで検証） | PASS |

## 候補状態の分離（present-but-unselectable との区別）

| 状態 | 条件 | 表示 | option role | 結果 |
|------|------|------|-------------|------|
| empty | 全員 capable_courses=[]（type 5 選択時） | 「この条件で対応可能なスタッフがいません」 | 0 件 | PASS |
| loading | reservation-staffs を promise gate で pending | 「スタッフ候補を読み込み中です」 | — | PASS |
| failure | reservation-staffs が 500 | 「スタッフ候補の取得に失敗しました」 | 対象 option なし | PASS |
| present-but-unselectable | 候補は render するが選択できない | — | — | **再現せず**（全経路で選択成立） |

## イベント / フォーカス差分

- fine pointer: Popover 開放時に `data-slot="command-input"`（cmdk 検索入力）へ autofocus が移る。
- coarse pointer: `SearchableSelect` の `onOpenAutoFocus` が `matchMedia("(pointer: coarse)")` で
  `preventDefault` し、検索 input への強制 focus を抑止（iPad のソフトキーボード誘発による
  Popover 不安定化の回避）。テストでは開放後 `document.activeElement` が command-input
  でないことを検証。
- 選択成立で Popover は閉じ option は unmount。`onCloseAutoFocus` も preventDefault で
  Dialog の FocusScope へ焦点を戻さない。
- `CommandItem.onPointerDown` は非 disabled 候補で `preventDefault` — pointerdown 時の
  focus 移動を抑止し、cmdk の onSelect（click 由来）が iPad でも発火する。
- modal `Popover` + `DialogContent` の `shouldPreventDialogOutsideInteraction` により、
  portaled option への pointerdown/tap は Dialog の outside-interaction dismiss を起こさない。
- `PopoverContent` の `pointer-events-auto` が modal Dialog の `body{pointer-events:none}` を
  打ち消し、portaled option へ click が届く。

## 既知の jsdom 差分（製品不具合ではない）

- jsdom は `TouchEvent.touches` を構築できず、`react-remove-scroll` の document リスナが
  `event.touches[0].clientX` で `TypeError` を投げる。ハーネスの touch tap は
  Radix/cmdk が実際に消費する `pointerover/pointerdown(pointerType:"touch")/pointerup/click`
  列のみを発火させる（TouchEvent は発火しない）。
- 2026-08-23 記録の「jsdom + カバレッジ計装で FocusScope が focus を掴み直し Popover が
  即閉じる」現象は、本リビジョンでは **素の実行・`--coverage` 双方で再現しなかった**
  （8/8 PASS）。当該 stub コメントは instrumentation + 当時の実装差分に依存する
  テスト環境側の履歴所見として扱う。

## 分離規則の保持

- active（`status === "active"`）/ 出勤（on-duty）/ capability（capable_courses 肯定形・
  fail-closed）/ clinic（`/v1/clinics/{clinicId}/reservation-staffs` の医院スコープ — 
  clinic 分離は API 側で行われ、FE は queryKey に clinicId を含めて残留を防ぐ）を変更していない。
- 「全スタッフ開放」workaround は採用していない。capability フィルタは
  `filterStaffCandidatesByCapability` の fail-closed 契約を維持。

## 結論

現行リビジョンで候補表示→選択→保存→再表示の全経路が合成環境で成立し、
申告された「候補があるのに選べない」症状は再現しなかった。修復すべき製品側の
欠陥は検出されず、プロダクトコードへの差分はない（最小修正の対象なし）。

境界: 合成環境の成功は元 iPad の実機症状解消や医院受入の証拠ではない。
実機（対象 iPad / PC のブラウザ版）での確認は引き続き残件とする。
