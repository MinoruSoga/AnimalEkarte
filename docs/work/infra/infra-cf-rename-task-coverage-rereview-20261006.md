## 判定

前回の抜け16件は、作業項目としては EMR-298 の計画要件か EMR-302 / EMR-303 に載っている。未記載の項目はない。

残る不足は1件である。STG 予行の確認項目一覧が、実行しない EMR-298 の計画成果にあり、実行する EMR-302 の合格条件になっていない。

`blocked_by` の向き（302 は 298 の完了後、303 は移行のブロッカーにしない）は正しい。303 が 302 の完了全体を待つことと、10/20 チケット群にブロック関係が無いことが、新しい順序の穴である。

## 抜け

### 予行の確認項目が EMR-302 の合格条件になっていない

EMR-298 は棚卸しと計画のみで、実行しない。確認項目一覧（Worker×4、service binding、R2、DO、cron、Access、LINE/LIFF、CORS、ゾーン、CI トークンの投入先）は、その計画文書の必須成果である。

EMR-302 の本文にあるのはスコープ、退役、改名5単位、順序制約、人間ゲート、人間決定である。計画の確認項目一覧を予行の合格条件にする文がない。

EMR-302 に1文足す。予行の合格は、EMR-298 の確認項目一覧をすべて満たすことである。

### 順序制約「7件」の一覧が本文から一意に数えない

依頼文は「§4 手順に順序制約7件（上記 EMR-302 と同じ）」と書く。EMR-302 の順序制約として列挙されている文は5つである。同時武装の禁止、ホスト名受領後の DNS/LINE 切替、`renamed_classes` と instance 名の同一リリース、切り戻し訓練後の退役、予行トークンの限定。

残り2件は、スコープ側の「Hyperdrive 先行除外」と「api と frontend の同一デプロイ」と読むのが自然である。計画 §4 には、この7文を番号付きで並べる。スコープの文から数を推測しない。

## 過剰

### 人間決定と順序制約が EMR-298 と EMR-302 の両方に本文としてある

決定の置き場は EMR-298 の §5、手順の正は EMR-298 の §4 である。EMR-302 はそれらを入力として実行する。同じ一覧を EMR-302 の本文に再掲すると、後から片側だけ直したときに二つの正ができる。

EMR-302 は「人間決定の正は EMR-298 §5、手順の正は EMR-298 §4」と参照する。再掲はしない。

### 本番の空資源が EMR-302 と既存の本番チケットの両方に見える

EMR-302 のスコープは Worker×4 と、空の prod bucket の作成を含む。既存チケットは本番構築、10/20 切替、PROD-SETUP、GOLIVE、初回管理者付与で、読み替え対象である。

空の本番 Worker、空 bucket、本番トークン、本番 DNS のどれを EMR-302 が作り、どれを読み替え後の PROD-SETUP が作るかが、どちらの本文にも境界として無い。両方が作ると二重になり、どちらも作らないと 10/20 の前提が空になる。

境界は1つにする。EMR-302 が新アカウントに作る本番側は、空 bucket と、cron を止めたままの prod api と prod frontend までである。PROD-SETUP 以降は、その殻の上の初回構築、GOLIVE、初回管理者付与だけを持つ。

## 分割・順序リスク

### 改名5単位を EMR-302 の1枚に置いたままにしない

5単位の順序自体は前回の分割案と一致している。問題は Plane の1ステータスと `blocked_by` が、チケット単位でしか動かないことである。

- ① CF 実行時識別子は、初回デプロイと同一リリースである。移行、予行、切り戻し訓練、soak、退役と同じチケットに残す。
- ② Go module の全置換は「別窓」と書かれている。約1700ファイルであり、10/20 前後の実装と同じ木を広く触る。EMR-302 の Done に含めると、静かな窓が来るまでアカウント移行チケットが開いたままになる。別チケットにする。
- ③ ローカル開発名は「最後」と書かれている。ディレクトリ名が compose project と volume を変える。切替チケットの完了条件に置かない。別チケットにする。
- ④ packaging と導入済み端末、⑤ docs と UI は、CF の単一実行確認の後でよい。EMR-302 の Done、および EMR-303 の開始から外し、別チケットにする。
- repo の in-place 改名は正しい。実施窓は②と同じにする。①の DNS 切替窓にも、③のディレクトリ改名にも重ねない。3文字列の決定は EMR-298 で同時に固定し、実施時期だけを分ける。

子チケットにせず本文の5段階のままにすると、②が止まるあいだ ①の完了を Done にできず、EMR-303 も始まらない。

### EMR-303 が EMR-302 の完了全体を待っている

「移行のブロッカーにしない」は、303 が 302 を止めない、という向きとしては正しい。依存の逆向きは、303 が 302 の完了後である。

302 が②③④⑤と旧アカウント退役まで含むと、使用量確認はディレクトリ改名の後まで始まらない。費用の主因である cron 5式は、新アカウントで武装した時点から課金される。GraphQL Analytics の定期確認は、新アカウントの STG が稼働し、新しいトークンで照会できる時点で開始する。

通知ポリシーの適用は、`notification_email` の帰属が決まってからで足りる。EMR-303 の `blocked_by` は、EMR-302 全体ではなく、新アカウント STG の稼働とトークン発行に付ける。

### 10/20 チケット群にブロックが無い

10/20 との関係は、EMR-302 の人間決定であり、推奨は「新アカウントの初回構築へ読み替える」である。既存の本番構築、PROD-SETUP、GOLIVE、初回管理者付与は別件のままである。

推奨は、共有アカウントで先に本番を作る実施を止めない。決定が降りる前に既存チケットを進めると、未稼働の本番を共有アカウントに作り、その後もう一度移すことになる。前提は、本番未稼働のうちに移すことである。

読み替え後の依存は次の1本にする。

- 10/20 と PROD-SETUP は、新アカウントでの STG 予行合格、cron の単一武装、空の本番殻の後に着手する。
- 旧アカウントの削除、Go module、ディレクトリ改名、docs の完了は待たない。
- 共有アカウントへの本番構築は実施しない。有料プラン、所有者、費用主体が STG 予行に間に合わない場合は、10/20 の日付を動かす。この判断は EMR-298 §5 の決定として残す。

### 旧 R2 キーの失効が切り戻し訓練より前にある

スコープの R2 手順は「コピー、チェックサム照合、切替、旧キー失効」である。退役は「照合、切り戻し訓練1回、soak の後」である。

切替の直後に旧キーを失効すると、訓練で旧 bucket の読み取りに戻れない。STG の画像は `stg-images` にだけある。旧キーの失効は、訓練と soak の後の退役段階へ移す。コピー手順は切替で止める。

### Worker×4 の同一デプロイが、予行トークンの限定と衝突しうる

「Worker×4（api と frontend の同一デプロイ）」と、「予行は `CLOUDFLARE_API_TOKEN` のみ」が同じチケットにある。

service binding が要求するのは、環境ごとの api と frontend を同じデプロイにすることである。stg の2つを1回、prod の2つを別の1回にする。4つを予行の1回に含め、STG 用トークンで prod Worker まで作ると、予行が本番シェルの作成を兼ねる。

予行がデプロイするのは stg の api と frontend である。prod の api と frontend は、その後に `PROD_CLOUDFLARE_API_TOKEN` で、cron を止めたまま作る。

### 旧 cron の disarm と削除の時点が1文になっていない

同時武装は禁止され、cron 5式の削除は soak 後の退役である。切替から退役までのあいだ、旧 cron を武装したまま新 cron を上げると禁止に反する。新 cron を退役まで止めると、そのあいだ容器の稼働が旧アカウントに残る。

切替の時点で旧 cron と旧 DO の実行を止め、新側だけを武装する。資源の削除は soak 後である。停止と削除を同じ操作にしない。

## このまま実施してよい依存

- EMR-302 は EMR-298 の完了後に着手する。実行前の分類、3文字列、DO 空起動の受け入れ、workers.dev の置換先は、計画の出口で固定されてから実行に入る。
- アカウント作成、トークン発行、有料プラン、ゾーンと DNS の移管、GitHub secret、LINE コンソールは、EMR-302 の人間承認ゲートのままとする。
- 本番データコピー、共有アカウントの閉鎖、workers.dev subdomain の解放、既存チケット本文の一括書き換え、使用量通知の未決を移行の完了条件にすることは、今回の記載に含まれていない。追加しない。
