## 4. 前金登録から取消までの院内チェックリスト

1. **元対象を確定**：clinic、元owner、任意appointment、必要petと実施記録。名前一致・予約変更・主飼主変更で資金を付け替えない。予約紐づけなしは許容し、0や仮予約で補わない。
2. **外部の事実を確認**：受領の額・通貨／円としての値・実日時・方法・外部取引ref・成立状態を資料と照合。providerが未知なら外部成立判定を勝手に実装しない。外部履歴が不明なものを新fundで補わない。
3. **既登録を確認**：外部証跡→同医院元飼主fund→訂正履歴・預りentry→既operationを照合。既登録ならread/履歴へ進み、前金を新しいpayment method名だけで再記録しない。同一額・日時・名前だけを取引identityにしない。外部IDの一意scopeが資料で分からない場合は重複不明として停止する。
4. **一回だけ登録**：未登録と実受領が確定したものに元証拠refを固定し、同一command/operation keyで506受領＋464receive/deposit_allocate＋口座版＋監査＋receiptを同TX保存する目標。受領済fundから預り対応だけを追加する場合、新fundを作らない。source original_source_referenceは固定import evidenceであり、後の金額訂正から消去／変更しない。現金のtendered/changeを非現金へ捏造しない。

- P5 部分充当と取消：前金3,000円のうち確認済み請求へ2,000円充当、未充当1,000円。その請求の取消が成立したら解除2,000円・残3,000円・実返金0。二重取消で残5,000円にしない。実返金が別途確認された1,000円は一度だけ控除する。取消条件／返金許可をこの数値例で決定しない。
- P6 重複／未受領：同じ外部証拠・同key、別key、別職員並行を照合し受領は一度。予約済みだけ／provider処理中／証拠不一致では実受領を作らない。外部実受領済み・院内結果不明では追加決済を求めない。
- P7 競合／失敗：他院／別飼主・失権・古い口座版・元fund不足・既実返金済み・方法停止を操作別に照合。監査／receipt失敗で資金と口座の片側保存なし。既成功同keyは保存結果、unknownは停止。誤記訂正は実移動0で原受領履歴保持。

各ケースの証跡台帳は、case ID／対象文書・実装commit／合成fixture ID／実行有無／clinic・owner・appointment・pet・元記録ref／外部証拠の参照（必要部分のみ、秘密情報除外）／fund・entry・billing・allocation・refund refs／操作keyとintent／期待版と結果版／前後の実受領・有効充当・未払・未充当・実返金／actor・実日時・記録日時／監査ref／C06結果／帳票取引ref／期待結果・実結果・停止理由を対応させる。全列が全ケースで必要な訳ではなく、無料ケースの資金refは「該当なし」、取得不明は「不明」と分け、0やダミーIDへ変換しない。

文書受入は4区分の各入口・元参照・終了条件・未決資料とownerが揃うこと。実装受入は上記対象subsetの一意性／現在認可／原子性／再読／unknown停止を確認すること。医院運用受入は実資料を差し込んだ手順を医院が確認すること。この3段階を独立に記録する。
