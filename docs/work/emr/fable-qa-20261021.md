# Fable Q&A — 契約と実装着手の境界（2026-10-21）

既存正本と採用済み回答を、Fableの実装引継ぎ用に補足する。業務要件・HTTP outcome・認可条件を変更しない。実装PRの修正・レビュー対応・マージは各実装セッションが担当し、この文書追補では行わない。

## 問診の入口、閲覧と再送

pendingを含む入口をconfirmed限定へ狭めず、serverの`current_target.editable`を採用する。これは未知のlifecycleを新たに許可する意味ではない。既存契約どおり現在の認可・lifecycleで判定し、未知状態はfalseとする。

`checked_in / in_consultation / accounting / completed`は飼主からの新規write不可だが、認可済みの閲覧は可能。取消・削除も新規write不可。`no_show`だけを理由に一律readonlyへせず、過去日・未回答だけの新cutoffも追加しない。現在対象の問診、履歴原文、結果照会はそれぞれ正規のscope・行認可に従う。

結果不明時は**同じoperation keyと同じ内容を保持**する。応答断・5xx・`claimed_uncommitted / not_found / result_unavailable`を未実行確定とみなして別keyでcreateしない。`Retry-After`が返された場合は期限まで結果照会・再送を待機し、その後も既存の照会・同key再送規則に従う。無条件・自動の再送許可にはしない。

[予約技術契約](../../design/domains/reservations/technical-spec.md#L753)は413/415/429/500/503で`Retry-After`が存在する場合の尊重を定めている。[OpenAPI](../../../backend/docs/api.yaml)の`RevisitIntakeInternalError`にも、既存429/503と同じ任意headerを記載する。500の新しい必須header・HTTP outcome・成功判定は追加しない。

[#752](https://github.com/MinoruSoga/AnimalEkarte/pull/752)の401について、ログインredirectの存在だけでは即時cache遮断を証明できない。失権・401時のcache無効化と、旧scopeの本文が直ちに表示・再利用されなくなることの実装確認が必要であり、「誤検出としてresolve済み」とは記載しない。この追補では他の実装PRのレビュー指摘を取り込まず、修正・試験・解消判定を行わない。

根拠: [問診DB契約の受付境界](../db-contracts/revisit-intake.md#L93)、[API/UI担当境界](../db-contracts/revisit-intake.md#L163)、[予約技術契約の現在読取・結果照会・HTTP error](../../design/domains/reservations/technical-spec.md#L753)。

## 証明書の適格性、入力と保存

`vaccines.rabies_certificate_eligible`と接種時eligibility snapshotは、EMR-486の選定済み・未実装依存である。`true`だけrabies可、`false / unknown`はnormalのみ。名称・価格・species等から狂犬病適格性を推定しない。過去のunknownを一括falseや現在master値で黙って上書きしない。

`CertificateInputs`の番号3欄（`certificate_number / injection_tag_number / dog_registration_tag_number`）、体格（`body_size`）、特徴（`distinguishing_features`）、注射量（`injection_amount_text`）、料金4欄（`registration_fee / injection_fee / tag_fee / total`）は、rabiesの発行前スタッフ入力として全てoptional/nullable。必須化、番号採番、医学的既定・換算、会計逆同期、自動合計を追加しない。`total`は独立入力で、nullと明示0を区別する。

normalは全10欄null-only。省略またはnullだけを許可し、空文字・空白・0を含む非null値は422 validation。`inputs={}`は許可し、保存時は全10欄を明示nullへ展開する。通常の飼主・ペット・接種・医院情報は既存snapshotの`source / owner / pet / clinic`から取得し、CertificateInputsを基本情報編集APIにしない。

発行後snapshotは不変。接種訂正後は新発行版とし、旧版の履歴を保持して有効出力を拒否する。通常の縦横は同editionの固定内容を使う。C06の短いhash commitment・canonical bytes再検証・同scope/key照会の契約を維持する。

## 帳票の「種類」、日付と描画主体

[3様式の既存見本対応](../../spec/domains/vaccinations/lifecycle.md#L116)に基づき、同じ「種類」の見出しを一律に同じfieldへ結び付けない。

| 見本の位置 | 採用するsnapshot field／表示 |
| --- | --- |
| 狂犬病の犬情報「種類」 | `pet.breed` |
| 通常の患者情報欄 | `pet.species` |
| 通常の接種日直下「種類」 | `source.vaccine_name` |
| 通常の日付 | 見本どおり和暦の年月日表記 |
| 狂犬病の生年月日 | 見本どおり和暦＋年齢 |
| 狂犬病の接種日 | 見本どおり西暦の年月日表記 |

これは帳票上の表示規則であり、APIのdate型`YYYY-MM-DD`を変更する意味ではない。未取得値をサンプル値で補わず、保存snapshotから表示する。

狂犬病予防注射済証は、2026-10-21本人選定（方向「横」、サイズ「A4」）により **A4横（幅297mm×高さ210mm）** とする。[帳票正本](../../spec/domains/vaccinations/lifecycle.md#requirement-fr-vaccinations-certificate-editions)へ同期済みであり、旧見本から推定した寸法ではない。APIの `layout=rabies` は維持し、normalの `landscape` へ変更しない。狂犬病の先行選定を通常へ自動適用しないとしていた当時の記載は、同日の別途本人確認により更新する。通常portraitはA4縦（幅210mm×高さ297mm）、通常landscapeはA4横（幅297mm×高さ210mm）として別途承認済み。狂犬病のA4横という先行決定と、この通常2様式の追加確認を区別する。3様式のPDFページ寸法・向きは[用紙寸法の受入条件](../../spec/domains/vaccinations/lifecycle.md#requirement-fr-vaccinations-certificate-editions)で確認し、見本セル配置との照合で代替しない。検証は未実施（NOT_RUN）。余白・縮尺・複数面付け等の追加仕様は定めない。

3様式とも**EMR-487のserver rendererを唯一の描画主体**とし、FEで帳票を二重描画しない。FEの確認previewと印刷は同じserver renderer由来のPDFを使い、発行前previewに業務writeを追加しない。renderer/template/font/assetの版固定と実描画受入は実装ownerの後続作業とする。

## この追補の検証境界

変更はHTTP 500の任意Retry-After記載漏れと本Q&A、既存証明書契約からの参照のみ。試験・Docker・隔離実行環境・DB・runtime・model・生成clientは**NOT_RUN／変更なし**。実装の成立や401/cache問題の解消を証明するものではない。静的なYAML・参照・差分のみ確認し、mergeはrootが担当する。
