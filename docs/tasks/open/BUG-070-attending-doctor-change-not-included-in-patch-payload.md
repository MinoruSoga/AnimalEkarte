# BUG-070: カルテ担当医変更が PATCH payload に含まれず保存されない

## 種類
バグ（フロントエンド — PATCH payload 構築ミス）

## 重要度
高

## 発見日
2026-03-28

## 再現手順

1. カルテ詳細画面（`/medical-records/:id`）を開く
2. 担当医フィールドのプルダウンで別のスタッフを選択する
3. 「保存」ボタンをクリックして PATCH リクエストを送信する
4. ページをリロードして担当医を確認する

## 期待動作

- 変更した担当医（`staff_id`）が PATCH リクエストの payload に含まれる
- DB に保存され、リロード後も変更後の担当医が表示される

## 実際の動作

- UI 上は選択した担当医名に更新される（ローカル state のみ更新）
- しかし保存時の PATCH payload に `staff_id` が含まれない
- DB は更新されず、リロードすると元の担当医に戻る

## 原因

カルテ編集フォームの保存ロジック（PATCH payload 構築部分）で、
`staff_id`（担当医）フィールドが payload に含まれていない。
UI の state 更新のみ行われており、API への送信が漏れている。

## 影響範囲

- カルテ詳細画面の担当医変更フロー全体
- 担当医の変更が一切保存できない状態

## 修正方針

カルテ PATCH リクエストを構築する箇所で `staff_id` を payload に追加する。
`buildMedicalRecordUpdateFields()` 相当の関数、または
`useMedicalRecordForm` 等の保存ロジックを修正する。

## 優先度
高（変更が保存されない = データ消失）
