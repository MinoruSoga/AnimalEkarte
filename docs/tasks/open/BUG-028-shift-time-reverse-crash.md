# BUG-028: シフト追加で終了時刻が開始時刻より前の場合にDBへの不正保存＋ページクラッシュ

## 種類
バグ（フロントエンド＋バックエンド — 時刻バリデーション未実装）

## 重要度
高

## 発見日
2026-03-28

## 再現手順
1. `/shifts` でスタッフ・日付セルの「+」をクリックしてシフト追加ダイアログを開く
2. 開始時刻に `18:00` を入力
3. 終了時刻に `09:00` を入力（開始時刻より前）
4. 「保存」ボタンをクリック

## 期待動作
- 「終了時刻は開始時刻より後に設定してください」等のバリデーションエラーが表示される
- POST リクエストが送信されない（フロントエンドで止まる）
- もしくはバックエンドで 400 Bad Request を返す

## 実際の動作
1. フロントエンドバリデーションなし → POST リクエストが送信される
2. バックエンドもバリデーションなし → HTTP 201 で保存成功（`start_time=18:00, end_time=09:00` の不正データがDBに保存）
3. 保存直後にReactコンポーネントがクラッシュ → 「アプリケーションで予期しないエラーが発生しました」エラー画面表示
4. ページリロード後も「シフトデータの取得に失敗しました」エラーが表示され続ける（不正DBデータが残るため）
5. DBから手動で該当レコードを削除するまでシフト管理ページが機能不全

## 影響
- シフトページが完全に機能停止する可能性（不正データが残るとリロードしても回復不可）
- DBに不正な時刻データ（end_time < start_time）が蓄積される可能性
- ユーザーが操作方法を誤ると、シフト管理機能全体が使用不能になる

## 修正方針
### フロントエンド
- `features/shifts/hooks/` または `features/shifts/routes/` でフォーム送信前に時刻バリデーションを追加
- 条件: `end_time <= start_time` の場合はエラーメッセージを表示しPOSTを中止
- エラーメッセージ例: 「終了時刻は開始時刻より後に設定してください」
- `FormFieldError` コンポーネントまたはトーストで表示

### バックエンド
- `backend/internal/service/` または `handler/` の shift 作成・更新処理に時刻バリデーションを追加
- `end_time <= start_time` の場合は `400 Bad Request` を返す
- ただし「休日」「有休」等の時刻不要なシフト種別は除外
