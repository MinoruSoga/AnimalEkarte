# BUG-024: 予防接種登録フォームの必須バリデーションが機能しない

## 種類
バグ（フロントエンドバリデーション未実装 + バックエンドエラー文字列タイポ）

## 重要度
高

## 発見日
2026-03-28

## 再現手順
1. `/vaccinations/select-pet` でペットを選択して新規登録フォームへ遷移
2. ワクチン種別・接種日を未入力のまま「保存」ボタンをクリック

## 期待動作
- フロントエンド: 「ワクチン種別を選択してください」「接種日を入力してください」等のバリデーションエラーが各フィールド下に表示され、POST 送信を防ぐ
- バックエンド: エラーレスポンス `{"error":"vaccine_id is required"}` を返す（正しいフィールド名）

## 実際の動作
- フロントエンド: バリデーションエラーが一切表示されない
- POST リクエストが送信される（`vaccine_id: 0`, `date: "2026-03-27T17:13:55.372Z"` 等）
- バックエンドが HTTP 400 を返すが、エラーメッセージが画面に表示されない
- バックエンドのエラー文字列にタイポ: `"vaccine_i_d is required"` (`vaccine_id` が正しい)

## リクエスト例
```json
{"medical_record_id":null,"pet_id":14,"vaccine_id":0,"date":"2026-03-27T17:13:55.372Z","next_date":null}
```

## レスポンス例
```json
{"error":"vaccine_i_d is required"}
```

## 影響
- ユーザーが未入力のまま保存しても何も起きないように見え、データが保存されたと誤認する可能性
- バックエンドのタイポにより将来的なエラーマッピングが困難

## 修正方針
### フロントエンド
- `features/vaccinations/hooks/` の保存処理前にバリデーション追加
- `vaccine_id` が未選択（0 または null）なら「ワクチン種別を選択してください」を表示
- `date` が未入力なら「接種日を入力してください」を表示
- 400 レスポンスのエラーメッセージをトースト等で表示する

### バックエンド
- `backend/internal/service/` または `handler/` の `vaccine_i_d` タイポを `vaccine_id` に修正
