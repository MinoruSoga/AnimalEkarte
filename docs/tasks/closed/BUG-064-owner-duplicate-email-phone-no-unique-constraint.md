# BUG-064: 飼主の重複メール・電話番号登録が許可される（UNIQUE制約なし・重複チェックUI未実装）

## 種類
バグ（バックエンドDB制約欠落 + フロントエンドバリデーション未実装）

## 重要度
高

## 発見日
2026-03-29

## 再現手順

1. 飼主登録フォームで任意のメールアドレス（例: `test@example.com`）を入力して登録
2. 同一メールアドレスで再度飼主登録を試みる
3. HTTP 201 で登録成功する（重複エラーなし）

## 期待動作

- 同一メールアドレスでの登録時は HTTP 409 Conflict を返す
- 同一電話番号での登録時はソフト警告（確認ダイアログ）を表示する
- 編集（PATCH）時にも既存アドレスとの衝突をチェックする

## 実際の動作

- `POST /api/v1/owners` で同一 email を送信しても HTTP 201 で重複登録成功
- `PATCH /api/v1/owners/:id` でも重複チェックなし
- 重複候補の UI 表示なし・そのまま登録される

## 原因

`owners` テーブルに `email` カラムの UNIQUE 制約がない。
バックエンドサービス層でも重複チェックロジックが実装されていない。

## 影響範囲

- 飼主登録フォーム（`/owners/new`）
- 飼主編集フォーム（`/owners/:id/edit`）
- 同一飼主の重複データが際限なく生成される

## 修正方針

1. `owners` テーブルに `email` カラムの UNIQUE 制約追加（`clinic_id` + `email`、論理削除考慮）
2. `owner_service.go` の `Create`・`Update` で重複チェックを追加し `ErrConflict` を返す
3. フロントエンドで 409 レスポンス時に「このメールアドレスはすでに登録されています」エラーを表示

## 優先度
高（重複データの蓄積でデータ品質が劣化する）

| イシュー | 領域 | 内容 |
