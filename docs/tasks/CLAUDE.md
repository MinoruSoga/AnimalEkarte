# Tasks

## 概要

このディレクトリのタスクドキュメントは `/task-create` コマンド（`.claude/skills/task-create/`）により自動生成される。

## 生成フロー

```
タスク依頼（ユーザー）
    ↓ /task-create
docs/tasks/open/TASK-XXX-*.md     ← ここ（全体像・依存関係・影響範囲）
    ↓ 領域別に分割
backend/issues/open/BE-XXX-*.md   ← バックエンドイシュー
frontend/issues/open/FE-XXX-*.md  ← フロントエンドイシュー
```

## ディレクトリ構造

```
docs/tasks/
├── CLAUDE.md    ← このファイル
├── open/        ← 未完了タスク（カテゴリ別サブディレクトリ）
│   ├── crash/          クラッシュ・500エラー系バグ
│   ├── medical-record/ カルテ・診療系バグ
│   ├── reservation/    予約・シフト系バグ
│   ├── validation/     入力バリデーション系バグ
│   ├── security/       セキュリティ系バグ
│   └── ux/             UX・ナビゲーション系バグ
└── closed/      ← 完了タスク（フラット）
```

## 採番ルール

- 形式: `BUG-XXX_kebab-case-title.md`（XXX は3桁ゼロ埋め）
- 番号: `open/` 全サブディレクトリ と `closed/` の両方から最大番号 + 1 で採番
- 新規チケットは適切なカテゴリのサブディレクトリに配置する

## タスクのライフサイクル

1. `/task-create` で `open/` に生成
2. 配下の全 BE/FE イシューが closed になったら `closed/` に移動

## 役割

タスクドキュメントは **親チケット** に相当する。1つのタスクから複数の BE/FE イシューが派生する。

- タスク = 「何をやるか」の全体像
- イシュー = 「どう実装するか」のAI実行可能な粒度

## イシュー品質ガイドライン

### 必須要件（これがないイシューは差し戻し）

| 要件 | 基準 |
|------|------|
| **再現可能** | 具体的なアカウント・URL・手順で誰でも再現できること |
| **ファイルパス:行番号** | 問題箇所・修正対象は必ず `ファイルパス:行番号` 形式で特定すること |
| **現状コード** | 問題のあるコードブロックを提示すること（「〜が問題」だけでは不可） |
| **修正コード** | コピペ可能な修正例を提示すること（「〜すべき」だけでは不可） |
| **影響範囲の網羅** | 関連する全ファイル・全エンドポイントをテーブルで列挙すること |
| **規約への紐づけ** | 違反しているプロジェクト規約（`.claude/CLAUDE.md`, `.claude/rules/*.md`）を引用すること |
| **参照実装** | 同一プロジェクト内で正しく実装されている箇所を提示すること |

### 禁止事項

| 禁止 | 理由 |
|------|------|
| 「〜かもしれない」「〜の可能性がある」 | 曖昧。調査して断定するか「未調査」と書く |
| ファイルパスなしの修正指示 | 実行不能。必ず `ファイルパス:行番号` を付ける |
| 「リファクタリングが必要」で終わる修正方針 | 抽象的。具体的なコード変更を示す |
| 影響範囲「他にもあるかも」 | 調査を完了させてから起票する。漏れは追記で対応 |
| 規約参照なし | 「なぜそう修正すべきか」の根拠がない |

### 優先度の判断基準

| 優先度 | 基準 |
|--------|------|
| **Critical** | データ改ざん・削除・認可バイパスが可能。本番環境で即時対応が必要 |
| **High** | 情報漏洩・権限昇格のリスク。次回リリースまでに対応が必要 |
| **Medium** | UX 上の問題・不整合。セキュリティ実害は軽微だが修正すべき |
| **Low** | コードの一貫性・可読性の改善。余裕がある時に対応 |

### 参照すべきプロジェクト規約一覧

イシュー起票時に、以下の規約のうち該当するものを必ず引用すること:

| 規約ファイル | 主な対象 |
|-------------|---------|
| `.claude/CLAUDE.md` | アーキテクチャ全般・エラー処理統一・フロントエンドベストプラクティス |
| `.claude/rules/security.md` | 認証・認可・入力検証・多層防御 |
| `.claude/rules/api.md` | REST API 設計・HTTP ステータス・セキュリティ |
| `.claude/rules/go-language.md` | Context 伝播・エラーハンドリング・インターフェース設計 |
| `.claude/rules/typescript-react.md` | React 19 パターン・型安全性・命名規則・パフォーマンス |
| `.claude/rules/error-handling.md` | Sentinel エラー・HTTP Status マッピング・フロントエンドエラー |
| `.claude/rules/database-design.md` | マルチテナント・インデックス・論理削除・N+1 対策 |
| `.claude/rules/testing.md` | テスト構造・命名・カバレッジ要件 |
| `.claude/rules/accessibility-rules.md` | WCAG 2.1 AA・セマンティック HTML・キーボード操作 |
| `.claude/rules/performance-rules.md` | API レスポンス目標・React パフォーマンス・バンドルサイズ |
