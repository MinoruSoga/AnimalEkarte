# フロントエンド・アーキテクチャ 仕様書

本ドキュメントは、Animal Ekarte のフロントエンド実装における設計思想、ディレクトリ構成、状態管理、およびバリデーション戦略を定義します。

## 1. ディレクトリ構成 (Feature-based Architecture)

システムは機能単位（Feature）で凝集度を高める「Feature-based Architecture」を採用しています。各機能ディレクトリは独立したモジュールとして振る舞い、他機能への直接的な依存を最小限に抑えます。

```
frontend/src/
├── app/                  # アプリケーション全体のエントリーポイント、ルーティング、プロバイダ定義
├── components/           # 全体共有コンポーネント (UIライブラリ, 共通レイアウト等)
├── config/               # 環境変数、定数、パス定義
├── features/             # 業務機能ごとのモジュール群 (auth, dashboard, medical-records 等)
│   └── [feature-name]/   # 各機能ディレクトリ
│       ├── api/          # 該当機能固有の API通信ロジック (TanStack Query フック等)
│       ├── components/   # 該当機能固有の UIコンポーネント
│       ├── hooks/        # 該当機能固有の カスタムフック (ビジネスロジック)
│       ├── routes/       # 該当機能の ページコンポーネント
│       ├── types/        # 該当機能の 型定義
│       └── index.ts      # 外部へ公開するインターフェース (Barrel export)
├── hooks/                # 全体共有のカスタムフック
├── lib/                  # サードパーティライブラリの設定 (axios, zod, queryClient)
└── types/                # グローバルな型定義
```

## 2. 状態管理戦略 (State Management)

本システムでは、状態の性質に応じて適切な管理手法を使い分けます。Redux などの単一の巨大なストアは使用せず、局所性と責務の分離を重視します。

### a) サーバー状態 (Server State)
- **技術**: `TanStack Query (React Query)`
- **用途**: APIからのデータ取得、キャッシュ管理、ポーリング（ダッシュボード等）、ミューテーション状態の追跡。
- **特徴**: データの鮮度管理 (`staleTime`) を機能ごとに最適化し、不必要な再取得を防ぎます。

### b) クライアント・ローカル状態 (Client Local State)
- **技術**: `useState`, `useReducer`, 固有のカスタムフック (`useDashboardKanban` 等)
- **用途**: モーダルの開閉、アコーディオンの展開状態、入力途中のフォームデータ。
- **特徴**: 状態を必要とするコンポーネントの「最も近い共通の親」に状態を持たせます。

### c) グローバル・アプリケーション状態 (Global State)
- **技術**: `React Context`
- **用途**: 認証情報 (`AuthContext`)。
- **特徴**: ユーザープロファイルや権限など、システム全体で頻繁に参照される静的な情報にのみ Context を使用します。

## 3. バリデーションとフォーム管理 (Validation & Forms)

- **技術**: `React Hook Form` + `Zod`
- **方針**: 
  - 複雑なフォーム（飼主登録、設定画面等）では `React Hook Form` を使用し、レンダリングパフォーマンスを最適化します。
  - スキーマ定義ベースのバリデーションに `Zod` を使用。日本語のカスタムエラーメッセージ (`frontend/src/lib/zod.ts`) を共通化しています。
- **UIとの結合**: バリデーションエラー発生時は、`aria-invalid` と `aria-describedby` を用いて `FormFieldError` と接続し、アクセシビリティを確保した警告を行います。

## 4. エラーハンドリング (Error Handling)

- **APIエラー**: `axios` インターセプターおよび `frontend/src/lib/handle-api-error.ts` により、HTTPステータスに応じた一元的なエラーハンドリングを実施します。
  - `400`: 入力エラー。トーストまたはフォームエラーとして表示。
  - `401`: 認証切れ。自動的に `/login` へリダイレクト。
  - `403`: 権限不足。専用のエラー画面またはトースト表示。
  - `500`: サーバーエラー。
- **レンダリングエラー**: `RouteErrorBoundary` を用いて、特定ページのクラッシュがシステム全体に波及しないように遮断します。

## 5. 認証・認可 (Auth & RBAC)

- **保護ルート**: `ProtectedRoute` コンポーネントが、認証済みであるかをチェックし、未認証の場合はログインへ弾きます。
- **UIレベルのアクセス制御**: `PermissionGate` コンポーネントを使用し、ユーザーのロール（`system_admin`, `clinic_admin`, `staff` 等）に応じて、ボタンの表示/非表示や操作可否を切り替えます。
