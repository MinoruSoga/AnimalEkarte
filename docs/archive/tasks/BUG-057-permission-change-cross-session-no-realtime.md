# BUG-057: 権限変更が他セッションにリアルタイム反映されない

**作成日**: 2026-03-29
**ステータス**: Open
**優先度**: Low-Medium
**領域**: Backend + Frontend
**関連**: FE-136（同一セッションの即時反映）, BUG-055（JWT 単一トークン）

---

## 背景・問題

`clinic_admin` がスタッフ B の権限グループを変更した場合、スタッフ B が
**ログイン中のセッション**でその変更を即座に受け取る手段がない。

| タイミング | 現在の動作 | 期待する動作 |
|-----------|-----------|------------|
| 権限グループを割当・保存 | スタッフ B のセッション変化なし | スタッフ B のメニュー・ボタンが更新される |
| スタッフ B がページ移動 | 新権限で動作 | （同上） |
| スタッフ B がページリロード | 新権限で動作 | （同上） |
| スタッフ B の JWT が失効・再発行 | 新権限で動作 | （同上） |

---

## 影響範囲

### セキュリティリスク

- スタッフ B の権限を **剥奪** したとき、スタッフ B のセッションでは JWT が有効な間
  アクセス権が残り続ける（JWT 有効期限が 24時間 → BUG-055 により最大 24時間）
- BUG-055 の修正（JWT 15分化）が完了すれば、最大 **15分** のラグに縮小される

### UX 問題

- 権限付与後もスタッフ B にメニューが即座に表示されない
- スタッフ B が「保存しましたよ」と伝えられてからページリロードが必要

---

## 解決方針の選択肢

### 案1: 定期ポーリング（推奨・シンプル）

`/me` を一定間隔で再取得し、権限変更を反映する。

```typescript
// features/auth/hooks/use-auth.tsx
// /me を 5分ごとに再取得
const { data: meData } = useQuery({
  queryKey: ["me"],
  queryFn: fetchMe,
  staleTime: 5 * 60 * 1000,   // 5分
  refetchInterval: 5 * 60 * 1000,  // ← 追加: 5分ごとに再取得
  refetchIntervalInBackground: false,  // タブ非アクティブ時はスキップ
});
```

**メリット**: 実装が単純、既存の React Query 設定を拡張するだけ
**デメリット**: 最大 5分の遅延がある。5分ごとに API リクエストが発生する

### 案2: フォーカス時の再取得

ウィンドウフォーカス時に `/me` を再取得する（React Query のデフォルト動作活用）。

```typescript
const { data: meData } = useQuery({
  queryKey: ["me"],
  queryFn: fetchMe,
  staleTime: 60 * 1000,  // 1分
  refetchOnWindowFocus: true,  // ← ウィンドウフォーカス時に再取得
});
```

**メリット**: UX 的に自然（タブを切り替えて戻ったタイミングで更新）
**デメリット**: 権限が剥奪されてもタブを切り替えるまで反映されない

### 案3: Server-Sent Events（SSE）または WebSocket（高コスト）

権限変更イベントをサーバーからプッシュ通知する。

**メリット**: リアルタイム反映
**デメリット**: 実装コストが高い（インフラ変更・Go の goroutine 管理等）。
動物病院向けシステムでは過剰な可能性あり

---

## 推奨実装

**案1（定期ポーリング 5分）+ 案2（フォーカス時再取得）の組み合わせ**が現実的。

BUG-055 の修正（JWT 15分化）が完了すれば、最悪ケースでも
「JWT 有効期限 15分 + ポーリング遅延 5分 = 最大 20分」のラグになる。
動物病院の業務運用上、このラグは許容範囲と判断する。

---

## 実装スコープ（派生イシュー）

| イシュー | 領域 | 内容 |
|---------|------|------|
| FE-136 | Frontend | 権限グループ割当後に `/me` を再取得して同一セッションの権限キャッシュを即時更新（FE-137 の前提） |
| FE-137 | Frontend | `/me` の `refetchInterval` 追加 + `refetchOnWindowFocus` 有効化（他セッションへの 5分以内反映） |

---

## 完了条件

- [ ] 権限グループ変更後、最大 5分以内にスタッフ B のセッションに変更が反映される
- [ ] タブがフォーカスされたタイミングで権限が更新される
- [ ] ポーリングが認証エラー（401）時に適切に停止する

---

## 依存・関連

- **BUG-055 完了推奨**: JWT を 15分に短縮すると漏洩リスクが大幅に低減するため、
  本バグの影響が「最大 24時間 → 最大 20分」に縮小される。BUG-055 と併せて対応することを推奨する。
- **FE-136**: 同一セッション内（自分自身の権限変更）は FE-136 で先に対応する
