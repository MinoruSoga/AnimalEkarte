# BUG-029: シフト編集ダイアログで既存の開始・終了時刻が表示されず、保存時に時刻がクリアされる

## 種類
バグ（フロントエンド — 編集フォームの初期値未設定）

## 重要度
高

## 発見日
2026-03-28

## 再現手順
1. `/shifts` でスタッフ・日付セルの「+」をクリックし、開始時刻 `09:00`、終了時刻 `18:00` でシフトを保存（全日）
2. 保存後にカレンダーに表示された「全日」バッジをクリックしてシフト編集ダイアログを開く
3. 開始時刻・終了時刻フィールドの表示内容を確認する
4. シフト種別のみ変更（例: 全日 → 午前）し、時刻フィールドは変更せずに「保存」をクリック
5. DBのシフトデータを確認する

## 期待動作
- 編集ダイアログを開いたとき、既存シフトの開始時刻（09:00）と終了時刻（18:00）が各フィールドに表示されている
- 時刻を変更せずに「保存」すると、既存の時刻値が保持される

## 実際の動作
- 編集ダイアログを開いても開始時刻・終了時刻フィールドが空（`--:--`）のまま
- DOM の input[type="time"] の value も空文字列
- 時刻を変更せずに「保存」すると、DBの start_time・end_time が NULL/空になる（時刻データが消失）

## 影響
- シフト種別だけを変更したいケースで、既存の時刻データが消えてしまう
- ユーザーは毎回の編集で時刻を再入力しなければならない
- 時刻が消えたことに気づかない場合、不完全なシフトデータが蓄積される

## 修正方針
### フロントエンド
- `features/shifts/hooks/` または `features/shifts/routes/` の編集ダイアログ初期化処理を修正
- `useShiftEditForm` または類似フックで、既存シフトデータの `start_time` / `end_time` を `useState` 初期値またはフォームの `defaultValue` として設定する
- API から取得した `ShiftEntry.start_time` / `ShiftEntry.end_time` をフォームフィールドにマップする
