# S09: 締め境界（AM/PM/EMG・越日）

> **目的**: 会計が完了時刻に基づき AM/PM/EMG の正しい区分・営業日へ集計され、越日 EMG と締め済み期間の保護が機能することを証明する。
> **所要目安**: 30分（データ準備含む） / **深度**: 深い
> **仕様正本**: [レジ締め業務](../../../spec/cash-register.md) / [レジ締め・履歴](../../../spec/screens/29-closing-aggregation.md) / [締め時間設定](../../../spec/screens/settings/closing-time-settings.md) / [会計精算](../../../spec/screens/11-accounting-detail.md)

## 前提条件

- 環境: ローカル（seed 003_demo）。対象クリニック: 「城東センター病院」（seed 003_demo の設定値: AM 開始 09:00 / AM・PM 境界 13:30 / 平日終了 19:00。平日レンジは AM 09:00:00〜13:29:59・PM 13:30:00〜18:59:59・EMG 19:00:00〜翌 08:59:59）。対象日は平日とする（日曜は終了時刻が異なる）。
- ログイン: システム管理者ロール（レジ締め cash-register-close・締め時間設定 closing-settings の権限は seed 003_demo の権限グループに定義がないため）。
- **データ準備（必須）**: 区分帰属は会計の完了時刻（`completed_at`）で判定される。同一営業日に完了時刻が 10:00 / 13:30:00 ちょうど / 14:00 / 20:00 / 翌日 02:00 の会計計 5 件を用意する。UI からは精算実行時刻がそのまま完了時刻になるため、実行時刻と異なる完了時刻はローカル DB のテストデータ更新で準備する（システム時計の変更は行わない）。

## 確認観点

- **帰属の判定軸**: 区分・営業日の帰属は完了時刻（`completed_at`）と締め時間設定の照合で決まる（仕様正本 締め時間設定 §主要な機能）。会計の予定日（scheduled_date）ではない。AM/PM/EMG は連続・非重複で 24 時間を被覆する。
- **越日 EMG（#215）**: 深夜 0:00〜AM 開始の会計は前日の EMG に帰属する（`backend/internal/billing/cash_register_service.go` の `resolvePeriodRange`。集計は completed_at の終端排他レンジ）。境界設定を後から変更しても締め済みレコードは再計算されない（仕様正本 29 §1）。
- **締め済み警告の判定粒度**: FE の締め済み判定は会計の予定日単位で、その日のいずれかの区分が締め済みなら警告される（区分単位ではない）。#8 の観察時に留意する。
- **不変性**: 締めレコードに更新・削除 API は存在せず append-only。不変性は `(clinic_id, close_date, period)` の UNIQUE 制約（二重締め防止）で担保される（仕様正本 §5）。
- **#10 のフィルタ粒度**: 締め履歴の区分フィルタはクライアント側フィルタで、現在ページ内の行だけに作用する（`frontend/src/features/cash-register/routes/CashRegisterHistoryPage.tsx`）。ページを跨ぐ絞り込み漏れを不具合と誤認しない。
- **seed の既存締めレコード**: seed 003_demo には八王子病院の締め記録（2026-05-21 AM/PM 等）が含まれる。城東センター病院での検証には影響しない（clinic_id 隔離の副次確認になる）。
- **実時間での帰属確認**: 「精算した瞬間の実時刻で正しい区分に入るか」は実行時刻に依存するため本シナリオの対象外。実行時間帯が偶然合致する場合のみ追加確認する【要実測・データ準備要検討】。

## 異常系

- **二重締め**: #7 と同一日・同一区分でもう一度締めを実行 → 拒否される（UNIQUE 制約）。【要実測: エラー表示の表現】
- **締め済み期間の編集強行**: #8 の状態で修正理由を入力せずに保存 → 保存できない（修正理由必須、仕様正本 11 §2.1）。理由を入力して保存した場合は監査ログに記録される（#115）。
