# 項目単位検証プロトコル (Field-Level Protocol)

> **目的**: 受入（V シリーズ）で**すべての入力項目**に同じ粒度のチェックを適用する。  
> **読者**: 受入実施者（AI / 人）。  
> **正本の位置**: 本ファイルは手順定義。項目一覧は [FORM-FIELD-INVENTORY.md](FORM-FIELD-INVENTORY.md)。フォーム手順は V01〜V05。  
> **最新更新**: 2026-08-14

---

## 1. 適用ルール

1. 対象フォームの inventory 行に列挙された**すべての入力項目**に、適用可能な F チェックを実施する。
2. 既存の **C1〜C3** はフォーム入口のまとめであり、**F を省略する理由にしない**。C1-1 が「必須の代表 1 欄」でも、他の必須欄は **F1** で個別に実施する。
3. 結果はシナリオ md に書かない。gitignore の `reports/uat-*/` results に `formId.fieldKey.Fx` 単位で残す。
4. 仕様に期待がない項目は 【要実測】として観測し、正しければ inventory / V シナリオの期待へ昇格する。
5. UI に存在しない・閲覧専用のみの項目は **N/A（理由: read-only / system）** とし、PASS に水増ししない。

---

## 2. F チェック定義

各項目について、型に応じて下表を適用する。

| ID | 名称 | 操作 | 期待 | 適用対象 |
|:--|:--|:--|:--|:--|
| **F0** | 存在・到達 | フォームを開き当該コントロールを特定 | ラベルまたは accessible name で操作可能。隠れ必須がない | 全項目 |
| **F1** | 必須空 | 必須項目を空（または未選択）のまま保存 | 保存されない。フィールドエラーまたは同等の明示フィードバック（無音失敗禁止） | `required=yes` |
| **F2** | 形式違反 | 型に合わない値を 1 件入力して保存 | 拒否。保存されない | string(email/phone/postal/url)、number、date、enum 等 |
| **F3** | 境界 | min-1 / min / max / max+1（または字数境界） | 境界内受理・境界外拒否 | min/max または maxLength がある項目 |
| **F4** | 有効値永続 | 有効な代表値を入れて保存 → 一覧/詳細 → F5 再読込 → 再オープン | 同じ値が永続・初期表示 | 入力可能な全項目（F1 で空が正しい任意項目は「空の永続」も 1 回） |
| **F5** | 任意の空クリア | 値あり → 空にして保存（nullable の場合） | null/空が永続。省略 PATCH で消えない契約がある場合はその仕様どおり | `required=no` かつクリア可 |
| **F6** | 無効状態 | disabled / 権限不足 / ロック後に編集を試みる | 変更不可、または拒否メッセージ | 条件付き disabled がある項目 |

### 2.1 型別の F2/F3 標準入力例

| 型 | F2 例 | F3 例 |
|:--|:--|:--|
| email | `abc` | — |
| phone | `abc`（形式検証がある場合） | — |
| postal | `12-3456` | — |
| number / money | `abc` または小数禁止時の `1.5` | -1, 0, max, max+1 |
| percent 0–100 | — | -1, 0, 100, 101 |
| date | 不正文字列 | 未来日（仕様で禁止の場合） |
| text max N | — | N 文字受理、N+1 拒否 |
| enum / select | 不正 value を API 直（UI 不能なら N/A） | — |
| boolean / toggle | — | ON 保存・OFF 保存の F4 各 1 |
| file | 非対応 MIME | 上限超サイズ |
| password | 短すぎ・英字のみ（ポリシー依存） | min length 境界 |

### 2.2 一括効率化（品質を落とさない範囲）

- **同一 validate 関数を共有するマスタ SidePanel 群**: F1 は各必須項目ごと。F2/F3 は型が同じ項目を inventory で「型代表」に指定し、代表 1 項目で実施 + 他は F0+F4 のみ、としてよい。**必須の F1 と有効値 F4 は省略不可**。
- **動的フィールド**（健診/検査項目定義）: マスタで定義したフィールド定義ごとに F0・F1（必須定義時）・F4 を実施。
- **行型グリッド**（治療明細・支払 split）: 行テンプレートの各セルを 1 項目として F を適用。行追加後に実施。

## 3. 記録フォーマット（results）

推奨キー:

```text
{scenarioId}.{formId}.{fieldKey}.{checkId}
例: V03.owner-create-edit.phone.F2
```

| status | 意味 |
|:--|:--|
| PASS | 期待どおり |
| FAIL | 製品欠陥 → `todo.md` 受入バグ |
| PARTIAL | 観測不十分 |
| BLOCKED | 環境・権限・fixture 不足 |
| N/A | 適用外（理由必須） |

レポート集計例（FINAL.md）:

```markdown
| フォーム | 項目数 | F PASS | F FAIL | F N/A | C1-C3 |
| owner-create-edit | 14 | 42 | 0 | 6 | PASS |
```

---

## 4. V シナリオとの関係

```text
Vxx.md          … フォーム単位の手順・業務固有チェック・C1〜C3 の入口
FORM-FIELD-INVENTORY.md … 全フォームの項目一覧（カバー範囲）
FIELD-LEVEL-PROTOCOL.md … 各項目への F0〜F6（本ファイル）
```

実施時は **inventory の項目行を左から右へ**進め、Vxx の固有手順（薬量ゲート、締め取消不可等）を追加で実施する。

---

## 5. 完了判定

ある V ファイル（またはスコープ指定フォーム集合）が受入完了となる条件:

1. inventory 上の対象フォームがすべて実施対象に含まれている  
2. 各フォームの**全項目**について、適用 F が PASS または理由付き N/A  
3. 当該フォームの C1〜C3（V 文書）が PASS または理由付き BLOCKED  
4. FAIL は `todo.md` に起票済み  
5. シナリオ md は未編集
