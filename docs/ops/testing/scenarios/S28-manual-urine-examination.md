# S28: 手動尿検査 — 手入力項目・文字列保持・機器結果との非混在

> **目的**: 尿検査を目視・試験紙で行う医院向けに、検査フォームで手入力項目を追加・保存でき、定性値（「±」「2+」等）や未判定が文字列のまま保持され、機器測定結果と混同・上書きされないことを納品前に証明する。
> **所要目安**: 20分 / **深度**: 中
> **仕様正本**: [screens/13-examinations-form.md §1.2](../../../spec/screens/13-examinations-form.md)。関連 tracker: `SLACK-MANUAL-URINE`（M4 カルテ検査タブ表示・医院承認の項目/凡例/単位/基準は別ゲート）。

## 前提条件

- ローカルの使い捨て clinic、または承認済みの専用 UAT tenant。
- 尿検査の手入力項目（定性項目・単位・基準値）を fixture で用意する。**各院の実際の項目・定性表現・単位・基準値は医院が承認した期待表が正本**。臨床的意味は推定しない。
- actor は examinations の作成・編集権限を持つ attached account。
- 機器連携（lab import）がある環境では、機器結果と手入力の両方を持つ fixture を用意する。
- 依存シナリオ: S02（異常値ハイライト・ロック）。機器受信の受入は lab-device lane（BRT-94〜100）で別ゲート。

## 手順と期待結果

| # | 操作 | 期待結果 |
|:--|:--|:--|
| 1 | 検査フォームで手入力項目を追加する | `addManualItem` で手動行（`manual-N` キー）が追加され、項目名・値・単位・正常値・基準値を入力できる |
| 2 | 定性値（「±」「2+」「陽性」等）を入力して保存 → 再読込 | 文字列がそのまま保持される。数値変換で「±」が消えたり「0」に化けたりしない（文字列保持） |
| 3 | 判定が付かない項目（未判定/「—」相当）を入力して保存 → 再読込 | 未判定の状態が保持され、勝手に「正常」や「0」に補完されない |
| 4 | 手入力項目と機器測定項目が混在する検査で、手入力値を更新して保存する | 機器由来の値が手入力で上書き・消去されない。origin（手動/機器）が混同されない（lab import の非上書き） |
| 5 | カルテの検査タブ（M4）で手入力の尿検査を表示する | 手入力の項目名・値・単位がカルテ表示へ正しく出る。患者/記録切替で別記録の値が残らない |
| 6 | 手入力項目を削除する | `removeItem` でその行だけが消え、他項目や機器結果に影響しない |

## 確認観点

- 手入力項目は `use-examination-form-items` の `addManualItem`（`manual-N` キー）で追加し、`setItemName`/`setInspectionValue`/`removeItem` で編集する。`ExamItemsTable` の name/inspectionValue/unit/normalValue/referenceValue 列を使う。
- 「±」「2+」等の定性値は文字列として往復することが核心。数値化で失われるのは FAIL。
- 機器結果との非上書きは `lab_import_examination_service`（backend）の合成回帰で確認済みだが、本シナリオは実 DB 往復・カルテ表示での受入。混同・上書きがあれば FAIL。
- origin（手動/機器）表示の採否は臨床 PO 決定ゲート。FE 変換で `job_id` が落ちる範囲を明示したうえで、表示するかを PO と決める。本シナリオでは混同しないこと自体を確認し、表示方式の裁定は別ゲートに残す。
- M4（カルテ検査タブ）は前単位で未検証。手入力値が pivot/一覧へ出ることを別ケースで確認する（手順 5）。
- 未承認の機器仕様・接続情報がない機器連携は BLOCKED とし、実装済み受信コードだけで連携済みと回答しない。

## 実装突合

- 変更サマリ:
  - `use-examination-form-items` の `addManualItem`（`manual-N`）・`setItemName`・`setInspectionValue`・`removeItem` と `ExamItemsTable` の列構成を現行コードと突合
  - `SLACK-MANUAL-URINE` の「文字列保持・未判定・手動/機器非上書き・M4 カルテ表示・医院承認項目」を手順 1–6 に対応づけ
  - origin 表示の PO 決定・機器受信の別ゲートを前提条件に明記
