# 検査機器ブラウザ直接受信 UAT

## 対象と判定

対象はNX600/AU10Vのみ。PU-4010/IDEXXは選択しない。各項目を`PASS` / `FAIL` / `BLOCKED` / `未実施`で記録し、実機未確認を`PASS`にしない。この文書の更新や合成テストは実機UATの証拠ではない。

## 前提

- HTTPSのChromeデスクトップ版で、指定医院にログインし、検査取込のcreate権限がある。
- NX600/AU10V専用USBシリアル変換器のみ接続する。PU-4010、IDEXX、他のシリアル機器は外す。
- `/lab-device`を前面で開き、「接続する」から各ポートを選ぶ。受信中にページを閉じない。
- ブラウザ受信はページを開いている間だけ。未送信データはメモリ内のみで、停止・ページ終了・clinic切替・権限喪失時に失われる可能性がある。失敗時は機器側で再送する。

## 確認項目

| No. | 操作 | 期待結果 | 判定 | 備考 |
|---:|---|---|---|---|
| 1 | `/lab-device`を開き、接続する | HTTPS Chromeでポート選択が開く。NX600/AU10V用を選ぶと9600 8N1で受信待ちになる | 未実施 | |
| 2 | 同じVID/PIDの変換器を2台接続し、両方を選ぶ | 2ポートが各1回だけopenし、それぞれの生バイトを独立して受け付ける。機器判定はbackend decoderが行う | 未実施 | |
| 3 | NX600から検査結果を1件送信 | 2秒アイドル区切りで1フレームを送り、画面に結果または未紐付けとして表示する | 未実施 | |
| 4 | AU10Vから検査結果を1件送信 | NX600と混ざらず、画面の値・単位・フラグが機器表示と一致する | 未実施 | |
| 5 | ペットを選ばずに送信し、待機患者を選んで再送 | 最初は未紐付けに残り、後続は選択した患者だけに紐付く | 未実施 | |
| 6 | 同じ結果を機器から再送 | 重複して別結果を作らず、duplicateとして扱われる | 未実施 | |
| 7 | USBを1本抜き、再接続する | 切断が表示され、選択し直すと受信を再開できる | 未実施 | |
| 8 | 認証切れまたは権限を失わせてから再試行する | 401/403で自動送信が停止し、ログイン/権限確認後の明示再試行だけで同じ医院scopeを再開する | 未実施 | |
| 9 | 受信中に別医院へ切替、create権限を失う、または画面を離れる | 旧医院のreader/port/queueが停止し、古いフレームが新医院へ送られない | 未実施 | |
| 10 | 2つ目のタブから同時接続する | origin-wide lockを取得できず、2つ目は安全に停止する | 未実施 | |

同型変換器のVID/PID一致は機器同一性の証拠ではない。2台の受信分離を確認しても、NX600/AU10Vの区別はdecoder結果と実機表示で別々に確認する。

## 返却してよい情報

- 実施日時、判定、操作番号、固定エラーメッセージ、表示件数
- 生電文、USBポート名、患者名、飼主名、カルテ番号は送らない

## BLOCKED / FAIL

- HTTPS Chrome、権限、専用変換器が用意できない場合は`BLOCKED`と理由を記録する。
- `FAIL`時は追加送信を止め、機器からの再送可否を確認する。画面終了・停止・clinic/権限変更では未送信分を失う可能性があるため、保存済みと推測しない。
