# 検査機器ローカル受信 クライアント実機確認票

## 対象と判定

対象はNX600とAU10Vのみ。PU-4010とIDEXXは送信せず、別の実機検証が完了するまで対象外とする。

各項目を`PASS` / `FAIL` / `BLOCKED` / `未実施`のいずれかで記録する。確認できていない項目を推測で`PASS`にしない。

## 返却してよい情報

- 実施日時
- 下表の判定と備考
- 「ローカル受信機」の状態表示と件数
- エラーメッセージの文面

生電文、USBポート名、患者名、飼主名、カルテ番号、画面全体のスクリーンショットはメールやチャットへ送らない。

## 前提

- NX600/AU10V専用のUSBシリアル変換器2本を接続する。
- PU-4010、IDEXX、その他のUSBシリアル機器は外す。
- 指定された医院でログインし、検査取込権限のあるアカウントを使用する。
- サポート担当から医院設定済みbundleを信頼済み経路で受け取り、別経路で伝えられたmanifest SHA-256と一致することをサポート担当が確認してから`install.sh`を実行する。USBを選択する操作はない。
- bundle内で`shasum -a 256 SHA256SUMS`を実行し、表示された64桁の値が別経路の値と完全一致することを確認する。一致しない場合は`install.sh`を実行しない。
- 状態確認が必要な場合はbundle内の`diagnose.sh`を実行する。出力は件数と固定エラー分類だけで、生電文やUSB名を含まない。

## BLOCKEDの扱い

- USBが2本認識されない、権限がない、対象患者を用意できない場合は`BLOCKED`とし、理由だけを書く。
- `FAIL`時は同じ操作を繰り返してデータを増やさず、状態表示と実施日時をサポート担当へ連絡する。
- 「受付超過」が1件以上になった場合は追加送信を止める。agent再起動で未配送データが消えるため再起動せず、サポート担当が機器側の再送可否を確認してから復旧する。
- PU-4010の2400 7E1/8E1条件、IDEXXのACK/session/retryは未確定のため、この確認票では`PASS`にしない。
