## V シリーズ — フォーム検証（入力・更新・DB 整合）

## 実行と記録のルール

- **実行環境**: ローカル（seed 003_demo）または STG（004_staging）。前提データはシナリオ内に検索条件で指定（ID 直書き禁止 — seed 変更に耐えるため）。
- **実行記録はシナリオファイルに書かない**（時点情報の混入で腐る — 旧 FUNCTIONAL_TEST_REPORT の教訓）。専用ブラウザ結果レポートも置かない。FAIL / 要対応は [`STATUS.md`](../../../../STATUS.md) の個票へ短く書き、シナリオ本文は手順の正本として維持する（過去の実行メモは `reports/` 配下に履歴として残るだけ）。
- **AI 実行**: browser-test スキルで実行可能な粒度で書かれている。NG 項目はリポジトリ直下 [`STATUS.md` §3 受入バグ（正本）](../../../../STATUS.md) へ `## BUG-XXX:` 節として起票する（ローカル連番 最大+1。バグではない対応事項は同ファイル §1 の `### TASK-XXX:` 節、USER 操作・決裁は [`q&a.html`](../../../../q&a.html) / [`PO-todo.md`](../../../../PO-todo.md)）。
- **【要実測】マーク**: 仕様文書に期待値が明記されていない挙動。初回実行で実測値を確認し、正しければシナリオの期待結果へ昇格させる（マークを外す）。
- **クレデンシャル禁止**: 実パスワード・トークンを本ディレクトリに書かない（[../../deploy/README.md](../../deploy/README.md) §4.4 準拠）。アカウントはロール名で指定する。
