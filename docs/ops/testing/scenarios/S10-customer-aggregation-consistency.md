# S10: 顧客集計ダッシュボード整合

> **目的**: 顧客集計ダッシュボードの主要指標（LTV・来院頻度・CPM 分布）が会計実データと一致し、見積が売上に混入しないことを証明する。
> **所要目安**: 15分 / **深度**: 薄い
> **仕様正本**: [顧客分析・集計機能](../../../spec/customer-aggregation.md) / [顧客集計ダッシュボード](../../../spec/screens/36-aggregation-dashboard.md)

## 前提条件

- 環境: ローカル（seed 003_demo）。ログイン: 権限グループ「執行」のスタッフ（owners の view を保有）。
- **依存シナリオ**: S08 実行済みであること。seed 003_demo の来院・会計データは 2016〜2023 年のみで過去 365 日の完了会計が存在しないため、S08 で精算した飼主を「飼主 A」として使用する。
- **飼主 B（見積のみ・データ準備要）**: seed 003_demo に見積レコードは含まれない。最終来院タブで「1年以上」または「来院なし」に分類される飼主を 1 名選び、そのペットのカルテの見積タブから合計金額のある見積を 1 件作成しておく（過去 365 日の完了会計がないことを会計一覧で事前確認する）。
- 休眠側データ: seed 003_demo は最終来院が 2023 年以前の飼主が大多数のため、「1年以上」区分の検証データ準備は不要。
- CSV 出力（#10）はダウンロード発生の確認までとし、ファイル内容の全列検証は行わない。
- 期間フィルタは既定（過去 365 日相当）のまま実施する。プリセットを変更した場合は #5 の会計一覧側の日付範囲も揃えること。

## 手順と期待結果

| # | 操作 | 期待結果 |
|:--|:---|:---|
| 1 | 顧客集計ダッシュボード `/aggregation` を開く | 売上ランキングタブが既定表示され、CPM セグメント 6 段階（Encounter/Growing/Core/Spot/Noah/Dormant）の人数チップが表示される |
| 2 | CPM チップのいずれかをクリック | 一覧が該当セグメントの飼主に絞り込まれる |
| 3 | 「来院回数」「最終来院」タブへ順に切替 | タブに応じて列構成が変わる（来院回数系の列／最終来院日・経過日数の列） |
| 4 | 売上ランキングタブで飼主 A を探し、年間診療費を控える | 飼主 A の年間診療費が表示される（金額基準は既定の「売上総額」のまま） |
| 5 | 会計一覧 `/accounting` で飼主 A・診療日=過去 365 日・ステータス「会計済」でフィルタし、請求金額を合算 | 合算額が #4 の年間診療費と一致する（LTV=過去 365 日の完了会計の税込合計） |
| 6 | 売上ランキングタブのフィルタパネルで金額基準を「売上総額」→「入金額」→「返金控除後」と切替 | 基準に応じて金額表示が切り替わる（S08 で部分入金→精算した飼主 A では入金額基準も #5 と整合する） |
| 7 | 売上ランキングタブで飼主 B を確認 | 見積の金額は年間診療費に算入されず、売上ゼロ（またはランキング対象外）のまま（見積≠会計） |
| 8 | 最終来院タブのフィルタで区分「1年以上」を選択 | 一覧が「1年以上」の飼主のみに絞り込まれる |
| 9 | 絞り込んだ一覧の任意の飼主数名の経過日数を確認 | いずれも 365 日以上であり、最終来院日と矛盾しない |
| 10 | 一覧で飼主 A の行をチェックし CSV 出力を実行 | 表示中のリスト内容が CSV としてダウンロードされる（仕様正本 36 §1.3） |
| 11 | 一覧の飼主名（飼主 A）をクリック | 飼主詳細 `/owners/:id` へ遷移し、会計履歴セクションで #5 と同じ会計が確認できる（ドリルダウン） |

## 確認観点

- **LTV の対象**: 過去 365 日間に完了（completed）した会計レコードの税込合計（仕様正本 §2.1）。見積（estimates）は会計（billings）と別ドメインであり、承認済みでも売上に算入されない。
- **最終来院区分の境界**: 90/180/365 日は `backend/internal/repository/ltv_repository.go` の SQL に固定値として実装されており、クリニック設定では変更できない（仕様正本 §2.2）。区分は「3ヶ月未満／3ヶ月以上／6ヶ月以上／1年以上／来院なし」の 5 分類。
- **並行ロード**: CPM チップと一覧テーブルは別クエリで非同期取得される（仕様正本 36 §3.1）。片方が先に表示される瞬間があっても不具合ではない。
- **CPM「Dormant」チップとの区別**: CPM の休眠判定はクリニック設定 `cpm_v1_dormant_days`（既定 240 日）による別軸の判定で、#7 の「1年以上」（365 日固定）とは基準が異なる。両者の件数不一致は不具合ではない（仕様正本 §2.2 出典注記）。
- **CPM チップの固定**: チップは CPM V1 の 6 区分に固定で、医院設定の CPM バージョンが V2 でも切り替わらない（仕様正本 36 §1.2）。V2 設定下でも表示が変わらないことを不具合と誤認しない。
- **来院なしの扱い**: 最終来院タブには「来院なしを含む」フィルタがあり、来院記録のない飼主は「1年以上」ではなく「来院なし」に分類される（仕様正本 §2.2）。#8 の絞り込みで混入しないこと。
- **clinic_id 隔離**: 集計 API はクリニック単位（`/clinics/:clinic_id/owners/aggregations`）。クリニック切替で他院の飼主が混入しないこと。
