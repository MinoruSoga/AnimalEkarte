# S25: 患者ヘッダーのマイクロチップ番号表示

> **目的**: カルテ編集の患者コンテキストヘッダーにマイクロチップ番号が正しく表示され、長い番号でも truncate + ツールチップで読め、死亡マーク等の他要素と共存して破綻しないことを納品前に証明する。
> **所要目安**: 10分 / **深度**: 薄い
> **仕様正本**: [screens/06-medical-records-form.md](../../../spec/screens/06-medical-records-form.md)。検証キュー: `SLACK-MICROCHIP`（[todo-verification.md](../../../../todo-verification.md)）。実装参照: `frontend/src/components/shared/PatientContextHeader/PatientContextHeader.tsx`。

## 前提条件

- ローカルの使い捨て clinic、または承認済みの専用 UAT tenant。
- マイクロチップ番号ありのペット（標準長・長い番号の 2 パターンが望ましい）と、番号なしのペット、死亡ペットの fixture。
- actor は medical-records の参照権限を持つ attached account。
- 依存シナリオ: S01（死亡ペットガード）・S19（viewport 適合）と連携。

## 手順と期待結果

| # | 操作 | 期待結果 |
|:--|:--|:--|
| 1 | MC 番号ありのペットのカルテを開く | ヘッダーに飼主名・ペット名とともにマイクロチップ番号が等幅フォント（`font-mono`）で表示され、aria-label で「マイクロチップ番号」と識別できる |
| 2 | 長い MC 番号・長い飼主名のペットで開く | 番号・名前が `max-w-[12rem]` 等で truncate され、ホバー/フォーカスのツールチップで全文を読める。ヘッダーが押し潰されない |
| 3 | MC 番号なしのペットで開く | MC 欄は表示されない（または空扱い）。空のプレースホルダが不自然に残らない |
| 4 | 死亡ペットで開く | 赤い「【死亡】」マークとミュート表示が維持され、MC 番号・名前と共存して破綻しない（S01 のガードと連携） |
| 5 | タブを切り替える・再読込する | ヘッダーは全タブで一貫して表示され、値が変わらない |

ヘッダー要素の構成と表示条件:

```text
PatientContextHeader（全タブで一貫・再読込で値は変わらない）
├─ 飼主名・ペット名 …… 長い値は truncate + ツールチップで全文
├─ 【死亡】マーク …… 死亡ペットのみ。赤 + ミュート色で他要素と共存
└─ マイクロチップ番号 …… 番号があるペットのみ（なしなら欄自体を出さない）
   ├─ 等幅フォント + aria-label で「マイクロチップ番号」と識別可能
   └─ 長い番号 → truncate、ホバー/フォーカスのツールチップで全文
```

## 確認観点

- `PatientContextHeader` は飼主名・ペット名・MC 番号を表示し、長い値は truncate + ツールチップ、死亡ペットは赤い「【死亡】」マーク + ミュート色。
- MC 番号は個体識別の安全情報。誤った番号・別ペットの番号・桁落ちが出るのは臨床安全上の FAIL。
- 表示だけでなく識別性（等幅・ラベル）も確認する。どの番号か判別できない表示は不十分。
- 狭い viewport での truncate は S19 と連携。ここではヘッダー要素の表示契約を確認する。

## 実装突合

- 変更サマリ:
  - `PatientContextHeader` の `microchipNumber` 表示（`font-mono`・aria-label・`max-w-[12rem]` truncate）と死亡マーク・ミュート表示を現行コードと突合
  - MC なし・長い番号・死亡ペット共存を手順 3–4 に対応づけ
