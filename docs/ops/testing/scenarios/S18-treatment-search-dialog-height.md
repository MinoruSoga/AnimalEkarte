# S18: 治療項目検索ダイアログ — 一覧の可視範囲と操作到達

> **目的**: 治療項目検索ダイアログが、短い一覧・長い一覧の両方で検索欄・一覧・閉じる操作が画面内に収まり、キーボード選択とフォーカス復帰が機能することを、対象 viewport で納品前に証明する。
> **所要目安**: 10分 / **深度**: 薄い
> **仕様正本**: [screens/06-medical-records-form.md](../../../spec/screens/06-medical-records-form.md)。検証キュー: `UAT-R2-MASTER-LIST-HEIGHT`（[todo-verification.md](../../../../todo-verification.md)）。

## 前提条件

- 対象 viewport は **1366×625 CSS px** から開始する（医院回答の Windows 8 / Chrome / 15.6 インチ想定）。実機の CSS 表示領域・ブラウザ版・100% と既報 125% ズームを run 記録に別記する。最新 Chromium の合格を旧 Chrome 対応済みとしない。
- 治療項目マスタに、一覧が 1 画面に収まる件数（短い一覧）と明確にはみ出す件数（長い一覧）の両方を用意する。固定 ID は仮定しない。
- actor は治療明細を追加できる medical-records 権限の attached account。
- 依存シナリオ: S17（数量確定）・S19（カルテ表示適合）と同じ fixture/run を使ってよい。

## 手順と期待結果

| # | 操作 | 期待結果 |
|:--|:--|:--|
| 1 | 治療タブで項目検索ダイアログを開く（短い一覧状態） | ダイアログ全体が `max-h-[80vh]` 内に収まり、検索欄・一覧・閉じる操作がはみ出さず到達できる |
| 2 | 長い一覧になる検索語またはフィルタで開く | 一覧領域だけがスクロールし（`max-h-[calc(80vh-12rem)]`）、検索欄と閉じる操作は画面内に固定される。ページ全体をスクロールさせずに最下行まで到達できる |
| 3 | 検索語を入力して絞り込む | 一覧が即時に絞り込まれ、選択候補が残る。検索欄が一覧のスクロールで隠れない |
| 4 | キーボード（矢印・Enter・Escape）だけで候補選択とキャンセルを行う | マウスなしで候補を選び確定/閉じるができる。フォーカスが一覧内を循環し、画面外へ迷子にならない |
| 5 | 項目を選択・確定する | 選択した項目が治療明細へ追加され、ダイアログが閉じる。フォーカスが呼び出し元（追加ボタン等）へ戻る |
| 6 | Escape または閉じるボタンで閉じる | 追加せず閉じる。フォーカスが呼び出し元へ戻る（focus restoration） |

ダイアログ内の固定/スクロール分担:

```text
治療項目検索ダイアログ（全体は max-h-[80vh] 内）
├─ 検索欄     … 固定。一覧のスクロールで隠れない
├─ 一覧領域   … max-h-[calc(80vh-12rem)]。ここだけがスクロールし最下行まで到達
└─ 閉じる操作 … 固定。選択確定 / Escape 後は呼び出し元へフォーカス復帰
```

## 確認観点

- 一覧上限は `TreatmentSearchDialog`（`frontend/src/components/shared/TreatmentSearchDialog/`）の `max-h-[calc(80vh-12rem)]`、ダイアログ本体は `max-h-[80vh]`。合成テスト 10 件で確認済みだが、本シナリオは**対象端末での可視範囲の受入**が目的。
- 「一覧の中だけスクロール・外側の操作は固定」を目視とキーボード到達で証明する。画面下のボタンが一覧の最下行までスクロールしないと押せない構成は FAIL。
- ズーム 125%（既報の発生条件）は必ず別 run で確認する。100% で収まることをもって 125% 合格としない。
- 長い一覧で検索・選択が最下行まで到達できること、短い一覧で余白が破綻しないことの両方を見る。
- 結果は viewport・ブラウザ版・ズーム・表示領域を紐づけて `reports/uat-YYYY-MM-DD/` に記録する。scenario 本文へ実行結果を書かない。
