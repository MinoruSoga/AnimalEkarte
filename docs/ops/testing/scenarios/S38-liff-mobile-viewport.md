# S38: LIFF モバイル画面 — スマホ viewport での表示適合

> **目的**: LIFF（LINE 内ブラウザ）の各画面がモバイル viewport で横スクロール・見切れ・タップ不能なく機能することを納品前に証明する。S04/S12 は機能フローの確認であり、本シナリオは表示適合を対象とする。
> **所要目安**: 15分 / **深度**: 中
> **仕様正本**: LIFF 各画面の仕様・[S04](S04-liff-reservation-journey.md)・[S12](S12-liff-pet-health.md) の機能面は別途実施済みであること。

## 前提条件

- 対象 viewport: **iPhone 相当 390×844** と最小想定 **360×640**（CSS px）。ブラウザの device emulation または実機。実機での LINE 内表示は mock lane とは別記する。
- LIFF 画面: リンク/連携画面（`LiffLinkPage`）、ペットヘルスカード（`PetHealthPage`）、ローディング（`LoadingPage`）、エラー画面（`shared-liff/ErrorPage`）。
- LIFF mock lane で表示できる状態（実 LINE 連携は本シナリオの必須条件ではない）。

## 手順と期待結果

| # | 操作 | 期待結果 |
|:--|:--|:--|
| 1 | 連携画面を 390×844 で開く | 説明文・同意・連携ボタンが画面内に収まり、横スクロールなし。ボタンのタップ領域が指で押せる（44px 目安） |
| 2 | ペットヘルスカードを 360×640 で開く | ペット一覧・ワクチン記録・次回予定が縦スクロールで全て到達可能。カードが画面端で見切れない |
| 3 | 長いペット名・多数ペット（S35 fixture 相当）で開く | 名称が truncate/折返しで破綻しない。一覧が縦スクロールで末尾まで到達 |
| 4 | ローディング・エラー・空状態（ペットなし）を開く | 各状態が画面中央に収まり、リトライ導線がタップ可能 |
| 5 | ソフトウェアキーボードを出した状態で入力フォームを操作 | 入力欄がキーボードに隠れず、スクロールで入力位置へ到達できる（visualViewport 縮小でも送信ボタン到達可） |
| 6 | 画面回転（横持ち 844×390）を試す | 横向きでも主要操作が到達可能。破綻する場合は仕様として明記 |

## 確認観点

- 院内 UI（S19 系）とは viewport・入力方式・フォントサイズが異なるため、デスクトップ PASS をモバイル合格に流用しない。
- タップターゲット・`safe-area`・キーボード表示時の見切れはモバイル固有のずれ箇所。
- `100vh` 直指定はモバイルブラウザのアドレスバーで見切れやすい。`dvh`/`svh` 対応を突合する。
- LINE 内 WebView 固有の挙動（下部ツールバー等）は実機 lane で確認し、mock/emulation で代替しない。
