# S39: 状態フィードバック — loading・空・エラー・disabled・フォーカスの可視性

> **目的**: 読込中・0 件・エラー・操作不可・フォーカス中の各状態が、ユーザーが状況を判別できる視覚フィードバックを持つことを納品前に証明する。「無音失敗」「状況不明な固まり」「フォーカス不可視」を FAIL とする。
> **所要目安**: 15分 / **深度**: 中
> **仕様正本**: 各 screens 正本。フォーカス復帰は S18/S32・`BUG-DIALOG-FOCUS-RESTORE`（bug.md）、必須エラーの無音禁止は FIELD-LEVEL-PROTOCOL F1 と連携。

## 前提条件

- 各状態を作れる fixture: 遅延させられる API（開発ツールのネットワークスロットリング等）、0 件の一覧、400/500 を返せる fixture 操作、権限不足・ロック済みのレコード。
- actor は編集権限を持つ attached account（権限不足の確認は別権限アカウントまたは権限の一時調整）。

## 手順と期待結果

| # | 操作 | 期待結果 |
|:--|:--|:--|
| 1 | スロットリング下で一覧・詳細を開く | スケルトン/スピナーが表示され、レイアウトシフト（CLS）で内容が飛び跳ねない。長時間時にタイムアウト/リトライ導線がある |
| 2 | API 400/500/ネットワーク断を発生させる | エラーバナーまたはトーストが出て状況が伝わる。白紙・無音固まり・二重送信可能状態にならない |
| 3 | 保存中の二重クリック・連打を行う | 送信中はボタンが disabled/ローディング表示になり、多重送信されない |
| 4 | 権限不足・確定済みロック・死亡ペット等の操作不可画面を開く | 操作が disabled 表示または理由付きで拒否される。押せるのに失敗だけする見た目にならない |
| 5 | Tab キーでフォーム全体を順に辿る | フォーカスリングが全インタラクティブ要素で視認でき、タブ順が見た目の順序と一致。フォーカスが画面外に逃げない |
| 6 | トースト・バナー・インラインエラーの文言色を確認 | エラー（赤系）・成功・情報が識別可能。色だけでなくアイコン/文言で状態が分かる |

## 確認観点

- 「保存できたか不明」「エラーが出たがどこか不明」「押せるのに反応しない」はいずれも FAIL。
- フォーカスリングは `outline`/`ring` の可視性を目視確認。`outline: none` で代替手段がない箇所は FAIL（キーボード導線は S18/S32 手順4・S34 手順4 と連携）。
- ローディング中のフォーム再送信・確定ボタン連打は会計（S21 冪等）と臨床（V01）の保護と別に、UI 上の抑止を確認する。
- 状態表示のないまま遷移する処理は【要実測】として記録し、仕様判断が必要なら PARTIAL。

## 実装突合

- `sonner` トースト、各フォームの `isSubmitting`/`disabled` 配線、フォーカス可視スタイル（`focus-visible`/`ring`）、スケルトンコンポーネントを現行コードと突合
