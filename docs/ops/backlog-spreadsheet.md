# バックログスプレッドシート 運用ルール

> Q&A バックログの正本と更新境界を定義する。外部シートの名称、URL、tab ID、列、所有者はリポジトリから検証できない。操作前に、権限のある人が承認済みポータルまたは Vault の locator と現行構造を確認し、確認日を作業記録へ残す。

## 正本

- Q&A のデータ正本は、組織が承認した外部スプレッドシートとする。
- 直接 URL や tab ID はこの公開リポジトリへ固定しない。権限のある locator から取得する。
- リポジトリ内に Q&A の複製ビューを置かない。旧 `q&a.html` は履歴資料であり、現行状態ではない。

## 回答文の記載規約

- 冒頭タグは `【対応済】`、`【未対応】`、`【未対応（対応予定）】` のいずれかとする。
- 実施可否は「未実装です。」「対応します。」のように明確に書く。
- 複数項目は項目ごとにタグを付ける。曖昧な内部用語を避ける。
- 「回答」列は開発側が管理する。相手側が管理するステータスや質問本文は変更しない。

## 更新フロー

1. 承認済み locator から対象シートを開き、sheet/tab/列と権限を人が確認する。
2. 書き込み前に対象 sheet、セルまたは行、文面を提示し、外部書き込みの明示承認を得る。
3. standing approval を使う場合は、対象 sheet・セル範囲・内容の種類・有効期限を記録する。範囲外は改めて承認を得る。
4. 利用可能な承認済みツールで編集する。特定のブラウザ、MCP、clipboard 手順を前提にしない。
5. 複数行入力はまず非機密の一セルで dry run し、改行と対象セルを確認する。UI 手順は変わり得るため、恒久手順として扱わない。
6. 更新後、対象セル/行を再読して文面を照合し、確認日と実施者を作業記録へ残す。秘密情報や個人情報をログへ複製しない。
7. 一括更新は UI 自動操作を避け、承認済みの import 手順と rollback 方法を用意する。

外部状態はこの文書の更新時には確認していない。操作ごとに検証が必要である。
