## 回答文の記載規約

### ステータスタグ（各項目の冒頭に必須）

| タグ | 意味 |
|------|------|
| `【対応済】` | 実装済み・現行機能で可能 |
| `【未対応】` | 未実装かつ現時点で対応予定なし |
| `【未対応（対応予定）】` | 未実装だが対応に着手する |

### 本文の表現規約

- 実施可否は二値で言い切る: **「未実装です。」**（着手しない）／**「対応します。」**（着手する）。
- 断定形で書く。「〜かもしれません」「ご検討ください」等の曖昧表現は使わない。
- 質問者への再現情報依頼・確認依頼・「現行仕様と一致しない」等の齟齬説明は書かない。
  - 過去のコード変更起因の不具合が修正済みの場合は「過去のコード変更に起因する不具合で、修正済みです。」と記載する。
- 「吸収します」等の内部用語・曖昧語を使わない。誰が読んでも分かる平易な表現にする（例: 「カタカナ・ひらがなのどちらで入力してもヒットします」）。
- 複数項目を含む質問は、項目ごとに `【タグ】【項目名】` または `・【タグ】項目名: 説明` の形式で分割して回答する。

## 更新フロー

1. 回答の新規記入・更新は **シートのセルを直接編集** する（Claude は claude-in-chrome によるブラウザ操作で実施）。
2. Claude がシートへ書き込む場合は、**書き込み前にセル位置（No）と文面を提示して承認を得る**（外部書き込みのため。承認省略の standing 宣言があればその範囲で省略可）。
3. Google Drive MCP は読み取り専用（転記結果の検証用）。セル書き込みには使えない。
4. **複数行テキストの入力手順（必須）**: `type` アクションは改行がEnter扱いになり行が下のセルへ分散する。必ず「javascript_tool で `navigator.clipboard.writeText()` → 名前ボックスでセル指定 → Enter で編集モード → cmd+v → Enter」の手順で貼り付けること（2026-07-14 に実地検証済み）。
5. 一括更新が必要な場合はブラウザ操作ではなく CSV エクスポート→手動インポートを検討する（UI 自動操作は数セル単位が現実的な粒度）。

## 責任分界

- **「回答」列**: 開発側（曽我）が記載。上記タグ・表現規約に従う。
- **「ステータス」列**（対応中／対応済み等）・「No／質問者／分類／内容」列: 先方（ノア他）管理。開発側は書き換えない。
- 回答文内のタグ（実装状態）とステータス列（先方の運用ステータス）は別概念。両者がズレて見える場合（例: 全項目【対応済】なのにステータス「対応中」）は先方に確認する。
