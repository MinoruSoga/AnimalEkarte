  ---
  予約可能枠 ホワイトリスト挙動の仕様変更 — PO論点整理

  現状の挙動（問題の本質）

  枠 1 件でも登録 → その区分の全日付がホワイトリストモードに
    ├─ 登録済み開始時刻の曜日/日 → その時刻のみ予約可
    └─ 枠が登録されていない日   → 終日予約不可  ← 罠

  「月曜だけ 10:00 を追加した」つもりが「火〜日は誰も予約できなくなる」。

  ---
  設計オプション（3案）

  Option A: 「ホワイトリストモード」スイッチ（推奨）

  予約区分に slot_mode ENUM('open', 'whitelist') を追加。

  ┌──────────────────┬─────────────────────────┬───────────────────────────┐
  │      モード      │       枠登録なし        │        枠登録あり         │

❯ ホワイトリストって何？                                                        
⏺ 「ホワイトリスト」とは許可リストのこと。

  ---
  この文脈での意味

  現在の reservation_type_available_slots の実装はこう動く：

  枠が 1 件もない   → 何も制限しない（通常の営業時間で予約可）
  枠が 1 件でもある → 「登録した時刻のみ許可」モードに切り替わる

  つまり枠を「追加する」のではなく、「許可リストを作る」という意味になっている。

  例:
  - 月曜 10:00 の枠を 1 件登録
  - → 月曜は 10:00 のみ予約可（それ以外の時刻は不可）
  - → 火〜日は枠がないので終日予約不可 ← これが罠

  ---
  問題の核心

  スタッフが「土曜の 14:00
  に特別枠を追加したい」と登録すると、登録した瞬間に「月〜金はもう予約できなくな
  る」という副作用が発生する。意図せず他の曜日を全部ブロックしてしまう。

  ---
  解決の方向性

  ┌─────────────────────┬───────────────────────────────────────────────────┐
  │       呼び名        │                       動き                        │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ ホワイトリストモー  │ 登録した時刻のみ許可。ない日は全部ブロック        │
  │ ド（現状）          │                                                   │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ 加算モード（変更後  │ 通常営業時間にプラスして特別時刻を追加するだけ。  │
  │ ）                  │ ない日はブロックしない                            │
  └─────────────────────┴───────────────────────────────────────────────────┘

  スイッチで「どちらの意図か」を選べるようにするのが Option A の提案。

              continue // 子を持つノードは選択肢に出さない

          result = append(result, all[i])
      }
      return result, nil
  }

  Q: Cross-tenant validation → Yes, accept the recommendation.

  FindByID(ctx, clinicID, *ParentID) before setting is mandatory. This is the
  standard P1 pattern in this codebase (see backend/internal/service/CLAUDE.md).

  and Create paths.
